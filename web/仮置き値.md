# モックアップの仮置き値

基本設計書・要件定義書で値が確定していない項目について、モックアップで置いた仮の値の一覧。

**この一覧は設計の決定ではない。** モックを動かすために必要だっただけであり、
ここに書いた値が要件定義書・基本設計書へ逆流しないよう、置いた場所と理由を残す。
確定したら `要決定事項.md` の手順（本文へ反映 → 一覧から落とす → `ナレッジ/決定事項.md` に理由を残す）に従う。

## 2 入力項目の制約値（基本設計書「画面詳細」(3-6) が【要決定】としている）

| 項目 | 仮置き値 | 置いた場所 |
| :-- | :-- | :-- |
| パスワードの桁数 | 8文字以上のみ。文字種の制約なし | `api/client.ts` の `changePassword` / `signUpGuardian` |
| 招待コードの入力形式 | 大文字へ正規化して照合。区切りのハイフンは表記のまま比較 | `api/client.ts` の `verifyInvitationCode` |

## 5 成長曲線の基準値（`m_growth_standard`）

**実装時に差し替えが必要。** `api/mockDb.ts` の `buildGrowthStandards()` が生成している値は、
0・12・24・36・48・60・72か月の中央値をおおよその値で置き、パーセンタイルを固定比率で掛けて
線形に補間したものである。厚生労働省の乳幼児身体発育調査の公表値ではない。

`source_version` には `仮置き（未投入）` を入れてあり、公表値を投入したら差し替わる。

## 6 認証まわりの仮置き（Go サーバ）

要決定事項.md の優先度Aにあたる項目を、動かすために仮に決めたもの。**設計の決定ではない。**

| 項目 | 仮置き | 置いた場所 |
| :-- | :-- | :-- |
| 認証情報の保持 | サーバ側にセッションを持ち、HttpOnly・SameSite=Strict の Cookie でセッションIDだけを渡す | `server/session.go` |
| CSRF 対策 | 独立した対策は未実装。SameSite=Strict は緩和策であって対策の決定ではない | 同上 |
| パスワードのハッシュ | bcrypt（既定コスト） | `server/main.go`・`server/api_auth.go` |
| Cookie の Secure 属性 | false。本演習の動作検証環境が localhost のため。HTTPS 公開時は true にする | `server/session.go` |
| セッションの有効期間 | 「ログイン状態を保持する」の有無で、自動ログアウト時間（30分）とログイン情報の記憶（30日）を切り替える | 同上 |

## 7 実装していないもの

要件・設計にはあるが、本モックアップの範囲外としたもの。

| 項目 | 理由 |
| :-- | :-- |
| 自動ログアウト | 無操作時間の計測を未実装。セッションの有効期限だけを持つ |
| 添付ファイルの実体 | ファイル名だけを持ち、保存も表示もしない |
| PDF出力 | 操作ログへの記録のみ行い、ファイルは生成しない |
| 通知（Web Push） | 演習範囲外（要件定義書） |
| 年度更新の実行 | 進級先の割り当て規則と卒園の判定条件が未確定のため、内容の確認までとした |
| 引き継ぎ猶予期間の判定 | 未実装 |
| 記録の保持年数にもとづく削除 | 未実装 |
| 定型文の編集 | 定型文を保持するテーブルが基本設計書「日誌」(5-4) に無いため、サーバ側の定数で持っている |

## 8 業務の規則を2か所に持っていること

参照範囲の判定・承認の可否・入力の検証といった規則は、次の2か所にある。

- `server/`（Go サーバ）… 実運用の判定。**権限の担保はこちら**
- `web/src/api/mock.ts`（ブラウザ内のモック）… サーバを立てずに動かすときと、テストの対象

**片方だけを直すと食い違う。** 規則を変えるときは必ず両方を直すこと。
食い違いを検出するために、`web/tests/integration.test.ts` が実サーバに対して
同じ観点（参照範囲・権限の拒否・設定値）を確かめている。
