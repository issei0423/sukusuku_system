# 見直しの係への頼み方（ひな形）

重い版のハーネス（`heavy.md`）で、設計書・コード・文書の見直しを係に割るときの形。照合する係（`verifier`）が読める形に、出力をそろえる。

## 割り方

- **観点で割る**（文書で割らない）。文書で割ると、文書をまたぐ矛盾が誰の担当にも入らない
- 1体の担当は、読む量でおよそ4000行まで。数は `heavy.md`「使う量の歯止め」に従う
- 観点ごとに「その道の目で見るときの例」を5〜10個書く。例に限らないと添える

## プロンプトに入れるもの

1. 使う人の言葉（原文）
2. **守ること**
   - ファイルは書き換えない。git を操作しない。出力ファイルにだけ書く
   - 読む場所（worktree・ブランチ）と主な文書
   - 直し方の案は、要件定義書「コンセプトとターゲット層」(1-1) に合うもので選ぶ
   - **既知を重ねない**：前の洗い出し・docs ブランチの `要決定事項.md`・`ナレッジ/決定事項.md` を先に読ませる。理由が誤っていると考えるときだけ「既知だが再考」
   - いまの本文だけを見る（改訂履歴・過去の版の記述は対象外）
   - 根拠を添える。確かめたら URL、確かめていなければ「推測」
   - 引用はそのまま、`ファイル:行` を添える。矛盾は両側を引く
3. **担当の観点**と、その道の目で見るときの例
4. **重さ**の定義（高：安全・誤共有・法令とのずれ・実装できない矛盾／中：現場で困る・届かない・食い違う／低：言葉の揺れ）
5. **出力ファイル**（一時フォルダの `review-<日付>/<id>-<観点>.md`）と、指摘ごとの形：

```
### <id>-01 （1行の見出し）
- 種類：矛盾／（その道）の目／抜け
- 重さ：高／中／低
- 場所：`文書:行`（矛盾なら両側）
- 引用：「…」
- 何がおかしいか：
- 現場で起きること：（誰が・いつ・何に困るか）
- 根拠：
- 直し方の案：（最小の直し。どの文書のどの節をどう変えるか）
- 誰が決めるか：AI で直せる／チーム／（導入先）
- 既知か：新規／既知だが再考（どこで決めたか）
```

6. 最終メッセージは40行以内：件数（重さ別）、大事な5件、出力ファイルのパス、読みきれなかった範囲

## 保育の目で見るときの根拠

設計や画面を「保育の現場で見ておかしくないか」で見直すときに当たるもの。

- 安全：こども家庭庁・内閣府「教育・保育施設等における事故防止及び事故発生時の対応のためのガイドライン」（午睡中の確認、SIDS の予防、重大事故の報告）
- 食事：厚生労働省「保育所におけるアレルギー対応ガイドライン」
- 健康：厚生労働省「保育所における感染症対策ガイドライン」
- 保育の計画と評価・記録：保育所保育指針とその解説（3歳未満児は個別的な計画）
- 身体の育ち：乳幼児身体発育曲線（母子健康手帳）
- 現場の声：docs ブランチの `20260609議事録まとめ.md`（保育士へのインタビュー）。ペルソナは架空で、設定だけを引く
- 家庭の事情：親権・面会の制限・DV のある家庭、きょうだい、祖父母の送迎、外国籍の保護者

## 終わったら

- 全部の出力ファイルを `verifier` に渡す（`heavy.md`「照合する」）
- 残った指摘を、「直せる」「人が決める」に分けて実行の点にする
