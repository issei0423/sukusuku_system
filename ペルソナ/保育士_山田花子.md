## 0 この文書について

**このペルソナは架空の人物であり、実在の保育士への聞き取りにもとづかない。** 要件定義書「コンセプトとターゲット層」(1-1) と「プロジェクトの背景」(1-2) から起こした**たたき台**である。

- **デモを操作したのは Claude である。** 人が触った結果ではない。「感想」は、この人物の立場に立って画面を見たときの**推定**であり、利用者の声として引用しない
- **「見つけた問題点」は、実際に画面で起きたことだけを書いた。** 確かめきれなかったものは「確かめられなかったこと」(5) に分けた
- 問題の指摘と論点の提示に留め、**どう直すかの結論は書かない**（`CLAUDE.md`「`修正箇所/` の使い分け」と同じ扱い）
- 氏名はモックアップのデモデータのものである。実在の人物ではない

**デモの条件**

| 項目 | 内容 |
| :-- | :-- |
| 対象 | `mockup-go-react` 系の `feat/tablet-orientation-layout` ブランチ（PR #71 の内容に、通知のベルマーク化を足した状態） |
| 動かし方 | Go サーバ1つ（画面の配信とデータの保存を兼ねる）。デモ専用のデータベースを使い、終了後に停止した |
| 端末 | タブレット横向き（1180×820・タッチ操作）。午睡チェックのみ縦向き（820×1180）でも確認 |
| アカウント | `yamada@hoiku.example.jp`（一般・さくら組担任）。日誌の承認のみ `takahashi@hoiku.example.jp`（管理者）で実施 |
| 実施日 | 2026-10-05（デモデータ上の「今日」も同日） |

## 1 ペルソナ

| 項目 | 内容 |
| :-- | :-- |
| 氏名 | 山田 花子（やまだ はなこ） |
| 年齢・経験 | 29歳。保育士7年目。現在の園は3年目 |
| 役割 | さくら組（1歳児・12名）の担任。もう1人の担任（佐藤 明子）と2人で受け持つ |
| システム上の権限 | 一般（保育士） |
| 使う端末 | クラスに1台の共用タブレット。事務室の PC も使う |
| ITの慣れ | スマートフォンは日常的に使う。PC の文字入力は遅くはないが、得意ではない |

**1日の流れとシステムを触る場面**

| 時間帯 | していること | システムを触る場面 |
| :-- | :-- | :-- |
| 朝 | 受け入れ。保護者から口頭やチャットで連絡を受ける | 保護者からの連絡を読む |
| 午前 | 活動・食事 | ほぼ触れない |
| 午睡（13:00〜15:00） | 寝かしつけ、10分ごとの午睡チェック。**唯一まとまって座れる時間** | 午睡チェック。合間に日誌の下書き |
| 夕方 | お迎え対応 | 保護者へ返信。日誌の申請 |
| 月に数回 | 身体測定、発達チェック | まとめて入力 |

**大事にしていること**

- 子どもから目を離さないこと。**画面を見ている時間は、子どもを見ていない時間**である
- 保護者に「今日のこの子」を自分の言葉で伝えること
- 午睡チェックの記録を、あとで説明できる形で残すこと

**困っていること（現状の紙の運用で）**

- 午睡チェック表・連絡帳・日誌に、同じことを何度も書く
- 書類が午睡の時間に終わらず、持ち帰りや残業になる
- 保護者からの連絡（お迎えの変更など）が、口頭・電話・連絡帳に分かれ、もう1人の担任へ伝え漏れる

**このシステムに期待すること**

- 午睡チェックが、子どもの横に立ったまま数秒で終わること
- 一度書いたことを、二度書かなくて済むこと
- 保護者からの連絡を、担任2人が同じ画面で見られること

## 2 デモの筋書きと結果

「ある日の午睡の時間から夕方まで」を想定して、次の順に操作した。

| 場面 | やったこと | 起きたこと |
| :-- | :-- | :-- |
| ログイン | 職員用の入口からログイン | ダッシュボードが開き、未対応（未読のチャット6件・発達チェックの未実施8名・ヒヤリハット未起票1件）と「午睡チェックが実施中です」が並んだ |
| 午睡チェック | 未記録の小林 結衣の「記録」を押し、体位を選んで記録 | 入力の窓が開いた。**呼吸「あり」・顔色「通常」は最初から選ばれており**、体位を選ぶだけで記録できた。記録後、ヘッダの表示が「チェックの時刻を過ぎています」から「次のチェックまで 09:59」へ変わった（未記録の園児は3名残っていた） |
| 午睡チェック（縦向き） | タブレットを縦にして同じ画面を開いた | 園児のカードは3列で並び、タイマーの帯も画面の幅に収まった |
| 日誌 | 下書き（山田 太郎の個人日誌）を開き、定型文を選び、本文を書き足して申請 | **定型文は本文に入らなかった**（改行だけが入った）。書き足した本文は確認画面に出て、申請できた。申請後は日誌一覧へ戻り、状態が「申請中」になった |
| 日誌（入力の確認） | 新規作成で、個人日誌のまま園児を選ばずに「確認へ進む」を押した | **確認画面へ進めた。** 対象は「さくら組」と表示された |
| チャット | 「山田 太郎の保護者」を開き、お迎え変更の連絡に返信し、その返信を編集 | 送信・編集ともできた。編集後は「（編集済み）」が付いた |
| 発達チェック | 山田 太郎の入力を開き、5項目のうち2項目だけ選び、所見を書いて確定 | 未入力3件のまま確定できた。一覧へ戻ると前回の実施日が今日になり、状態が「予定どおり」になった |
| 身体記録 | 山田 太郎を選び、身長を桁違い（785）で入力 | 「想定の範囲（40〜140cm）の外です」と出た。「登録する」を押すと「このまま登録する」に変わり、もう一度押さない限り登録されなかった。正しい値（79.6cm・10.2kg）で登録すると、記録済みが1名になった |
| 園児の記録 | 園児一覧から山田 太郎の「記録」を開いた | 日誌・身体測定・午睡チェックが日付順に並んだ |
| ログアウト | ヘッダの「ログアウト」を押した | 職員用の入口へ戻った |

## 3 感想（この人の立場で見たときの推定）

**助かると感じそうなところ**

- **ダッシュボードで、今やるべきことが分かる。** 未読のチャットと午睡チェックの実施中が最初に目に入るので、出勤してすぐ何から手を付けるかを迷わない
- **保護者からの連絡が1か所に集まる。** お迎えの変更が、もう1人の担任にも園長にも同じ画面で見えている。伝え漏れの心配が減る
- **身体測定の桁の打ち間違いを止めてくれる。** 12人分を続けて打つと必ず1回は間違える。黙って登録されないのは安心できる
- **園児ごとに記録が1列に並ぶ。** 面談の前に、その子の日誌と身体測定をまとめて見返せる
- **「担当するクラスの日誌のみ表示しています」と書いてある。** 見えていないものがあることが分かるので、「あの日誌が無い」と慌てない

**不安になりそうなところ**

- **午睡チェックで、呼吸と顔色が最初から「あり」「通常」になっている。** 急いでいるときほど、見ていなくても記録できてしまう。あとで「見たのか」と聞かれたとき、この記録では答えられない
- **1人記録しただけで、タイマーが次の10分へ戻る。** 残りの3人を見落としても、画面の一番目立つところは「大丈夫」と言っている
- **12人に、1人あたり3回ずつ押す。** 10分ごとに36回。寝かしつけの合間にやるには多い
- **定型文が入らない。** 入ると思って選んだのに何も起きないと、故障なのか自分の操作が悪いのか分からない
- **保存できたのかが分からない。** 申請も確定も登録も、押したあとに「できました」と出ない。一覧の表示が変わったことで、ようやく分かる
- **発達チェックを途中のまま確定できてしまう。** 3項目を空のまま確定しても、止められも確かめられもしなかった

**全体として**

日誌・チャット・身体記録は、紙の二度書きが減る実感を持てそうである。一方、**いちばん頻繁に、いちばん急いで触る午睡チェックが、いちばん気になる**。記録の速さと記録の確かさがぶつかる場面であり、ここの作りが園に受け入れられるかどうかを左右すると感じた。

## 4 見つけた問題点

実際に画面で起きたことだけを挙げる。**どう直すかは書かない。**

### 4-1 記録の正しさ・安全にかかわるもの

| 画面 | 起きたこと | 論点 |
| :-- | :-- | :-- |
| 午睡チェック画面 | 記録の窓で、**呼吸「あり」・顔色「通常」が最初から選ばれている。** 体位だけ選べば記録できる | 午睡チェックは観察した事実の記録である。**観察していない値をシステムが先に入れている**ことになり、`CLAUDE.md`「システムは判断をしない」と、要件定義書「記録の一貫性」(7-1) が求める記録の信頼性にかかわる。速さとのかね合いをどこに置くか |
| 午睡チェック画面 | 未記録が3名残っていても、1名を記録するとヘッダが「次のチェックまで 09:59」へ戻る | タイマーが示すのは「クラスとして最後に誰かを記録してからの時間」なのか、「全員を確認し終えてからの時間」なのか。定義が画面から読み取れない |
| 日誌作成画面 | 記録種別が個人日誌のまま、**対象の園児を選ばずに確認画面へ進める。** 対象は「さくら組」と表示される | 個人日誌に対象の園児が無い状態を許すか。申請まで通るかは確かめていない |
| 発達チェック入力画面 | 5項目のうち3項目が未入力のまま確定でき、確かめる表示も出ない。画面には「未入力のままにするとチェック漏れの対象になります」とある | 未入力のまま確定することを許すのか。許すなら、確定の時点で何を伝えるか |
| 発達チェック一覧 | 確定後、状態は「予定どおり」になるが、**次回の予定日は過ぎた日付（2026/09/01）のまま** | 次回の予定日をいつ・何から計算し直すのか |
| 発達チェック入力画面 | 所見を書いて確定したあと開き直すと、選んだ項目は残っているが**所見の欄は空**だった | 所見が保存されていないのか、読み込まれていないのか。未確認 |
| 身体記録画面 | 「過去の記録」の記録者が、氏名ではなく**職員ID（S003）**で出る | 誰が記録したかを人が読める形で示す必要がある。保護者向けの共有日誌閲覧画面にも同じ表示がある（`ペルソナ/保護者_山田健一.md`） |

### 4-2 使い勝手にかかわるもの

| 画面 | 起きたこと | 論点 |
| :-- | :-- | :-- |
| 午睡チェック画面 | 1人の記録に3回の操作（記録 → 体位 → 記録する）が要る。12名で36回 | 要件定義書「午睡チェック」(4-4) は体位を「スワイプボタンで一人ずつ記録できる」としている。現在の作りとの差をどう扱うか |
| 日誌作成画面 | **定型文を選んでも本文に入らない。** 改行だけが入る（2回確かめた） | 不具合。雛形の呼び出しは正しく入る |
| 全般 | 申請・確定・登録のあとに、**完了を知らせる表示が出ない**（コードにも該当する部品が無い） | 操作が通ったことを何で伝えるか。共通の扱いとして決める必要がある |
| 発達チェック一覧 | 月齢が他の画面と1か月ずれて見える（山田 太郎は一覧で1歳3か月、入力画面・園児一覧・身体記録画面で1歳4か月） | 一覧は**予定日の時点**の月齢を出す作りである（基本設計書「発達チェック・身体測定」(4-8)）。規則どおりだが、**何の時点の月齢かが画面に書かれていない** |
| チャット画面（職員） | 保護者からの連絡（お迎えの変更など）に、対応したかどうかの印を付ける手段が見当たらない | 基本設計書の権限一覧には「未対応スレッドの管理」があり、「画面の一覧」(3-2) も未対応スレッドの切り替えを挙げている。モックアップには無い |
| チャット画面（職員） | リアクションの操作が見当たらない | 要件定義書「チャットツール」(4-3) は全ロールにリアクションを定めている。モックアップには無い |
| チャット画面（職員） | 横向きで、画面全体が縦に 52px だけスクロールする | 3つの領域を画面の高さに収める意図（基本設計書「画面の一覧」(3-2)）と合っていない |
| 身体記録画面 | 範囲外の値のとき「もう一度「登録する」を押してください」と出るが、ボタンの名前は「このまま登録する」に変わっている | 文言とボタン名の食い違い |
| 園児一覧 | アレルギーが2つあると「乳小麦」と続けて表示される | 区切りが無く、1つの品目に読める。アレルギーの表示であり、読み違いの影響が大きい |
| 日誌作成画面 | 「この園児の過去の記録」に、いま編集している日誌そのものが出る | 過去の記録として出す範囲 |

## 5 確かめられなかったこと

- **人が触ったときの速さ・押しやすさ。** 操作は自動で行った。指で押したときの押し間違いや、片手で持ったときの届きやすさは分からない
- **実機での見え方。** PC のブラウザでタブレットの画面幅とタッチ操作を再現した。iPad の Safari では確かめていない
- **午睡チェックの通知音とタイマーの進み方。** デモデータの午睡が13時開始のまま続いており、実施時刻（22時台）では常に時刻超過の表示だった。**終了し忘れた午睡チェックがどう扱われるか**は論点として残る
- **発達チェックの確定が一覧に反映されるまでの時間。** 1回目の確定直後は一覧が古いままに見え、2回目は反映されていた。再現の条件は確かめていない
- **園児の記録に発達チェックが出るか。** 確定後に開いた範囲では、日誌・身体測定・午睡チェックだけが並んでいた。仕様なのかは確かめていない
- **異常時の記録、ヒヤリハットの起票、日誌の差し戻しを受けたあとの修正、写真の添付、複数の職員による同時編集。** 今回の筋書きに入れていない
- **もう1人の担任と1台のタブレットを使い回す場面。** 記録者の取り違えが起きないかは、2人で触らないと分からない
