## 0 この文書について

**このペルソナは架空の人物であり、実在の保護者への聞き取りにもとづかない。** たたき台である。

- **デモを操作したのは Claude である。** 人が触った結果ではない。「感想」は、この人物の立場に立って画面を見たときの**推定**であり、利用者の声として引用しない
- **「見つけた問題点」は、実際に画面で起きたことだけを書いた。** 確かめきれなかったものは「確かめられなかったこと」(5) に分けた
- 問題の指摘と論点の提示に留め、**どう直すかの結論は書かない**
- 「鈴木 和子」は今回のデモのために置いた架空の名前である。園児の鈴木 花子、母の鈴木 美和はモックアップのデモデータのものである

**1巡目との違い**

1巡目は「すでに登録を済ませ、アプリに慣れた父親」だった。2巡目は**「招待コードの紙を受け取り、自分のスマートフォンではじめて登録する祖母」**にした。保護者にとって最初の体験である新規登録を通る。

**このデモは一度、途中で止まった。** 新規登録を実行した時点でサーバが応答しなくなり、**登録を完了できなかった**（「見つけた問題点」(4-1)）。その時点では、登録したあとに見えるはずの画面を、同じ園児の既存のアカウント（母・鈴木 美和）で代わりに確かめた。

**翌日（2026-10-06）、この不具合を直してから続きを行った。** 祖母のアカウントで登録を完了し、登録後の体験まで通した（「不具合を直したあとの続き」(2-1)）。

**デモの条件**

| 対象 | `mockup-go-react` 系の `feat/tablet-orientation-layout` ブランチ（PR #71 の内容に、通知のベルマーク化を足した状態） |

| 実施日 | 2026-10-05 |

## 1 ペルソナ

| 項目 | 内容 |
| :-- | :-- |
| 氏名 | 鈴木 和子（すずき かずこ） |
| 年齢 | 68歳。退職して数年 |
| 子どもとの関係 | 鈴木 花子（1歳6か月・さくら組）の祖母。**水曜と金曜のお迎えを担当している** |
| システム上の権限 | 保護者（続柄：祖母） |
| 使う端末 | 自分のスマートフォン。文字は大きめに設定している |
| ITの慣れ | 家族とのメッセージと写真は使える。**アプリの登録やパスワードの設定は、いつも娘にやってもらっている。** メールアドレスは持っているが、ふだん使わない |

**園とのかかわり方**

| 場面 | していること | 気にしていること |
| :-- | :-- | :-- |
| 週2回のお迎え | 担任から、その日の様子を口頭で聞く | 聞いたことを娘に正しく伝えられるか |
| 急な呼び出し | 娘夫婦が仕事で出られないとき、代わりに迎えに行く | 園からの連絡が自分に届くか |
| 家で | 孫の様子を、娘から聞いて知る | 自分も園での様子を知りたい |

**大事にしていること**

- 孫を安全に連れて帰ること。お迎えに行くのが自分であると、園に分かっていること
- 娘夫婦に手間をかけさせないこと。**自分ひとりで登録を済ませたい**
- 分からないことを、分からないまま進めないこと

**困りそうなこと**

- 紙に印刷された英数字を、小さな画面に打ち込む
- 長い文章（利用規約）を、小さな字で読む
- パスワードを決め、それを覚えておく

**このシステムに期待すること**

- 紙に書いてあるとおりに打てば、登録できること
- うまくいかないとき、誰に聞けばよいかが分かること
- 孫の様子が、自分のスマートフォンでも読めること

## 3 感想（この人の立場で見たときの推定）

**助かると感じそうなところ**

- **やることが上から順に並んでいる。** いまどこにいて、あと何が残っているかが分かる。先の段は薄くなっていて、順番を飛ばせない
- **打ち間違えたとき、「園から配布されたコードをお確かめください」と言ってくれる。** 何を見直せばよいかが分かる
- **コードが合うと「確認しました。次へ進んでください」と出る。** 合ったことが分かるので、安心して次へ進める
- **続柄に「祖母」がある。** 自分のような立場の人が使うことが想定されていると感じる

**不安になりそうなところ**

- **紙のとおりに打ったつもりなのに、通らない。** ハイフンを打たなかっただけで「確認できません」と言われる。どこが違うのか分からず、コードを疑い、紙を疑い、自分を疑う
- **「有効期限が切れています」と言われても、どうすればよいか分からない。** 園に電話すればよいのか、次のお迎えまで待つのか。書いていない
- **「登録する」を押したら、止まった。** ずっと「登録しています…」のまま。壊したのか、待てばよいのか、もう一度押してよいのか分からない。**ここで登録をあきらめる**
- **利用規約が長く、字が小さい。** 画面には 11〜13px の文字もある。読んだことにしてチェックを入れる
- **メールアドレスが要る。** ふだん使わないので、正しく打てているか自信がない。確かめる手段（確認のメールが届くなど）は無い
- **パスワードを忘れたら、どうすればよいのか分からない。** 入口には何も書いていない

**登録できたあとに感じそうなこと**（不具合を直したあとの続きから）

- **登録できたのかどうか、一瞬分からない。** 何も言われずに画面が変わる。「できました」の一言がほしい
- **孫の名前が最初に出て、ほっとする。** 間違った子どもの画面ではないことが、すぐ分かる
- **いきなり「未読5」と出る。** 自分宛てに5件も来ていたのかと思う。開いてみると、登録する前の、娘と先生のやりとりだった。**読んでよいものだったのか**が気になる
- **日誌に「写真 1」と書いてあるのに、写真が見えない。** 一番見たかったものが見られない
- **先生に、自分が祖母だと伝わっているのかが分からない。** 最初の一言で名乗ったが、名乗らなければ「鈴木 和子」という名前しか先生には見えない

**全体として**

登録の画面の組み立ては分かりやすい。段を追って進む作りは、不慣れな人に向いている。しかし**「紙に書いてあるとおりに打てば登録できる」という一番の期待が、2か所で裏切られた**。ハイフンを省くと通らず、最後のボタンで止まる。この人は自分ひとりで済ませたかったのに、娘に頼むことになる。そして娘が試しても、同じところで止まる。

## 4 見つけた問題点

実際に画面で起きたことだけを挙げる。**どう直すかは書かない。** 1巡目で挙げたものは繰り返さない。

### 4-1 登録できない・全体が止まる

| 画面 | 起きたこと | 論点 |
| :-- | :-- | :-- |
| 新規登録画面 | **「登録する」を押すと、サーバが応答しなくなる。** 登録は完了せず、その後は**ほかの利用者のログインも通らなくなる**（サーバを再起動するまで）。メールアドレスを正しく入れた場合と、空のまま押した場合の両方で起きた | **保護者が1人登録を試みるだけで、園全体でシステムが使えなくなる。** **2026-10-06 に直した**（個人チャットのルーム名を、取引を始める前に引くようにした。修正後は登録が 0.1 秒ほどで終わることを確かめた）。原因は Go サーバの登録処理にある（`server/api_auth.go` の `handleSignUpGuardian`。データベースへの接続を1本に絞っている状態で、登録の途中に別の問い合わせを出しており、互いを待ち続ける）。ブラウザ内モック（`npm run dev:mock`）で同じことが起きるかは確かめていない。結合テスト12件はこの状態で通っているため、**新規登録は結合テストの対象に入っていないとみられる** |
| 新規登録画面 | **メールアドレスを空のまま「登録する」を押せる。** 入力を促す表示は出ない | メールアドレスはログインIDである（要件定義書「ログインIDの定義」(4-1-1)）。空のまま登録の処理へ進ませないための検査が、画面にもサーバにも無い |

### 4-2 はじめての人がつまずくもの

| 画面 | 起きたこと | 論点 |
| :-- | :-- | :-- |
| 新規登録画面 | **ハイフンを省くと、正しいコードでも「確認できません」と出る** | 基本設計書「招待コード（t_invitation_code）」(5-2) は、入力欄の扱いを「ハイフンは**入力しても省略してもよい**。省略された場合はシステムが補う」と定め、理由を「打ち方の違いで失敗させない」としている。モックアップは省略を受け付けない |
| 新規登録画面 | 期限切れのとき「この招待コードは有効期限が切れています」と出るが、**次に何をすればよいかは出ない** | 園に再発行を頼む、という次の行動を示すかどうか |
| 保護者用トップ | **パスワードを忘れたときの案内が無い** | 再設定は「管理者による一時パスワードの再発行」と定められている（要件定義書のログイン機能の一覧にある「パスワードの再設定」、基本設計書「一時パスワードの再発行」(4-3)）。仕組みはあるが、**保護者がそれを知る場所が無い** |
| 利用規約同意画面 | 規約が改定されたとき、**どこが変わったのかが示されない** | 全文を読み直すことになる。差分を示すかどうかは、以前に `要決定事項.md` で扱った論点である。確定した内容と画面が合っているかの突き合わせが要る |
| 新規登録画面・利用規約同意画面 | 「※本文は草案です。園情報の記入と法務の確認が未了です。」が保護者の画面に出ている | `利用規約・プライバシーポリシー.md` が草案であることに由来する。保護者に見せる前に確定が要る |
| 保護者向けの全画面 | **11px・12px・13px の文字がある**（送信時刻、補足の説明など） | 保護者には高齢の利用者も含まれる。端末側の文字の拡大がどこまで効くかは実機で確かめる必要がある |
| 新規登録画面 | 招待コードの入力欄に、例として `ABCD-1234-EFGH` が薄く出ている。これは**デモデータに実在するコード**である | 入力例に、実際に発行されうる形の値を使うことの是非 |

### 4-3 園の側の操作で気づいたこと

祖母の登録を進めるために、管理者として招待コードを発行した際に気づいたものである。

| 画面 | 起きたこと | 論点 |
| :-- | :-- | :-- |
| 招待コード管理画面 | 発行の手段が**「一括発行」（クラス単位）だけ**で、園児1人に1枚だけ出す操作が見当たらない | 基本設計書「画面の一覧」(3-2) は、この画面の機能を「招待コードの発行・一括発行・失効」としている。祖父母の分を1枚足す、期限切れの1枚を出し直す、といった場面で、クラス全員分を発行することになる |
| 招待コード管理画面 | デモデータのコードは、発行日（2026/09/28）より有効期限（2026/09/25）のほうが前になっており、すべて期限切れだった | デモデータの日付をずらす処理（`MOCKUP.md`）が、発行日には効いて有効期限には効いていない。**起動した日によっては、新規登録のデモが最初からできない** |
| 招待コード管理画面 | 発行の完了は、ブラウザの標準の通知（「12 枚を発行しました」）で示される | 1巡目で挙げた「完了を知らせる表示が出ない」に対して、ここだけ別の示し方になっている |

### 4-4 登録したあとに気づいたこと

不具合を直して登録を完了したあと、祖母・担任・母のそれぞれの画面で気づいたものである。

| 画面 | 起きたこと | 論点 |
| :-- | :-- | :-- |
| チャット画面（保護者） | **新しく登録した保護者が、登録する前の個人チャットのやりとりをすべて読める。** 未読の数にも数えられる | 個人チャットは園児ごとに1つのルームである（基本設計書「チャット」(5-5)）。後から加わった保護者に、それ以前のやりとりを見せるかどうか。祖父母やきょうだいの保護者が後から加わる場面で、**先に登録していた保護者は、自分の書いたものが読まれることを知らない** |
| チャット画面（職員） | 新しい保護者が加わっても、**職員にそのことを知らせる表示が無い**。メンバー一覧に名前が1つ増えるだけで、**続柄（祖母）も出ない** | お迎えに来る人が誰なのかは、園児の安全にかかわる。続柄は登録のときに入力させているが、職員の画面で使われていない。先に登録していた保護者にも知らされない |
| 保護者ホーム | 登録を終えた直後、**完了を知らせる表示も、はじめての人への案内も出ない** | 1巡目で挙げた「完了を知らせる表示が出ない」の、保護者にとって最初の場面である |
| 共有日誌閲覧画面 | 写真が付いた日誌で、写真の代わりに「**写真 1**」「**写真 2**」という文字だけが出る | 添付が未実装であることによる（`ペルソナ/保育士_佐藤明子.md`）。保護者がいちばん見たいものが見えない |

**確かめて、問題が無かったもの**

- 使用済みの招待コードでは、もう一度登録できない（「この招待コードはすでに使われています」）
- 登録したメールアドレスとパスワードで、ログインし直せる
- 大文字で発行されたコードを小文字で打っても通る

---

## 5 確かめられなかったこと

- **メールアドレスを空のまま登録した場合に、何が登録されるか。** 不具合を直す前は、空のままでも登録の処理へ進んでいた。直したあとは、招待コードを使い切らないよう試していない
- **新規登録を通す結合テストの追加。** デモデータの招待コードがすべて期限切れのため、そのままでは自動のテストに組み込めない
- **続柄によって見える範囲や連絡の届き方が変わるか。** 続柄の選択肢に祖母・祖父があるが、権限や通知に違いがあるかは確かめていない
- **人が紙を見ながら打ったときの打ち間違いの起きやすさ。** `0` と `O`、`1` と `I` のような読み違いが、実際のコードでどの程度起きるか
- **実機での文字の大きさ。** 端末の設定で文字を大きくしたとき、画面が崩れないか
- **招待コードの配布用の出力**（紙にどう印刷されるか）
