## 0 この文書について

**このペルソナは架空の人物であり、実在の保護者への聞き取りにもとづかない。** 要件定義書「コンセプトとターゲット層」(1-1) から起こした**たたき台**である。

- **デモを操作したのは Claude である。** 人が触った結果ではない。「感想」は、この人物の立場に立って画面を見たときの**推定**であり、利用者の声として引用しない
- **「見つけた問題点」は、実際に画面で起きたことだけを書いた。** 確かめきれなかったものは「確かめられなかったこと」(5) に分けた
- 問題の指摘と論点の提示に留め、**どう直すかの結論は書かない**
- 氏名はモックアップのデモデータのものである。実在の人物ではない

## 1 ペルソナ

| 項目 | 内容 |
| :-- | :-- |
| 氏名 | 山田 健一（やまだ けんいち） |
| 年齢・仕事 | 34歳。会社員。フルタイム勤務で、配偶者も働いている |
| 子ども | 山田 太郎（1歳4か月・さくら組）。第一子。卵アレルギーがある |
| システム上の権限 | 保護者 |
| 使う端末 | 自分のスマートフォン。通勤の電車と、子どもが寝たあとに開く |
| ITの慣れ | 仕事でチャットを毎日使う。アプリの操作に抵抗はない |

**園とのかかわり方**

| 場面 | していること | 気にしていること |
| :-- | :-- | :-- |
| 朝の送り | 配偶者と交代で送る。担任と話せるのは1〜2分 | 体調のことを伝えきれたか |
| 日中 | 仕事中は電話に出にくい | 園からの連絡に気づけるか |
| 夕方の迎え | 祖母に頼む日がある | 誰が迎えに行くかが園に伝わっているか |
| 夜 | 子どもが寝たあとに、その日の様子を読む | 今日どう過ごしたか。ちゃんと食べたか |

**大事にしていること**

- 自分が見ていない時間の子どもの様子を知ること
- 園に伝えたことが、担任に確実に届くこと
- アレルギーのことを、園の誰もが把握していること

**困っていること（現状の紙と電話の運用で）**

- 連絡帳を書くのは送る側の親だけで、もう一方は園での様子を知らないまま過ごす
- お迎えの変更や欠席を電話で伝えると、朝の忙しい時間に園の電話がつながらない
- 伝えたことが担任まで届いたのか、確かめる方法がない

**このシステムに期待すること**

- 夫婦のどちらからでも、同じ情報が見られること
- 連絡が届いたこと、読まれたことが分かること
- 急ぎのときにどうすればよいかが、迷わず分かること

## 2 デモの筋書きと結果

「夜、子どもが寝たあとにスマートフォンを開く」場面を想定して、次の順に操作した。

| 場面 | やったこと | 起きたこと |

## 3 感想（この人の立場で見たときの推定）

**助かると感じそうなところ**

- **開いてすぐ、子どもの今日が読める。** ホームから1回押すだけで日誌に届く。寝かしつけのあとの短い時間で読み切れる
- **送る担当でない日でも、園の様子が分かる。** 連絡帳を持っていない側の親にも同じものが届く
- **お迎えの変更を、電話せずに伝えられる。** 朝の電話がつながらない時間を待たなくて済む。担任から「承知しました」と返ってくるので、届いたことが分かる
- **入口を間違えても、どこへ行けばよいか教えてくれる。** 「ログインできません」で止まらない
- **画面がすっきりしている。** 押せるものが少なく、迷わない

**不安になりそうなところ**

- **「急ぎは電話で」と書いてあるのに、電話番号がどこにも無い。** 熱が出た朝に、このアプリから園の番号を探すことになる
- **欠席の連絡が読まれたのかが分からない。** 返信が来るまで、伝わったかどうかが分からない。朝のうちに返信が無ければ、結局電話をかける
- **「担任の先生とのやりとり」に、園長先生からのメッセージが来る。** 担任と自分だけの場所だと思って書いていた。誰が読んでいるのかを、最初に知っておきたかった
- **日誌の下の「S003」「S001」が何か分からない。** 誰が書いたのかを知りたいのに、記号しか出ていない
- **長い文を打つと、自分が何を書いたか見えない。** 体調のことは長くなる。打ち間違いに気づけない
- **送ったメッセージを取り消せない。** 編集はできるが、配偶者と二重に送ってしまったときに消せない
- **「さくら組」に、先生どうしの相談が見えている。** 見てよいものなのかが分からず、落ち着かない

**全体として**

「園での様子が分かる」という期待には応えている。日誌が読める喜びは大きい。一方、**「伝えたことが届いたか」「急ぎのときどうするか」という、園に連絡する側としての不安**は残る。記録を読む場面はよくできているが、連絡する場面はまだ細い、と感じた。

## 4 見つけた問題点

実際に画面で起きたことだけを挙げる。**どう直すかは書かない。**

### 4-1 伝達の確かさ・信頼にかかわるもの

| 画面 | 起きたこと | 論点 |
| :-- | :-- | :-- |
| 保護者ホーム・チャット画面（保護者） | 「急なご連絡はお電話でお願いします」とあるが、**園の電話番号も、電話をかけるリンクも無い** | 基本設計書「画面基本構成」(3-5) は、緊急連絡の案内を置く理由を「その場で電話へ切り替えられる案内が要る」としている。番号が無いと切り替えられない。**園の電話番号をどこに持つかは、基本設計書に定めが見当たらない**（設計の抜け） |
| 共有日誌閲覧画面 | 記入者と確認者が「**記入：S003　／　確認：S001**」と職員IDで出る | 保護者に見せる名前を何にするか（氏名か、「担任」「園長」のような立場か） |
| チャット画面（保護者） | 「担任の先生とのやりとり」に園長の投稿が届く。**このチャンネルを誰が読めるのかは、保護者の画面に示されていない**（職員側のメンバー一覧には、園長・担任2名・保護者が並んでいる） | チャンネルの名前と、実際に読める人の範囲が合っていない。保護者にどこまで示すか |
| チャット画面（保護者） | 「さくら組」のチャンネルに「こちらは**園からのお知らせ**です。返信はできません。」と出る | 文言がチャンネルと合っていない。クラスグループへ保護者が投稿できないこと自体は、モックアップのサーバ側の制御どおりである |
| チャット画面（保護者） | 自分のメッセージに「編集」はあるが、**「取消」が無い** | 基本設計書の権限一覧「メッセージの編集・送信取消」は、保護者にも自分の投稿の取消を認めている。モックアップには無い |

### 4-2 使い勝手にかかわるもの

| 画面 | 起きたこと | 論点 |
| :-- | :-- | :-- |
| チャット画面（保護者） | 入力欄が**1行**で、長い文は打っている途中に前半が見えない（職員側は複数行の入力欄） | 体調や家庭での様子の連絡は長くなる |
| チャット画面（保護者） | 送信後、**入力欄が最新の吹き出しに重なり**、文の終わりが隠れる | 最新のメッセージが読めない |
| チャット画面（保護者） | 写真などを添付する手段が見当たらない（職員側には「添付」がある） | 保護者からの添付を認めるか。認めるなら範囲をどうするか。要件定義書「添付ファイルの制限」(4-3) との突き合わせが要る |
| チャット画面（保護者） | リアクションの操作が見当たらない | 要件定義書「チャットツール」(4-3) は全ロールにリアクションを定めている。「読みました」を一言で返す手段になりうる |
| パスワード変更画面 | 「（**制約値は未確定です**）」という開発中の注記が、保護者の画面に出ている | パスワードの要件は基本設計書「データ保護」(6-3) で確定済みである。古い注記が残っている |
| メニュー | 表示されるのは「山田 太郎ちゃんの保護者」で、**ログインしている本人の氏名は出ない**。チャットでも自分の投稿は「私」と出る | 両親がそれぞれアカウントを持つ場合、どちらでログインしているかを確かめる手がかりが無い |

### 4-3 この人の立場から出てくる問い

不具合ではなく、設計の判断として決まっていることへの問いである。

| 問い | 背景 |
| :-- | :-- |
| 送った連絡が読まれたかを、保護者は知ることができないのか | 既読は保護者側に表示しない定めである（基本設計書「既読確認」(4-6)）。欠席やお迎え変更のように**返事が要る連絡**では、届いたかどうかが分からない不安が残る |
| 欠席・お迎え変更の連絡が、ほかの雑談と同じ扱いでよいのか | 専用の機能を設けずチャットで受ける、という演習上の想定である（`要決定事項.md`「演習上の想定として置いたもの」(1-1)）。園の側で見落とさない仕組みは、職員側の「未対応スレッドの管理」に頼ることになるが、モックアップには未実装である（`ペルソナ/保育士_山田花子.md`） |
| 身体測定や発達チェックの共有された記録は、どこで見るのか | ホームの「共有された記録」に出ていたのは日誌だけだった。今回は職員側から発達・身体の共有を行っていないため、見え方を確かめていない |

## 5 確かめられなかったこと

- **人が触ったときの感じ方。** 操作は自動で行った。片手で持って親指で押したときの届きやすさ、文字の読みやすさは分からない
- **実機での見え方。** PC のブラウザでスマートフォンの画面幅とタッチ操作を再現した。iPhone の Safari や Android では確かめていない。特に、**文字入力のキーボードが出たときに入力欄がどこへ動くか**は実機でないと分からない
- **はじめて使うときの流れ。** 招待コードでの新規登録、利用規約への同意は今回の筋書きに入れていない。保護者にとって最初の体験であり、別に確かめる必要がある
- **きょうだいがいる場合、両親がそれぞれログインした場合の見え方**
- **通知。** 新しいメッセージが届いたことを、アプリを開いていないときに知る手段は、演習の範囲外である（要件定義書「通知の到達性」）。ベルの件数は、開いたときに見えるものでしかない
- **停止されたアカウント、規約の再同意が必要なアカウントでの見え方**
