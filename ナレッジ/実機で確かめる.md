# 実機で確かめる

デプロイした画面（公開先。Oracle Cloud の VM。URL は本線の `deploy/oci-free/README.md`）を、iPad やスマホの本物の画面で確かめるときの手順。`localhost` で立てて見る方式は無い（`決定事項.md` 2026-11-06）。

> **中間発表のデモで映す手順の正は、本線の `デモ手順書.md`**（2026-11-05 版。uxplay で iPad と iPhone を2つの窓に映す）。デモ手順書の推しのつなぎ方は、下の「2台を映すときのつなぎ方」で 2026-11-06 に確かめた。ただしデモ手順書は、uxplay の設定が `-reset 0 -nohold`、iPhone を映せるかが「試していない」のままで、この節と違う（2026-11-06 時点）。

## 2台を映すときのつなぎ方（2026-11-06 にうまくいった形）

iPad（保育士）と iPhone（保護者）を、パソコンの uxplay の2つの窓に同時に映すとき。2026-11-06 のデモでこの形にして、ラグと止まりが無くなった。

### 形

- **iPhone は USB ケーブルでパソコンにつなぐ。** パソコンのインターネットは、iPhone の USB テザリングから取る。iPhone の映像（保護者）もケーブルで届く
- **iPad はパソコンのモバイル ホットスポットにつなぐ。** iPad の映像（保育士）は、iPad からパソコンへ直接届く
- **パソコンの Wi-Fi は、ホットスポットを出すだけに空けておく。** 学校の Wi-Fi にも iPhone の Wi-Fi のテザリングにもつながない

| | 前の形（パソコンも iPad も iPhone の Wi-Fi のテザリングに入れる。2026-11-06 午後） | この形 |
| :-- | :-- | :-- |
| パソコンから iPhone までの応答 | 20〜448 ms | USB で 1 ms |
| パソコンから iPad までの応答 | 測れない（iPhone を中継する） | 1〜88 ms（画面が止まっている間に長くなる） |
| iPad からの合図の途切れ（映像が止まる） | 14 分で 84 回（1回 3〜24 秒） | 0 回 |

### 初めてのパソコンで1回だけ

- **Apple Devices アプリ**（Microsoft Store）と **Apple Mobile Device Support** を入れる。Apple Mobile Device Support は `winget install --id Apple.AppleMobileDeviceSupport` で入る。入れるときに「変更を許可しますか」が出るので「はい」を押す
  - Apple Devices アプリだけでは、USB のネットの口（Apple Mobile Device Ethernet）が出なかった（2026-11-06）。Apple Mobile Device Support を入れて、iPhone のケーブルを挿し直したら出た

### 手順

1. **iPhone**：「設定 → インターネット共有」をオンにして、USB ケーブルでパソコンにつなぐ。ロックを外し、「このコンピュータを信頼しますか？」で「信頼」を押す
   - パソコンの「Apple Mobile Device Ethernet」が「切断」のままなら、iPhone の「ほかの人の接続を許可」をオフにしてオンに戻す。2026-11-06 はこれでつながり、パソコンに `172.20.10.x` が付いた
2. **パソコン**：Wi-Fi を空ける。学校の Wi-Fi と iPhone のテザリングの自動接続を止めてから、Wi-Fi を切る。止めないと、学校の Wi-Fi（優先が上）にすぐつながり直す

   ```
   netsh wlan set profileparameter name="<学校の Wi-Fi の名前>" connectionmode=manual
   netsh wlan set profileparameter name="<iPhone のテザリングの名前>" connectionmode=manual
   netsh wlan disconnect interface="Wi-Fi"
   ```

3. **パソコン**：「設定 → ネットワークとインターネット → モバイル ホットスポット」をオンにする。共有するのは「Apple Mobile Device Ethernet」の接続。ネットワーク帯域は「使用可能なすべて」のまま
   - 5 GHz を選ぶと立ち上がらなかった（2026-11-06。理由は `WiFiDeviceOff`）。「使用可能なすべて」なら立ち上がった。iPad がどちらの帯でつながったかは確かめていない
   - ホットスポットに `192.168.137.1` が付くまで、数十秒かかった
4. **iPad**：Wi-Fi で、パソコンのホットスポットの名前を選び、パスワードを入れる。名前とパスワードは、パソコンのモバイル ホットスポットの画面に出る（文書には書かない）
5. **パソコン**：uxplay を2つ起動する。スタートメニューの「uxplay 保育士（iPad・緑）」と「uxplay 保護者（スマホ・青）」
6. **映す**：iPad は「保育士」、iPhone は「保護者」を選ぶ。**iPhone は USB でつないだまま一覧に「保護者」が出て、映せた**（2026-11-06）

### 終わったら戻す

- モバイル ホットスポットをオフにする
- 自動接続を戻す

  ```
  netsh wlan set profileparameter name="<学校の Wi-Fi の名前>" connectionmode=auto
  netsh wlan set profileparameter name="<iPhone のテザリングの名前>" connectionmode=auto
  ```

- iPhone のケーブルを抜く。挿したままだと、パソコンのインターネットが iPhone 経由になり、スマホのデータ量を使う

### デモ中に気をつけること

- **iPhone のケーブルを抜かない。** パソコンのインターネット（iPad のインターネットも）と、保護者の映像が両方切れる
- **映像の窓を最小化しない。** 2026-11-06 に、最小化された保育士の窓が止まって見えた
- **パソコンを電源につなぐ。** このパソコンは電池だと 3 分でスリープし、Wi-Fi が切れる（2026-11-05 に電源の設定で確かめた）
- 固まったら、iPad・iPhone で「画面ミラーリング」を選び直す。前の接続が残っていると、最大 30 秒は断られる（下の `-reset 30`）

### uxplay の設定

`%APPDATA%\leapbtw\uxplay-windows\arguments.txt`（保育士）と `%APPDATA%\leapbtw\uxplay-windows-2\arguments.txt`（保護者）。2026-11-06 の中身：

```
-n uxplay-windows -nh -m 02:55:58:50:4C:01 -reset 30
-n uxplay-windows-2 -nh -m 02:55:58:50:4C:02 -reset 30
```

- **`-nohold` は入れない。** iOS は「画面ミラーリング」の一覧を開くと、見えている受け手すべてに問い合わせる。`-nohold` があると、その問い合わせだけで、いま映している人が追い出される。2026-11-05 に、iPad の問い合わせで保護者の iPhone が追い出されたのをログで確かめた（UxPlay の `lib/raop.c`）
- **`-m` で受け手の ID を決めておく。** 無いと、パソコンの最初のネットの口の MAC を使う。WSL があるパソコンでは、それが再起動のたびに変わる仮想の口で、iPad から別の受け手に見える
- **`-reset 30`**：iPad からの合図が 30 秒途切れたら切る。`0`（切らない）だと、固まった接続が残り、選び直しても断られ続ける（`-nohold` を外したため）
- ログは `%LOCALAPPDATA%\uxplay-windows\logs\`（保育士）と `%LOCALAPPDATA%\uxplay-windows-2\logs\`（保護者）。止まった理由は、ログの `seconds since last client feedback`（合図の途切れ）と `lost connection` で見る

### うまくいかなかったこと（2026-11-05〜06）

- **パソコンも iPad も、iPhone の Wi-Fi のテザリングに入れる**：つながるが、2台ともラグがひどく、iPad は 10 秒おきに止まった。テザリングが 2.4 GHz のチャンネル 6 で、学校の Wi-Fi など周りの 5 つと取り合っていた。iPad の映像は iPad → iPhone → パソコンと iPhone を中継するので、電波を2回使う
- **iPhone の「互換性を優先」をオフにする**：テザリングを起動し直しても 2.4 GHz のままだった（2026-11-06）。オフにしたあと、パソコンからテザリングが見えなくなり、「ほかの人の接続を許可」をオフにしてオンに戻すまで出てこなかった
- **`-vsync no`**（映像を音の時刻に合わせない。遅れを減らすつもり）：2026-11-06 に入れて試したが、効き目は確かめられなかった。いまは入れていない

## iPad の画面をパソコンに映す（学校で）

2026-10-30 に、SIM の無い iPad でデプロイした画面を開き、パソコンに映すために使った。

### 手順

1. **パソコンをスマホのテザリングにつなぐ**
   - USB でつなぐのが確実
   - iPhone：「設定 → インターネット共有」をオンにして、USB ケーブルでつなぐ。Windows に Apple Devices アプリと Apple Mobile Device Support が要る（上の「初めてのパソコンで1回だけ」。2026-11-06 に、Apple Devices アプリだけでは足りないと分かった）
   - Android：「設定 → ネットワーク → テザリング → USB テザリング」をオンにする
2. **パソコンをモバイル ホットスポットにする**
   - Windows の「設定 → ネットワークとインターネット → モバイル ホットスポット」をオンにする
   - 「インターネット接続を共有する」を USB の接続にする。iPhone なら「Apple Mobile Device Ethernet」、Android なら「Remote NDIS」のような名前で出る
   - 迷ったら、パソコンの学校の Wi-Fi を切る。USB しか選べなくなる
   - iPad の Wi-Fi で、ホットスポットのネットワーク名を選び、パスワードを入れる
3. **ミラーリングする**
   - パソコンで、AirPlay を受けるソフトを起動する（5KPlayer・AirServer・LonelyScreen など）。初回はファイアウォールの許可を「許可」にする
   - iPad のコントロールセンターから「画面ミラーリング」を押し、パソコンの名前を選ぶ

### うまくいかなかったこと

- **学校の Wi-Fi のまま、パソコンをホットスポットにする**：iPad はつながるが、オフラインになる（2026-10-30）。学校の Wi-Fi が、プロキシか端末ごとの認証で、共有した先の通信を通さないためと見ている（原因は確かめていない）
  - ミラーリングだけなら、iPad とパソコンの間の通信なので、オフラインのままでも動くはず（試していない）
- **スマホのテザリングがパソコンの Wi-Fi の一覧に出ない**（2026-10-30）：iPad からはつながるのに、パソコンには出なかった。パソコンで探し直しても、見える Wi-Fi が学校の `eduroam` の1つだけだった。パソコンの Wi-Fi が、つないでいる先のほかを探せなくなっていた。**機内モードをオンにしてオフに戻したら直った**
  - 前は Wi-Fi でテザリングにつないでいた。USB のドライバ（Apple Devices）は入っていないので、USB のテザリングは使っていない
  - 機内モードで直らなければ、パソコンの再起動、その次に「設定 → ネットワークとインターネット → ネットワークの詳細設定 → ネットワークのリセット」（試していない）
- **iPhone のテザリングに、iPad とパソコンの両方をつなぐ**：端末どうしの通信が遮られて、ミラーリングの一覧にパソコンが出ないことがある。パソコンを親機にすれば避けられる

### 気をつけること

- サイトの表示はスマホのデータ量を使う。ミラーリングそのものはパソコンと iPad の間だけなので使わない
- スマホの電池がかなり減る。USB でつないだまま充電しながら使う

## パソコンで画面の大きさをまとめて見る

本物の端末ではなく、パソコンで iPhone・iPad の画面の大きさを並べて見るなら、Responsively App を使う。デプロイ先の URL を入れるだけで、iPad のテザリングは関係ない。
