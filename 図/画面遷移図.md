# 0 本書の位置づけ

- 本書は**図**であり、画面と画面の**つながり（遷移）**を示す。学校テンプレート「【テンプレート】3_基本設計書.docx」がユーザインターフェイス設計の章で求める**画面遷移図（別紙）**にあたる。
- **画面そのものの定義**（画面名・概要・利用者・表示項目・入力項目）は `基本設計書.md`「画面の一覧」(3-2)「画面詳細」(3-6) と `図/画面詳細図.md` が持つ。本書は画面名を参照するだけで、定義を重複して持たない。
- **利用者種別ごとの画面の所属**は `基本設計書.md`「画面体系図」(3-3) が持つ。本書が示すのは所属ではなく遷移である。
- **遷移の前提**（初回ログインの順番、通知を押したときの行き先、確認画面を挟む範囲、外した遷移）は `基本設計書.md`「画面遷移」(3-4) が持つ。本書はそれを図と一覧表に描く。
- **画面の数は書かない。** 数を持つのは `基本設計書.md`「画面の一覧」(3-2) と `図/画面ID対応表.md`「権限別の画面数」(3) だけである。
- 記述が食い違った場合は、**要件定義書 → 基本設計書 → 本書**の順で正とし、本書を追随させる。
- **モックアップは正ではない。** 本書に貼った画面画像は、第2.7版の設計で作ったモックアップを写したものである。第3.0版で足した画面には画像が無く、変えた画面の画像は古い姿のままである（「画面画像の出典」(0-2)）。実装が設計と食い違っていれば、設計に合わせて実装を直す。

> **退役させた文書**：`画面遷移図_チャットツール.md` 第0.2版（ドラフト、2026/07/27）。チャットツールの遷移は本書「チャットツール」(5) が持つ。**画面遷移図の正を1本に絞る**方針による（要件定義書・基本設計書と同じ扱い）。内容は git 履歴に残る。

## 0-1 表記ルール

| 表記 | 意味 |
| :-- | :-- |
| 実線の矢印 `-->` | 利用者の操作による遷移 |
| 点線の矢印 `-.->` | 条件が成立したときにシステムが起こす遷移（一時パスワード、規約の改定など）と、画面の外からの入口（Web Push の知らせ） |
| ラベルの「管理者」 | **管理者（園長・主任）のみ**が通れる遷移。一般（保育士）には導線を表示しない |
| ダイアログ | 画面として起こさず、元の画面の上に重ねる（`基本設計書.md`「画面の洗い出しの考え方」(3-1) の基準3）。図では名前に「（ダイアログ）」を添える |
| 丸い枠 `([ ])` | 画面ではない入口（Web Push の知らせ、全画面のヘッダの通知など） |
| 同じ画面の中の切り替え | 前の日・次の日、チャンネルの切り替え、保護者のチャットの一覧と会話の入れ替えなど。**遷移として描かず**、一覧表に「同じ画面の中の切り替え（遷移ではない）」と書く |

- 画面名は `基本設計書.md`「画面の一覧」(3-2) の名称と一致させる。本書で言い換えない
- 画面IDは採番しない（`CLAUDE.md`「機能は番号ではなく機能名で呼ぶ」の方針）。画面IDは `図/画面ID対応表.md` だけが持つ
- 節の並びは `基本設計書.md`「画面の一覧」(3-2) の区分の順（共通・認証／連絡帳／日誌／チャット／午睡／発達・身体・成長の記録／マスター・アカウント・設定）とし、最後に保護者が使う画面をまとめた節を置く

- **よく使う記録と「確認しました」は、連絡帳（クラス）画面の行の上で終える**（1件3タップ以内。`基本設計書.md`「画面基本構成」(3-5) の「誰でも使える操作の条件」）。連絡帳（園児）画面へ移るのは、活動のひとこと・写真・「園から」を書くとき、1人のページを読むときである
- **午睡の「ねた」「おきた」は、午睡チェック画面の園児の行で記録する**（「午睡チェック」(6)）。連絡帳の画面へは移らない。記録はそのまま連絡帳のきょうのようすに並ぶ。午睡チェックを終えたあとの押し間違いは、連絡帳（園児）画面で直す
- 管理者は連絡帳（クラス）画面でクラスを選び、全クラスの連絡帳を**あとから読む**。事前の承認の画面は無い
- 日誌から連絡帳への道は「クラスのようすへ引き写す」の1つだけである。**写しただけでは保護者に届かない**（段2の守りを通って職員が送る）。個人日誌の午睡・食事の欄は、逆に、きょうのようすから日誌の下書きに入る（日誌作成・編集画面の中の操作。遷移ではない）

# 4 日誌システム

日誌は**園内の記録**である（`基本設計書.md`「保護者へ届けるときの関所」(2-4) の段3）。承認は園内の確認として残る。例外として、保育士が共有を選んで申請し、管理者が承認した個人日誌は、保護者が園からの日誌画面で読む（第2.5版）。

```mermaid
flowchart TD
    SD["職員ダッシュボード"] --> DL["日誌一覧画面"]
    DL -->|新しく書く・開く| DE["日誌作成・編集画面"]
    DE -->|一覧へ戻る| DL
    DE -->|確認へ進む| DC["日誌確認画面"]
    DC -->|戻る| DE
    DC -->|申請する| DL
    DL -->|PDF 出力・管理者| PDF["出力の条件（ダイアログ）"]
    PDF --> DL
    CL["園児一覧画面"] -->|記録| DT["園児タイムライン画面"]
    DT -->|開く| DE
    DT -->|園児一覧へ| CL
    SD -->|承認待ちの日誌・管理者| AL["承認待ち一覧画面"]
    AL -->|承認へ| AP["日誌承認画面"]
    AP -->|承認・差し戻し| AL
    DE -->|クラスのようすへ引き写す| CC["連絡帳（クラス）画面"]
    NA["異常時記録画面"] -.->|ヒヤリハットを起票| DE
```

- **園児タイムライン画面への導線は園児一覧画面が持つ。** 本書 第1.2版は日誌一覧画面からとしていた（「モックアップ実装との差異」(10) No.4）

# 5 チャットツール

チャットは**会話の窓口**である。保護者が記録を読むのは連絡帳画面と成長の記録画面であり、**日誌・発達・身体の記録を共有するカードはチャットに流さない**（`基本設計書.md`「画面の一覧」(3-2)）。職員側では、チャンネルの切り替え・メッセージの送受信・リアクション・「確認しました」・既読確認が**チャット画面の中で完結する**。保護者側も画面としては1つで、**チャンネル一覧と会話の切り替えを画面の中の状態変化として持つ**（実装でも URL は変わらない）。

```mermaid

    SD["職員ダッシュボード"] -->|未対応の個人チャット| SCH["チャット画面（職員）"]
    SCH -->|グループ編成| GE["グループ編成画面"]
    GE -->|チャットへ| SCH
    SCH -->|園からの配布物| HM["配布物管理画面"]
    HM -->|チャットへ| SCH
    SCH -->|写真を添える| PK["写っている子を選ぶ（ダイアログ）"]
    PK --> SCH
    SCH -->|連絡帳の引用| CK["連絡帳（園児）画面"]
    SD -->|誤送信対応・管理者| MS["誤送信対応記録画面"]
    PH["保護者ホーム"] -->|園児の区画の園とのやりとり| GCH["チャット画面（保護者）"]
```

- 保護者はチャット画面のみを利用し、グループ編成画面・誤送信対応記録画面への導線を持たない
- **誤送信対応記録画面へはチャット画面からではなく、サイドナビの「管理（管理者）」から入る**（「モックアップ実装との差異」(10) No.3）。連絡帳で送ったものの誤送信も同じ画面に記録する

# 9 保護者の画面
