# 0 本書の位置づけ

**本書は、提出時に学校テンプレートの様式を満たすための対応表である。**

本プロジェクトは**画面を番号ではなく名前で呼ぶ**方針を採っている（`CLAUDE.md`「機能は番号ではなく機能名で呼ぶ」）。番号だけでは何の画面か伝わらず、画面が増減したときに全体の番号がずれるためである。

一方、学校テンプレート「【テンプレート】3_基本設計書.docx」は **`n-n-n-n`（機能大分類-機能小分類-画面番号-権限）形式の画面ID**を求めている。

**両立させるため、本文では名前で呼び、提出時に本書で番号を添える。** `基本設計書.md`「本書の位置づけ」(1-4) で予告していた対応表がこれにあたる。

- **画面IDは本書だけが持つ。** 他の文書には書かない。書くと、画面が増減したときに直す場所が増える
- 画面名の正は `基本設計書.md`「画面の一覧」(3-2)。本書は名前を参照するだけで、定義を重複して持たない
- 画面の中身は `図/画面詳細図.md`、つながりは `図/画面遷移図.md` が持つ

# 1 採番の規則

`n-n-n-n` の各桁を次のとおり定める。

| 桁 | 意味 | 値 |
| :-: | :-- | :-- |
| 1桁目 | **機能大分類** | 1:共通基盤 2:日誌システム 3:チャットツール 4:午睡チェック 5:発達チェック・身体測定 6:園児マスター・アカウント管理 |
| 2桁目 | **機能小分類** | 大分類の中での機能のまとまり（下表） |
| 3桁目 | **画面番号** | 小分類の中の連番。**利用者がたどる順**に振る |
| 4桁目 | **権限** | 0:ログイン不要 1:管理者のみ 2:管理者・一般（職員） 3:保護者 9:全ロール |

**機能大分類は、`基本設計書.md`「画面の一覧」(3-2) の区分に合わせた。** 要件定義書「機能要件」(4) の節の並び（共通基盤／日誌／チャット／午睡／発達）と同じ順である。園児マスターとアカウント管理は共通基盤の一部だが、画面数が多いため大分類を分けた。

**機能小分類**

| 大分類 | 小分類 | 内容 |
| :-: | :-: | :-- |
| 1 共通基盤 | 1 | 認証（入口・登録・パスワード・規約） |
| | 2 | ホーム（ダッシュボード・保護者ホーム） |
| | 3 | 保護者への記録の共有 |
| 2 日誌システム | 1 | 作成と申請 |
| | 2 | 承認 |
| | 3 | 参照 |
| 3 チャットツール | 1 | 送受信 |
| | 2 | 運営（グループ編成・誤送信対応） |
| 4 午睡チェック | 1 | 実施 |
| | 2 | 参照 |
| 5 発達チェック・身体測定 | 1 | 発達チェック |
| | 2 | 身体測定 |
| | 3 | 設定（スケジュール・共有範囲） |
| 6 園児マスター・アカウント管理 | 1 | 園児マスター |
| | 2 | アカウント |
| | 3 | 運用（年度更新・監査） |

**4桁目の権限は、その画面を使える最も広い利用者を示す。** 「2:管理者・一般」の画面は管理者も使える（管理者は一般の全画面を利用できる。`基本設計書.md`「画面体系図」(3-3)）。参照できる**範囲**の制限（一般は自クラスのみ）は画面IDでは表さない。範囲は `基本設計書.md`「権限マトリクス」(6-1) が持つ。

# 4 画面が増減したときの手順

**画面IDは本書だけが持つため、直す場所は1か所である。**

1. `基本設計書.md`「画面の一覧」(3-2) に画面を足す／落とす
2. 本書の該当する小分類の表へ行を足す／落とす。**画面番号は小分類の中で振り直す**
3. `図/画面詳細図.md` と `図/画面遷移図.md` を直す
4. 「権限別の画面数」(3) の件数を数え直す

**既存の画面IDを使い回さない。** 落とした番号は空けたままにする。過去の提出物や議事録が古い番号を指している場合に、別の画面と取り違えるためである。
