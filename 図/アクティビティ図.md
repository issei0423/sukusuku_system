# 0 本書の位置づけ

- 本書は、`図/ユースケース図.md` の各ユースケースについて**処理の手順と分岐**を示す。誰が何をできるかはユースケース図が、扱うデータは `図/ER図.md` が保持する。
- **図は業務フロー単位で作成し、利用者種別ごとの一覧は 1 章に対応表として示す。** 同じフローに複数のロールが登場するため（申請は一般、承認は管理者など）、ロール単位に図を分けると1つの業務が分断されてしまうためである。図中では各アクティビティの先頭にロールを付す。
- 全体要件定義書と本書の記述が食い違った場合は、**全体要件定義書を正とし、本書を追随させる。**

## 0-1 図の凡例

| 記法 | 意味 |
| :-- | :-- |
| 角丸の枠 | 開始・終了 |
| 四角 | アクティビティ（処理） |
| ひし形 | 分岐（条件判断） |
| `【管理者】` などの接頭辞 | そのアクティビティを行うロール。`【システム】` は自動処理 |
| 枠で囲んだ範囲 | システムが判断せず、**園の運用に委ねる**部分 |

# 1 利用者種別とフローの対応

| 利用者種別 | 主に関わるフロー |
| :-- | :-- |
| 未ログイン利用者 | 2-1 保護者アカウントの自己登録、2-2 ログイン |
| 保護者 | 2-1、2-2、3-4 記録の共有（受け取り側）、3-5 園児の追加紐づけ |
| 一般（保育士） | 2-2、3-1 日誌の作成・申請、3-2 午睡チェックの実施、3-3 発達チェックの実施、3-4 |
| 管理者（園長・主任） | 上記すべてに加え、3-1（承認・共有指定）、4-1 年度更新、4-2 アカウントの発行と停止、4-3 パスワードの再設定、4-4 監査対応 |

# 2 ログイン・登録

## 2-1 保護者アカウントの自己登録

```mermaid
flowchart TD
    S(["開始"]) --> A1["【管理者】園児を登録し招待コードを発行する"]
    A1 --> A2["【管理者】配布用の一覧を印刷し保護者へ手渡す"]
    A2 --> A3["【保護者】保護者用トップから新規登録を選ぶ"]
    A3 --> A4["【保護者】招待コードを入力する"]
    A4 --> D1{"【システム】コードは有効か"}
    D1 -->|無効・期限切れ・使用済| A5["【システム】エラーを表示する"]
    A5 --> A4
    D1 -->|有効| A6["【システム】利用規約とプライバシーポリシーを表示する"]
    A6 --> D2{"【保護者】同意するか"}
    D2 -->|同意しない| E1(["登録を完了せず終了"])
    D2 -->|同意する| A7["【保護者】メールアドレス・パスワード・氏名・続柄を入力する"]
    A7 --> D3{"【システム】メールアドレスは園内で未使用か"}
    D3 -->|使用済| A8["【システム】重複エラーを表示する"]
    A8 --> A7
    D3 -->|未使用| A9["【システム】アカウントを作成しコードの園児と紐づける"]
    A9 --> A10["【システム】招待コードを使用済にする"]
    A10 --> A11["【システム】同意した版と日時を記録する"]
    A11 --> A12["【システム】クラスグループへ参加させる"]
    A12 --> E(["完了"])
```

- 新規登録の導線は**保護者用トップにのみ置く**。職員用トップには置かない（「アプリのログイン」(4-1-1)）。
- **1枚のコードは1アカウントの登録にのみ使える**（4-1-2）。父母それぞれが登録する場合は、同一園児に対して必要な枚数を発行する。
- メールアドレスは**ロールをまたいで園内で一意**。職員が自児の保護者アカウントを作る場合は別のメールアドレスが必要になる（4-1-1）。
- 園は恒久パスワードを保持しない（8 No.3）。

## 2-2 ログイン

```mermaid
flowchart TD
    S(["開始"]) --> A0["【利用者】自分の系統のトップを開く<br>（保護者用／職員用）"]
    A0 --> A1["【利用者】ログインIDとパスワードを入力する"]
    A1 --> D1{"【システム】アカウントはロック中か"}
    D1 -->|ロック中| A2["【システム】待機時間または管理者への連絡を案内する"]
    A2 --> E1(["終了"])
    D1 -->|ロックなし| D2{"【システム】認証に成功したか"}
    D2 -->|失敗| A3["【システム】失敗回数を加算する"]
    A3 --> D3{"【システム】失敗回数が上限に達したか"}
    D3 -->|未達| A1
    D3 -->|到達| A4["【システム】一定時間ログインを受け付けない"]
    A4 --> E1
    D2 -->|成功| D0{"【システム】アカウントのロールは<br>入口の系統と一致するか"}
    D0 -->|不一致| A0b["【システム】認証を成立させず<br>正しい系統の入口を案内する"]
    A0b --> E1
    D0 -->|一致| D4{"【システム】一時パスワードでのログインか"}
    D4 -->|はい| D5{"【システム】有効期限内か"}
    D5 -->|期限切れ| A5["【システム】管理者への連絡を案内する"]
    A5 --> E1
    D5 -->|期限内| A6["【利用者】パスワードを変更する"]
    A6 --> A7["【システム】変更が完了するまで他機能を使わせない"]
    A7 --> D6
    D4 -->|いいえ| D6{"【システム】同意済みの規約は最新版か"}
    D6 -->|旧版・未同意| A8["【システム】利用規約を表示する"]
    A8 --> D7{"【利用者】同意するか"}
    D7 -->|同意しない| E2(["ログインを完了せず終了"])
    D7 -->|同意する| A9["【システム】同意した版と日時を記録する"]
    A9 --> A10
    D6 -->|最新版| A10["【システム】ロールに応じた画面を表示する"]
    A10 --> E(["完了"])
```

- 失敗回数・待機時間はマスタ値（4-1-1）。**管理者は待機時間の経過を待たずに即時解除できる**。
- 一時パスワードの期限切れは、**ログイン試行の制限によるロックとは区別する**。待機時間の経過では解消せず、管理者による再発行が必要（4-1-1）。
- 職員向け画面は無操作が続くと自動ログアウトする。**「ログイン情報の記憶」より自動ログアウトを優先する**（4-1-4 (4)）。
- **ロールの判定は入口ではなくアカウントで行う。** 職員用の入口から保護者アカウントではログインできず、その逆もできない（「アプリのログイン」(4-1-1)）。

## 2-3 ログアウト

```mermaid
flowchart TD
    S(["開始"]) --> A1["【利用者】画面のログアウトを選ぶ"]
    A1 --> D1{"【システム】保存していない入力があるか"}
    D1 -->|ある| A2["【システム】破棄される旨を表示して確認する"]
    A2 --> D2{"【利用者】実行するか"}
    D2 -->|取り消す| E1(["ログイン状態のまま終了"])
    D2 -->|実行する| A3
    D1 -->|ない| A3["【システム】セッションを無効化する"]
    A3 --> A4["【システム】「ログイン情報の記憶」の保存を破棄する"]
    A4 --> A5["【システム】ログインしていた系統のトップへ戻す"]
    A5 --> E(["完了"])
```

- 遷移先は**ログインしていた系統のトップ**。保護者用なら保護者用トップ、職員用なら職員用トップへ戻る（「アプリのログイン」(4-1-1)）。
- セッションの無効化は 8 セキュリティ要求 No.9「セッションの保護」と整合する。
- **ログアウトは操作ログの対象としない。** 誰が記録したかの追跡は各操作の記録（「操作ログの参照」(4-1-4 (2))）で満たされる。
- 共有端末で担当を交代する場合の起点となる。**午睡チェックの実施中は、先に「午睡チェックを終了する」を行ってからログアウトする**（「端末の利用形態と本人特定」(4-1-4 (4))、本書「午睡チェックの実施」(3-2)）。
- 無操作による自動ログアウトは別の仕組みだが、遷移先とセッションの扱いは本フローに従う。

# 3 日々の業務

## 3-1 日誌の作成から保護者への共有

```mermaid
flowchart TD
    S(["開始"]) --> A1["【一般】雛形を選んで日誌を作成する"]
    A1 --> D1{"【システム】他の職員が編集中か"}
    D1 -->|編集中| A2["【システム】編集中である旨を表示する"]
    A2 --> E1(["終了"])
    D1 -->|未編集| A3["【システム】編集ロックを取得しロック識別子を発行する"]
    A3 --> A4["【一般】本文・写真・定型文を入力する"]
    A4 --> A5["【一般】下書き保存または承認申請をする"]
    A5 --> D2{"【システム】ロック識別子は有効なものと一致するか"}
    D2 -->|不一致| A6["【システム】ロックが解除された旨を表示し保存を拒否する"]
    A6 --> E1
    D2 -->|一致| A7["【システム】保存し状態を申請中にする"]
    A7 --> A8["【システム】管理者へ通知する"]
    A8 --> A9["【管理者】承認待ち一覧から内容を確認する"]
    A9 --> D3{"【管理者】承認するか"}
    D3 -->|差し戻し| A10["【システム】状態を差し戻しにし作成者へ通知する"]
    A10 --> A4
    D3 -->|承認| A11["【管理者】保護者へ共有するかを選ぶ"]
    A11 --> D4{"共有するか"}
    D4 -->|しない| A12["【システム】承認済みとしてアーカイブする"]
    A12 --> E(["完了"])
    D4 -->|する| A13["【システム】対象園児の保護者との個人チャットへ送る"]
    A13 --> A12
```

- 共有の**既定値は記録種別ごとのマスタ値**（個人日誌＝共有する、クラス日誌・週案月案・ヒヤリハット＝共有しない）。管理者が個別に変更できる（4-2 (1)）。
- 共有済みの日誌が修正された場合は、**再度の承認と共有指定を経て**改めて送られ、チャット上に「内容が更新されました」と表示される。
- 承認済みであっても**参照範囲は広がらない**。一般が閲覧できるのは自クラスの園児に紐づく日誌のみ（8 No.6）。
- 管理者による強制解除でロックが失われた場合、**他者の更新が無くても保存は拒否される**（4-1-4 (3)）。入力中の内容は画面に残す。

## 3-2 午睡チェックの実施

```mermaid
flowchart TD
    S(["開始"]) --> A1["【一般】午睡チェック画面で開始する操作を行う"]
    A1 --> A2["【システム】実施中にし自動ログアウトの対象外とする"]
    A2 --> A3["【システム】画面を常時点灯しログイン中の職員名を表示する"]
    A3 --> A4["【システム】年齢別の間隔でタイマーを開始する"]
    A4 --> A5["【システム】チェック時刻に通知音を鳴らす"]
    A5 --> A6["【一般】園児を目視で確認する"]
    A6 --> A7["【一般】体位・呼吸・顔色を記録する。体温は所定のタイミングのみ"]
    A7 --> A8["【システム】チェック時刻とサーバ時刻での保存時刻を両方保持する"]
    A8 --> D1{"【一般】通常と異なる状態か"}
    D1 -->|通常| D2{"午睡は終了したか"}
    D1 -->|異常あり| A9["【一般】発見時刻・状況・とった対応を記録する"]
    A9 --> A10["【システム】一括確認画面で強調し通知音を伴って管理者へ通知する"]
    A10 --> B1
    subgraph B1["園の運用に委ねる範囲"]
        A11["【一般】口頭で応援を要請する"] --> A12["【園】救急要請・保護者への連絡の要否を判断する"]
    end
    B1 --> D3{"【一般・管理者】ヒヤリハットとして起票するか"}
    D3 -->|起票する| A13["【システム】ヒヤリハットの下書きを日誌へ生成する"]
    A13 --> A14["【一般】不足分を追記して申請する"]
    A14 --> D2
    D3 -->|起票しない| D2
    D2 -->|継続| A5
    D2 -->|終了| A15["【一般】終了する操作を行う"]
    A15 --> A16["【システム】実施中を解除し自動ログアウトを再び適用する"]
    A16 --> E(["完了"])
```

- 終了操作を忘れた場合は、**午睡の時間帯（マスタ値）の終了時刻で自動的に解除される**（4-1-4 (4)）。
- 担当を交代する場合は、実施中であっても「終了する」→ログアウト→次の職員がログイン→「開始する」の順で引き継ぐ。
- **システムは異常の有無を判定しない。** 平熱は画面に並べて表示するのみで、発熱の判定はしない（4-2 (3)）。
- **ヒヤリハットに該当するかの判定も自動起票も行わない**（4-2 (1)）。起票していない異常時の記録は一括確認画面で把握できる状態を保つ。
- 本機能は**保育士による目視確認の代替ではない**。通知が届かなかった場合も巡回で担保する（4-2 (3)）。

## 3-3 発達チェックの実施

```mermaid
flowchart TD
    S(["開始"]) --> A1["【システム】月齢マスタから推奨スケジュールを園児へ適用する"]
    A1 --> D1{"【管理者】個別に上書きするか"}
    D1 -->|上書きする| A2["【管理者】園児単位でスケジュールを手動設定する"]
    A2 --> A3["【システム】推奨からの逸脱が分かるよう表示する"]
    A3 --> A4
    D1 -->|しない| A4["【システム】予定日が近づくと担任へ通知する"]
    A4 --> A5["【一般】クラスから園児を選ぶ"]
    A5 --> A6["【システム】生年月日から月齢を算出し該当区分のチェックリストを表示する"]
    A6 --> A7["【一般】確認できた・一部・未確認 を入力し所見を書く"]
    A7 --> D2{"入力を終えたか"}
    D2 -->|途中| A8["【一般】下書き保存する"]
    A8 --> A7
    D2 -->|完了| A9["【システム】記録を確定し過去記録と並べて表示する"]
    A9 --> D3{"【システム】予定日を過ぎた未入力があるか"}
    D3 -->|ある| A10["【システム】チェック漏れとして強調表示し担任へ通知する"]
    A10 --> A5
    D3 -->|ない| D4{"【管理者】保護者へ共有するか"}
    D4 -->|しない| E(["完了"])
    D4 -->|共有する| A11["【システム】共有範囲設定に従い項目単位で共有可否のフラグを付ける"]
    A11 --> A12["【システム】共有可の項目のみを個人チャットへ引き渡す"]
    A12 --> E
```

- **「未入力」と「未確認」は別の状態**として保持する。チェック漏れの対象になるのは「未入力」のみで、「未確認」は**その回に観察できなかったという事実の記録**であり評価ではない（4-2 (4)）。
- チェック項目・発達過程区分・推奨頻度はすべてマスタ。**保育所保育指針の改定にコード変更なしで追従する**（7-1 No.7）。
- **伸びの停滞・後退の可視化は行うが、判定・診断は行わない。** 判定・診断ではない旨を画面上に明示する。

## 3-4 記録の共有と保護者の閲覧

```mermaid
flowchart TD
    S(["開始"]) --> A1["【管理者】共有範囲設定で項目ごとの共有可否を定める"]
    A1 --> A2["【システム】記録に共有可否のフラグを付けて個人チャットへ引き渡す"]
    A2 --> A3["【システム】共有可の項目のみを含むメッセージを生成する"]
    A3 --> D1{"【システム】写真を含むか"}
    D1 -->|含む| D2{"【システム】写真の利用同意は掲載先の段階を満たすか"}
    D2 -->|満たさない| A4["【システム】投稿前に警告を表示する"]
    A4 --> A5["【職員】掲載先を見直す"]
    A5 --> A3
    D2 -->|満たす| A6
    D1 -->|含まない| A6["【システム】保護者の個人チャットへ送信する"]
    A6 --> A7["【保護者】自発的にアプリを開く"]
    A7 --> A8["【保護者】個人チャットで記録を閲覧する"]
    A8 --> A9["【システム】既読を記録する。保護者側には表示しない"]
    A9 --> A10["【職員】既読状態を確認する"]
    A10 --> E(["完了"])
```

- **通知は画面内表示が基本であり、保護者がアプリを開かない限り届かない**（4-1-4 (1)）。したがって**緊急を要する連絡はこの経路に載せず、園から電話で行う**（4-2 (2)）。
- 既読が付かないことをもって、システムが再送・エスカレーションを行うことはない。未読の一覧を職員が確認できる状態までが本システムの責務。
- 写真の利用同意は3段階（園内記録／自児の保護者へ共有／他の保護者にも見える場）。**同意が未取得・不明の園児は最も狭い段階のみを許可する**（4-1-3）。

## 3-5 園児の追加紐づけ

```mermaid
flowchart TD
    S(["開始"]) --> A1["【管理者】下の子の招待コードを発行し手渡す"]
    A1 --> A2["【保護者】ログイン済みの状態で招待コードを入力する"]
    A2 --> D1{"【システム】コードは有効か"}
    D1 -->|無効| A3["【システム】エラーを表示する"]
    A3 --> A2
    D1 -->|有効| A4["【システム】コードの園児をアカウントへ紐づける"]
    A4 --> A5["【システム】当該園児のクラスグループへ参加させる"]
    A5 --> A6["【システム】自児の範囲に加える"]
    A6 --> E(["完了"])
```

- **紐づけの解除は管理者のみが行える**（誤入力・親権の変更に対応）。解除は操作ログに記録する（4-1-2）。

# 4 管理業務

## 4-1 年度更新

```mermaid
flowchart TD
    S(["開始"]) --> A1["【管理者】年度更新を実行する"]
    A1 --> A2["【システム】更新内容の一覧を表示する"]
    A2 --> D1{"【管理者】内容は正しいか"}
    D1 -->|修正が要る| A3["【管理者】個別に修正する"]
    A3 --> A2
    D1 -->|正しい| A4["【システム】新年度のクラスを作成する"]
    A4 --> A5["【システム】在籍中の園児の所属クラスを繰り上げる"]
    A5 --> A6["【システム】担任の割り当てを新年度分へ移す"]
    A6 --> A7["【システム】最年長クラスの園児を卒園にする"]
    A7 --> A8["【システム】卒園児と保護者の紐づけを終了する"]
    A8 --> A9["【システム】クラスグループを新年度の構成へ再編する"]
    A9 --> A10["【システム】過年度のクラスグループを閲覧のみのアーカイブにする"]
    A10 --> A11["【システム】引き継ぎ猶予期間を開始する"]
    A11 --> A12["【システム】紐づく在籍園児がいなくなる保護者アカウントを一覧で提示する"]
    A12 --> D2{"【管理者】卒園児の記録を保護者へ渡すか"}
    D2 -->|渡す| A13["【管理者】保護者向け記録の引き渡し出力を実行する"]
    A13 --> A14
    D2 -->|渡さない| A14["【管理者】提示されたアカウントを停止する"]
    A14 --> E(["完了"])
```

- **引き継ぎ猶予期間**は年度更新の実行日を起点とする。期間中、前担任は前年度に担任していたクラスの在籍園児の記録を**閲覧のみ**できる（4-1-2）。
- 卒園児は在籍していないため、猶予期間中も参照の対象に含めない。
- **個人チャットへ添付して渡す場合は、紐づけの終了前に行う**（4-1-3）。

## 4-3 アカウントの停止

```mermaid
flowchart TD
    S(["開始"]) --> D1{"対象は職員か保護者か"}
    D1 -->|退職した職員| A1["【管理者】アカウントを停止する"]
    D1 -->|保護者| D2{"【システム】紐づく在籍園児が1人でも残っているか"}
    D2 -->|残っている| A2["【システム】アカウントは有効のまま"]
    A2 --> E1(["終了"])
    D2 -->|1人もいない| A1
    A1 --> A3["【システム】ログインを拒否する。過去の記録は保持する"]
    A3 --> E(["完了"])
```

- **管理者ロールは常に2名以上**とすることを運用要件とする。管理者が1名になる操作（停止・削除・ロールの変更）にはシステムが警告を出す（4-1-1）。
- 停止したアカウントはログインできないが、**過去の記録は保持する**（4-1-2、7-3）。

## 4-4 パスワードの再設定

```mermaid
flowchart TD
    S(["開始"]) --> A1["【利用者】パスワードを忘れた旨を管理者へ伝える"]
    A1 --> D1{"対象は管理者自身か"}
    D1 -->|管理者自身| A2["【他の管理者】再発行を行う"]
    A2 --> A3
    D1 -->|職員・保護者| A3["【管理者】一時パスワードを再発行する"]
    A3 --> A4["【システム】自動生成した値を画面に1度だけ表示する"]
    A4 --> A5["【システム】ハッシュ化して保存し旧パスワードを無効化する"]
    A5 --> A6["【管理者】口頭または手渡しで本人へ伝える"]
    A6 --> D2{"【利用者】有効期限内にログインしたか"}
    D2 -->|期限切れ| A7["【システム】どのパスワードでもログインできない状態にする"]
    A7 --> A3
    D2 -->|期限内| A8["【利用者】ログインし新しいパスワードを設定する"]
    A8 --> A9["【システム】変更が完了するまで他機能を使わせない"]
    A9 --> E(["完了"])
```

- 一時パスワードは**再表示・再閲覧の手段を持たない**。伝え損ねた場合は再発行からやり直す（4-1-1）。
- **管理者が1名しか存在しない状態でその管理者が失念した場合、システム上の復旧手段はない。** 管理者2名以上の運用で回避する。

## 4-5 監査（実地指導）への対応

```mermaid
flowchart TD
    S(["開始"]) --> A1["【監査】提示を求める範囲が示される"]
    A1 --> D1{"何を提示するか"}
    D1 -->|午睡チェック表| A2["【管理者】日付・クラスを指定して帳票を出力する"]
    A2 --> A3["【システム】チェック時刻と保存時刻を両方出力する"]
    A3 --> A6
    D1 -->|日誌| A4["【管理者】期間を指定してPDF出力する"]
    A4 --> A6
    D1 -->|発達記録| A5["【管理者】園児・期間を指定してPDF出力する。全項目を含む"]
    A5 --> A6
    D1 -->|操作の履歴| A7["【管理者】日付・操作者・対象機能・対象園児で絞り込む"]
    A7 --> A8["【システム】操作ログを出力する"]
    A8 --> A6
    A6["【管理者】出力物を監査へ提示する"] --> E(["完了"])
```

- 午睡チェック記録は**サーバ時刻を記録時刻とし、修正は上書きせず履歴を残す**。削除は行わない（4-2 (3)）。
- 操作ログは**追記のみ**で、画面からの編集・削除の手段を持たない（4-1-4 (2)）。
- 発達記録のPDF出力は**園内利用が前提で、共有範囲設定にかかわらず全項目を含む**。保護者へ渡す出力は共有可の項目のみを含む別の機能（4-2 (4)、4-1-3）。
