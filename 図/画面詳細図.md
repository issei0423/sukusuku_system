# 0 本書の位置づけ

- 本書は**図**であり、各画面の**レイアウト（どこに何が置かれるか）**を示す。学校テンプレート「【テンプレート】3_基本設計書.docx」がユーザインターフェイス設計の章で求める**画面詳細（別紙）**にあたる。
- **項目の一覧**（表示・入力・操作）は `基本設計書.md`「画面詳細」(3-6) が持つ。本書は同書の項目を**配置として示す**ものであり、項目の定義を重複して持たない。
- **入力項目の制約値**（必須・桁数・形式・エラー文言）は `基本設計書.md`「メッセージ一覧」(4-9) とテーブル定義(5) が持つ。本書では扱わない。
- **画面のつながり**は `図/画面遷移図.md` が持つ。
- 記述が食い違った場合は、**要件定義書 → 基本設計書 → 本書**の順で正とし、本書を追随させる。
- 掲載している氏名・メールアドレス・招待コード・測定値は**すべて架空**である。実在の園児・保護者の情報は含まない。

## 0-1 表記ルール

ワイヤーフレームは**等幅テキスト**で描く。理由は3点。

1. **差分が追える。** 画像で持つと、どこが変わったかを git の履歴から読めない
2. 図・要件定義書・テスト仕様書は**リポジトリ内の Markdown が正**という方針に沿う（`CLAUDE.md`）
3. 提出時に作図が必要になれば、draw.io へ渡して整えられる

| 表記 | 意味 |
| :-- | :-- |
| `[ ボタン ]` | 押せるもの（ボタン・リンク） |
| `< 入力欄 >` | 入力欄・選択欄 |
| `( )` / `(*)` | 選択肢（未選択／選択中） |
| `[ ]` / `[x]` | チェックボックス（未／済） |
| `...` | 同じ形のものが続く（一覧の行など） |
| `(!)` | 警告・注意喚起の表示 |
| **枠の右端は閉じない** | 日本語と英数字が混在すると等幅でも幅が揃わないため。左端と上下の罫線だけで領域を示す |

- **配置は相対的な位置関係を示すもの**であり、ピクセル単位の寸法を定めるものではない
- 画面名は `基本設計書.md`「画面の一覧」(3-2) の名称と一致させる

## 0-2 全画面に共通する規定

`基本設計書.md`「画面基本構成」(3-5) より、レイアウトに影響するものを再掲する。**本書の全画面がこれに従う。**

| 規定 | 内容 |
| :-- | :-- |
| テーマカラー | 優しい黄色。警告色は黄色と対比の付く色を用いる |
| グリッド | 職員（タブレット／PC）＝12カラム、保護者（スマートフォン）＝シングルカラム |
| タップ領域 | **44×44px 以上**。タブレットでの操作を前提とする |
| ヘッダ | ログイン中の利用者名を**常時表示**する（職員は所属クラスも） |
| ログアウト | 職員はヘッダに常時表示。保護者はメニュー内 |
| 免責表示 | 成長グラフ・発達チェックの比較には「判定・診断を行うものではありません」を**固定表示**する |
| サイドナビ | **保護者向け画面は持たない** |

# 1 共通レイアウト

## 1-1 職員（タブレット／PC）

```text
+----------------------------------------------------------
| すくすく        [!] 未対応 3    さくら組 山田 花子  [ ログアウト ]
+--------------+-------------------------------------------
| ダッシュボード  |

```

- **ログイン中の職員名と所属クラスをヘッダに常時置く。** 共有端末での記録者の取り違えを防ぐため（要件定義書「端末の利用形態と本人特定」(4-1-4 (4))）
- サイドナビは**現在地を強調**する。「管理」は管理者にのみ表示し、一般には項目自体を出さない
- 通知には未対応件数を添える。**【要確認】** 通知から該当画面への導線を設けるかは未定（`図/画面遷移図.md`「要確認事項」(8) No.5）

- ログアウトはメニュー内に置く

# 2 共通・認証

## 2-1 職員用トップ／保護者用トップ

```text
+--------------------------------------
|              すくすく
|          （園のロゴ・園名）
|
|  ログインID   < example@hoiku.jp     >
|  パスワード   < ********             >
|
|  [x] ログイン状態を保持する
|
|           [    ログイン    ]
|
|  -- 保護者用のみ ------------------
|  はじめての方   [ 招待コードで新規登録 ]
|
|  (!) ログインIDまたはパスワードが違います（残り 3 回）
+--------------------------------------
```

| 分類 | 項目 |
| :-- | :-- |
| 入力 | ログインID（メールアドレス）、パスワード、ログイン状態を保持するかの選択 |
| 操作 | ログイン、新規登録へ（**保護者用のみ**） |
| 表示 | エラーメッセージ、ロック中の案内 |

- **表示するのは認証の導線のみ。** 園児情報・記録などの実データも、サービス紹介コンテンツも置かない（`基本設計書.md`「画面詳細」(3-6)）
- **新規登録の導線は保護者用トップにのみ置く。** 職員アカウントは管理者が発行するため（要件定義書「アカウントの管理」(4-1-2)）
- 職員用と保護者用は**同じ様式で、入口だけが異なる**。誤った系統でのログインは成立させず、正しい入口を案内する

## 2-2 ログイン中に入口を開いたとき

```text
+--------------------------------------
|              すくすく
|
|  すでにログインしています。
|  別のアカウントでログインするには、
|  先にログアウトしてください。
|
|       [   ログアウトする   ]
|       [   前の画面へ戻る   ]
+--------------------------------------
```

- **ログインフォームを表示しない。** ログイン中は系統・アカウントを問わず新しいログインを成立させないため（要件定義書「同時ログインの扱い」(4-1-1)）
- **案内にログイン中の氏名・ロールを出さない。** 共有端末で、前の利用者が誰であったかを第三者に示さないため

## 2-3 新規登録画面（保護者）

```text
+--------------------
| < 戻る    新規登録
+--------------------
| (1) 招待コードの入力
|   < ABCD-1234-EFGH >
|   [ コードを確認する ]
|
| (2) 利用規約への同意
|   +----------------
|   | 利用規約（本文をスクロール）
|   +----------------
|   [ ] 利用規約に同意します
|
| (3) アカウント情報
|   メールアドレス     < >
|   パスワード        < >
|   パスワード（確認）  < >
|
|        [ 登録する ]
+--------------------
```

- 段階を1画面の中で上から順に踏ませる。**招待コードが確認できるまで (2)(3) を操作できない**
- **園児名を画面に表示しない。** 招待コードだけでは、誰の保護者かを名乗る前の段階であるため。紐づく園児は登録完了後のホームで確認する
- **【要確認】** 招待コードの入力形式（区切りの有無・大文字小文字の扱い）は「メッセージ一覧」(4-9) と合わせて決める

## 2-4 職員ダッシュボード

```text
+--------------+-------------------------------------------

|              | +-- よく使う --------------------------
```

- **未対応の件数を最上部に置く。** 出勤直後に「何が残っているか」を1画面で把握させるため

- 承認待ちの区画は**管理者にのみ表示**する

# 3 日誌システム

## 3-1 日誌一覧画面

```text
+-----------------------------------------------------------
| 日誌
| 種別 <すべて>  クラス <さくら組>  状態 <すべて>
| 期間 <2026/08/01> 〜 <2026/09/01>   [ 絞り込む ]
|                                    [ 新しく書く ]
+-----------------------------------------------------------
| 記録日      種別        対象        作成者    状態
| 09/01(月)  個人日誌     山田 太郎   山田花子  下書き    [ 開く ]
| 08/31(日)  クラス日誌   さくら組    山田花子  申請中    [ 開く ]
| 08/30(土)  ヒヤリハット  さくら組    佐藤明子  差し戻し  [ 開く ]
| 08/29(金)  個人日誌     鈴木 花子   山田花子  承認済    [ 開く ]
| ...
+-----------------------------------------------------------
| < 前へ    1 / 4    次へ >                       全 37 件
```

- **状態を列として持つ**（下書き／申請中／差し戻し／承認済）。差し戻しは他と区別できる色にする
- 一覧は11件以上でページングする（`基本設計書.md`「一覧表示とページング」(3-7)）
- 一般（保育士）の既定の絞り込みは**自クラス**。他クラスは選べない（要件定義書「対象権限列の読み方」(4-2 冒頭)）

## 3-2 日誌作成・編集画面

```text
+-----------------------------------------------------------
| < 日誌一覧へ          状態：下書き   (!) 佐藤明子さんが編集中
+-----------------------------------------------------------
| 記録種別  (*)個人日誌 ( )クラス日誌 ( )週案・月案 ( )ヒヤリハット
| 対象     <山田 太郎>              記録日 <2026/09/01>
|
| [ 雛形を呼び出す ]  [ 定型文を入れる ]
| +--------------------------------------------------------
| | 本文
| |
| +--------------------------------------------------------
| 写真（1〜3枚）  [ + 追加 ]    +-----+ +-----+
|                             |  1  | |  2  |
|                             +-----+ +-----+
| +-- この園児の過去の記録 ---------------------------------
| | 08/29 個人日誌  ...                          [ 開く ]
| +--------------------------------------------------------
|                     [ 下書き保存 ]     [ 確認へ進む ]
```

- **他の職員が開いている場合は、その旨をヘッダ直下に出す**（要件定義書「同時編集」(4-1-4)）。ロックの解除は `基本設計書.md`「編集ロックの解除」(4-5) に従う
- 過去の記録を同じ画面に並べる。**前回の記述を見ながら書けるようにするため**
- 写真は**3枚まで**。上限に達したら追加を無効にする

## 3-3 日誌承認画面（管理者）

```text
+-----------------------------------------------------------
| < 承認待ち一覧へ       申請 09/01 17:20   作成者 山田花子
+-----------------------------------------------------------
| 個人日誌 ／ 山田 太郎 ／ 記録日 2026/09/01
| +--------------------------------------------------------
| | 本文（読み取り専用）
| +--------------------------------------------------------
| 写真   +-----+ +-----+
|        |  1  | |  2  |
|        +-----+ +-----+
|
| +-- 保護者への共有 ---------------------------------------
| | (*) 共有する     ( ) 共有しない
| | 共有先：山田 太郎ちゃんの保護者（個人チャット）
| +--------------------------------------------------------
| 差し戻す理由 < 差し戻すときのみ入力 >
|
|        [ 差し戻す ]                    [ 承認する ]
```

- **共有の指定を承認と同じ画面に置く。** 承認後に別画面で指定させると、共有し忘れが起きるため
- 差し戻しは理由の入力を必須とする。**何を直せばよいかが作成者に伝わらないため**
- **【要確認】** 共有するの既定値を「する／しない」のどちらに置くかは未定

```text
| +------------+ +------------+ +------------+
| ...
+-----------------------------------------------------------

  +-------------------------------------------
  | 山田 太郎    13:25

  | 呼吸  (*)あり ( )なし
  | 顔色  (*)良好 ( )不良
```

- **タイマーを画面の上部に固定する。** スクロールしても視界から外さない（`基本設計書.md`「画面基本構成」(3-5)）

- うつ伏せを選んだときの警告は**注意喚起であって判定ではない**。記録自体は妨げない
- 記録は**園児カードから1件ずつ**行い、確認画面を挟まない。連続入力を前提とするため（同「画面の洗い出しの考え方」(3-1) の基準2）
- この画面は**開いたまま運用**し、実施中は自動ログアウトの対象外とする

# 6 発達チェック・身体測定

## 6-1 発達チェック入力画面

```text
+-----------------------------------------------------------
| < 発達チェック一覧へ    山田 太郎（1歳3か月）    2026/09/01
+-----------------------------------------------------------
| 発達過程区分：おおむね1歳3か月〜2歳
| +-- 運動 ------------------------------------------------
| | ひとりで歩く        (*)確認できた ( )一部 ( )未確認
| | 階段をはう          ( )確認できた (*)一部 ( )未確認
| +--------------------------------------------------------
| +-- ことば ----------------------------------------------
| | 意味のある語を話す    ( )確認できた ( )一部 (*)未確認
| +--------------------------------------------------------
| 所見  +--------------------------------------------------
|       |
|       +--------------------------------------------------
| [x] 前回の記録と並べて表示する
| +-- 前回（2026/06/01・0歳11か月）--------------------------
| | ひとりで歩く    未確認 → 確認できた
| +--------------------------------------------------------
| (!) 本機能は発達の判定・診断を行うものではありません
|                     [ 下書き保存 ]     [ 確定する ]
```

- **免責表示を保存操作の直上に固定する。** 比較を見ながら入力する画面であり、判断と取り違えられやすいため
- **「未入力」と「未確認」は別の状態。** 未確認は結果として保持し、未入力はチェック漏れの対象となる（`基本設計書.md`「画面詳細」(3-6)）
- 区分は**月齢から自動で表示**するが、項目はマスタから読む。園が調整できるため

## 6-2 身体記録画面

## 7-3 招待コード管理画面（管理者）

```text
+-----------------------------------------------------------
| 招待コード    クラス <さくら組>   状態 <未使用>   [ 絞り込む ]
|                   [ 発行する ] [ 一括発行 ] [ 配布用に出力 ]
+-----------------------------------------------------------
| コード           園児        発行日   有効期限   状態
| ABCD-1234-EFGH  山田 太郎   08/25   09/25    未使用  [ 失効 ]
| IJKL-5678-MNOP  山田 太郎   08/25   09/25    使用済
| QRST-9012-UVWX  鈴木 花子   08/25   09/25    未使用  [ 失効 ]
| ...

  [ 一括発行 ] を押したとき
  +-------------------------------------------
  | クラス           < さくら組 >
  | 園児1名あたりの枚数 < 2 > 枚
  | 有効期限         < 30 > 日
  | → さくら組 12 名 × 2 枚 ＝ 24 枚を発行します
  |              [ 発行する ]   [ やめる ]
  +-------------------------------------------
```

- **1枚＝1アカウント**であり、園児ごとに必要枚数を発行する（要件定義書「招待コードの発行」(4-1-2)）。両親それぞれに配るなら2枚
- 同じ園児に複数枚が並ぶため、**園児名でまとめて見られる**ようにする
- 配布用の出力は、**コードと園児名の対応を取り違えないこと**を優先した様式にする
