# 0 本書の位置づけ

- 本書は、**画面（フロントエンド）とサーバ（バックエンド）の間でやり取りする内容**を定める。`基本設計書.md`「共通の処理」(4-2) の別紙にあたる。
- **フロントエンドとバックエンドを並行して作るための取り決め**である。両者はこの一覧だけを見て、相手の実装を待たずに作れる。
- 画面そのものの定義は `図/画面詳細図.md`、テーブルの定義は `基本設計書.md`「データベース設計」(5) が持つ。本書はその間をつなぐ部分だけを持つ。
- 記述が食い違った場合は、**要件定義書 → 基本設計書 → 本書**の順で正とし、本書を追随させる。

## 0-1 共通の規定

| 項目 | 規定 |
| :-- | :-- |
| 経路の接頭辞 | すべて `/api/` で始まる |
| 形式 | 要求・応答とも **JSON**（`Content-Type: application/json; charset=utf-8`） |
| 文字コード | UTF-8 |
| 日付 | `YYYY-MM-DD`（例 `2026-09-07`） |
| 日時 | `YYYY-MM-DDTHH:mm:ss`（例 `2026-09-07T13:00:00`）。**日本標準時（JST）**（`基本設計書.md`「日付と時刻の扱い」(6-3)） |
| 認証 | **HttpOnly の Cookie** でセッションを識別する。要求ごとにトークンを添えない（同「認証情報の保持方式」(6-3)） |
| CSRF | 状態を変える要求は `Origin` を検証する（同「CSRF対策の方式」(6-3)） |
| 区分値 | `1` `2` のような**文字列**で受け渡す。画面側で表示名へ変換し、**数字を画面に出さない** |
| 論理削除 | 削除は `is_deleted` を立てる。応答から消えるのではなく、フラグで示す。**ただし保護者への応答では、連絡帳で取り消したものを返さない**（保護者の全画面から消す。`基本設計書.md`「連絡帳」(5-4)） |
| 例外の形式 | `GET /api/events` は `text/event-stream`（下記「知らせ（SSE）の形」(1-3)）。写真・顔写真の送信は `multipart/form-data`、実体の取得は画像そのものを返す |

## 0-2 エラーの返し方

**すべてのエラーで同じ形を返す。** 画面はこの形だけを解釈すればよい。

| 項目名 | 型 | 必須 | 説明 |
| :-- | :-- | :-: | :-- |
| `message` | `string` | 必須 | **利用者へそのまま見せられる文言**。技術的な内容を含めない |
| `kind` | `string` | 任意 | 画面が分岐に使う種別（`credential` など） |
| `remaining` | `number` | 任意 | **第3.0版では返さない。** 残りの試行回数を示すと、ログインIDが在るかどうかが分かるため（要件定義書「アプリのログイン」(4-1-1)）。ロックしたときだけ `kind: 'locked'` で知らせる |
| `names` | `string[]` | 任意 | 他児の名前の注意で見つかった名前（`POST /api/contact/name-check` の応答。エラーではない） |
| `correct` | `string` | 任意 | 入口を取り違えたときに案内する正しい系統（`staff` / `guardian`） |

**状態コード**

| コード | 使う場面 |
| :-: | :-- |
| `200` | 成功 |
| `400` | 入力が要件を満たさない（桁数・形式・必須） |
| `401` | 未ログイン、または認証に失敗した |
| `403` | **権限または参照範囲の外**。存在しない場合と同じ文言にし、あるかどうかを推測させない |
| `404` | 経路が存在しない |
| `409` | 競合（編集ロックの不一致、重複する登録、**終了した午睡の実施への記録、家庭からの同時編集、その日の園からが既にある**） |
| `429` | **AI の下書きが、その日の上限回数に達した** |
| `503` | **外部の AI が下書きを返さなかった**（混雑・提供者の不具合・接続の失敗・応答の拒否・10秒を過ぎた）。文言は「いまは下書きを作れません。そのまま書いて送れます」 |
| `500` | サーバ側の想定外の失敗 |

> **エラーの文言はマスタで持ち、コードに直接書かない**（`基本設計書.md`「メッセージ一覧」(4-9)）。

## 0-3 権限の担保

**対象権限の列は、サーバ側で判定する範囲を示す。** 画面側の出し分けは操作性のためであり、権限の担保ではない（`基本設計書.md`「権限チェックの実装方針」(6-2)）。

| 表記 | 意味 |
| :-- | :-- |
| 未ログイン可 | ログインしていなくても呼べる |
| 全ロール | ログインしていれば呼べる。**返す範囲は利用者の参照範囲で絞る** |
| 管理者・一般 | 職員のみ。保護者は呼べない |
| 管理者 | 管理者（園長・主任）のみ |

- **一覧・詳細は、参照できる範囲をサーバ側で絞り込む。** 園児IDを直接指定した不正な取得を許さない
- 保護者には**職員の名簿を返さない**。チャットの送信者名はメッセージ側が持つ
- **判定の関数は3つ**（職員の園児単位・保護者の紐づけ・参加）。連絡帳・成長の記録は紐づけ（紐づけより前の日も読める）、保護者の個人チャットは参加した時点以降で判定する（`基本設計書.md`「権限チェックの実装方針」(6-2)）
- **保護者の応答に、監査の層の項目を入れない**（午睡の確認の記録・入眠時の体温・対象外・異常時の記録、日誌、発達の「一部」「未確認」と所見、園児の顔写真）

## 1-1 経路ごとの要求と応答の補足

**テーブルの型をそのまま使わない経路の、要求と応答をここに書く。**（2026/10/09 に足した経路と、形が変わった経路）

## 1-3 知らせ（SSE）の形

`GET /api/events` は、開いている画面へ「変わった」とだけ知らせる。**記録の中身を入れず、種類と、読み直しに要る ID だけ**を送る。見せてよいかは、画面が読み直す経路の判定で決まる（`基本設計書.md`「権限チェックの実装方針」(6-2)）。形は `feat/sse-realtime-v2` の `server/events.go`（`219358b`）にそろえる。

| 項目 | 規定 |
| :-- | :-- |
| 応答 | `200`、`Content-Type: text/event-stream`。未ログインは `401`、手続きの途中（パスワードの変更・規約の同意の前）は `403` |
| つないだとき | `retry: 3000`（切れたらつなぎ直すまで3秒）と、コメント行 `: connected` |
| 知らせ | 記録の知らせは `event:` の名前を付けず、`data: {"type": "…", …}` の1行（画面は `message` として受ける） |
| 心拍 | **30秒ごとに名前付きの知らせ `event: ping`**（`data:` は空）。あわせてセッションの期限切れを見つけて閉じる。**画面は `ping` が45秒届かなければ切れたとみなし**、つなぎ直しながら5秒ごとに読み直す（つながっている間の保険の読み直しは30秒ごと）。コメント行は画面の側から見えず、中継が接続を保ったままサーバが止まると気づけないため名前付きにする（`基本設計書.md`「リアルタイムの反映と通知」(4-10)） |
| 閉じるとき | ログアウト・停止・紐づけの終了・パスワードの変更・一時パスワードの再発行で、その場で閉じる |
| 取りこぼし | 送り先ごとに溜められる数を超えたら接続を閉じる。画面はつなぎ直したときにすべてを読み直す |

| `type` | 入る ID | 職員へ | 保護者へ |
| :-- | :-- | :-- | :-- |
| `chat` | `room_id` | 参加者（個人チャットは園児単位） | 参加者 |
| `diary` | `diary_id` | 読める職員 | **送らない** |
| `handout` | `handout_id` | 見られる人 | 見られる人 |
| `nap` | `class_id`・`child_id` | 読める職員。異常時の記録も（管理者の画面は未確認の件数を読み直し、増えたら音を鳴らす） | **送らない**（確認の回数・間隔が分かってしまうため） |
| `development` | `child_id` | 読める職員 | **確定したとき**、紐づけで読める保護者 |
| `physical` | `child_id` | 読める職員 | 身体測定を共有するとき、紐づけで読める保護者 |
| **`contact`**（第3.0版で足す） | `child_id` か `class_id` | 読める職員 | 紐づけで読める保護者。**ねた・おきた・取り消し・訂正・「確認しました」を含む** |

> **実装との違い**（`219358b` の時点）：実装は `contact` をまだ持たず、保護者へ `nap`（開始・終了・園児の記録）と `diary`（承認して共有した個人日誌）を送っている。心拍はコメント行（`: ping`）である。第3.0版では、保護者への `nap` と `diary` を止め、ねた・おきたを `contact` で送り、心拍を `event: ping` に改める

# 3 本書の限界

- **経路ごとの要求の項目は、上の型定義の一部を送る形になる。** どの項目を送るかは経路によって異なり、本書では型の単位でのみ示している。細部は実装（`web/src/api/http.ts`）が持つ
- **並び順・絞り込みの条件は経路ごとに異なる。** 一覧を返す経路は、既定の並び順と件数を `基本設計書.md`「一覧表示とページング」(3-7) に従う
- 本書は **Go + React 版モックアップの実装から起こした**。実装が設計と食い違っていれば設計に合わせて実装を直す（`図/画面遷移図.md`「本書の位置づけ」(0) と同じ扱い）
