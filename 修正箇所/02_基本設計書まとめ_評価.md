# 評価: `基本設計書_作成必要要素まとめ.md`

対象ファイル: `docs`ブランチ直下の `基本設計書_作成必要要素まとめ.md`（370行、作成日2026/07/14）。
学校テンプレート「【テンプレート】3_基本設計書.docx」（通販システム例）の章構成に対応させ、すくすくシステム版基本設計書を書くための「何を書くべきか／どこから引けるか／何が欠けているか」を章ごとに整理したドキュメント。

## 総評

構成・引用の正確性は高い。ただし、**実装コード（`mockup`ブランチ `hoiku_app/`）を情報源として一切参照していない**という明確な弱点があり、これによりいくつかの記述が古くなっている、または裏付けが取れるはずの指摘が裏付けなしのまま残っている。

## 良い点

1. **引用は正確**: `N-01`〜`N-10`（F-15要件定義書の非機能要件）、`F-15-xx`（機能ID）などの引用を実際のソース文書（`発達チェック機能_要件定義書.md`、`HFD_要件定義書02_レビュー編集済み.md`）と照合したが、捏造や誤引用は見つからなかった。
2. **章立てが実行可能な作業指示になっている**: 「テンプレートに書かれていること／すくすく版で書く必要がある要素／既存資料からの転用元／欠けている要素（要決定）」の4分類が全章で一貫しており、そのままチームの分担作業（末尾に担当者名まで既存ガントチャートと紐付け）に使える。
3. **要件定義書側の弱点にも踏み込んでいる**: 末尾「要件とのギャップ（レビュー指摘事項）」で、既読確認機能が要件一覧に無いこと、登降園管理が要件のスコープ外であることなどを指摘しており、`claude.md`の「抜け漏れの検出」方針（個別機能だけでなく、そもそも存在しない機能領域にも注意を払う）に沿っている。
4. **判断を下していない**: 「〜を決定する必要がある」という書き方に終始しており、`claude.md`の「システムは判断しない／AI下書きはたたき台」という原則を守れている。

## 問題点

### 1. 実装コードを一切参照していないため、記述が古い／裏付けが取れる指摘が未検証のまま

`mockup`ブランチの `hoiku_app/app.py` を確認したところ、以下の食い違いがあった。

| 文書の記述（5-1節） | 実装の実態 | 評価 |
| :-- | :-- | :-- |
| 「DBMSの選定は未定」 | SQLite で確定済み（`sqlite3`使用） | 古い。すでに決まっている |
| 「発達チェック系テーブルの正規化設計は未定義」 | `dev_items`（項目マスタ）と`dev_results`（結果）が既に分離されて実装済み | 古い。設計判断はすでに実装側で下されている |
| 「推奨頻度マスタ」「個別スケジュール」「共有範囲設定マスタ」「身体測定記録」が未定義 | 実装のDBスキーマにこれらのテーブルは存在しない | 裏付けが取れた。本当に未着手 |

→ 「未定」という同じラベルの中に、実は実装側で既に決まっている項目と、本当にまだ何も手が付いていない項目が混在しており、このままではどちらを優先着手すべきか判断を誤る。

### 2. 実装との新たな不整合（この文書のどの章にも触れられていない）

`children` テーブルに生年月日フィールドが存在しない（`age_label`という表示用テキストのみ）。しかしF-15要件定義書は「生年月日を月齢計算の単一の根拠（SSoT）とする」（N-07）ことを大前提としている。この矛盾は基本設計側の5章（DB設計）でも6章でもどこにも指摘されておらず、本文書のカバレッジの盲点。

### 3. 前回指摘（`修正箇所/01_トップページ未定義.md`）との不整合

前回作成した「トップページ・ログイン・サインアップ導線が要件定義書にない」という指摘が、この文書の「3 ユーザインターフェイス設計」章（画面体系図・画面基本構成）にも「6 セキュリティ設計（未ログイン状態で何が見えるか）」章にも反映されていない。2つのドキュメントが同時期にレビューされているにもかかわらず情報が同期していない状態。

### 4. 軽微な内部表記ゆれ

「6-1」の欠けている要素で「ログイン必須アプリなら『ログイン画面のみ』と明記」と書きつつ、その一文自体が「本当にログイン必須アプリなのか（トップページの要否）」という前提を無条件に置いてしまっている。これは指摘3とも関係し、前提そのものが本文書内では未検証。
