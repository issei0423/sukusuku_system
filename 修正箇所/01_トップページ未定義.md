# 指摘: トップページ、およびログイン／サインイン／ログアウト導線が要件定義書に定義されていない

## 指摘の要約

要件定義書（`HFD_要件定義書02_レビュー編集済み.md`）には、未ログイン時にユーザーが最初に見る「トップページ」という画面・概念が存在しない。それに伴い、ログイン・新規登録（サインアップ）・ログアウトという認証まわりの導線が、その起点画面の要件としてどこにも定義されていない。

## 現状の要件定義書の記述

要件定義書「4-1 機能全体像」の「アプリのログイン」節（該当箇所を引用）:

> ログイン機能で利用者の種別を判断し、表示画面・利用機能を切り替える。

**機能要件表:**

| 機能名 | 概要 |
| :-: | :-: |
| ログイン・ログアウト | IDとパスワードによる認証を行う。 |
| 権限管理 | 管理者（園長・主任）＝全操作・承認／差し戻し・職員アカウント発行。一般（保育士）＝日誌の作成・編集・申請、自クラス閲覧。 |
| ログイン情報の記憶 | ログイン状態を一定期間保存する機能 |
| テンプレート機能 | 日誌（クラス・個人・週案・月案）を呼び出す機能。 |

この節は「ログイン」という機能の中身（認証方式・権限・セッション保持）は定義しているが、**その機能がどの画面（トップページ）に配置され、未ログイン時に何が表示されるか**には一切触れていない。

基本設計側（ドラフト「基本設計書」画面一覧、`基本設計書_作成必要要素まとめ.md` 3-2）でも、画面一覧は `SCR-001 ログイン画面` から始まっており、トップページに相当する画面は存在しない。

## 何が欠けているか

1. **トップページという画面・概念自体の不在**
   要件定義書にも基本設計ドラフトにも、「アプリ起動時に最初に表示される画面」の定義がない。ログイン画面がトップページを兼ねるのか、サービス紹介的な独立画面を設けるのかが未決定・未記述。

2. **ログイン／ログアウトとトップページの関係が未定義**
   ログイン機能そのものは要件化されているが、「トップページ上のどこに、どういう導線で配置するか」の記述がない。ログアウト操作後にどの画面へ遷移するか（トップページに戻るのか、ログイン画面のみが再表示されるのか）も未定義。

3. **新規登録（サインアップ）が要件定義書に一切存在しない**
   要件定義書のログイン節は「ログイン・ログアウト」のみを定義しており、アカウント新規作成（サインアップ）についての記述がどこにもない。

## 実装との整合状況（事実の記録。良し悪しの判断はしない）

`mockup` ブランチの実装（`hoiku_app/static/index.html`）を確認したところ、以下の状態だった。

- ログイン画面のセクションに `<!-- 画面1: トップ / ログイン -->` というコメントがあり、実装側は「トップページ＝ログイン画面」として1画面に統合する設計をすでに行っている。
- 同じ画面内に「ログイン」「新規登録」の2タブが実装されている（新規登録は保護者向け、招待コード方式）。**これは要件定義書には存在しない機能**であり、要件定義書と実装のあいだにギャップがある。
- ログアウトボタンはログイン後の画面（`id="app"`）のヘッダー内に実装されている。ログアウト後の遷移先はコード上「トップ/ログイン画面（`id="login"`）」に戻る動きだが、これも要件定義書には根拠となる記述がない。

→ 実装側は独自に意思決定して作っているが、要件定義書がそれを裏付けていないため、**「なぜその設計にしたか」の根拠が要件定義書に残っていない**状態になっている。

## 決定が必要な論点（たたき台。結論はここでは出さない）

- [ ] トップページを独立画面として設けるか、現行実装のようにログイン画面と統合するか
- [ ] 独立させる場合、未ログイン時に何を見せるか（サービス説明・機能紹介など）を要件化するか
- [ ] 新規登録（サインアップ）を正式な機能要件として要件定義書に追記するか（対象: 保護者のみか、職員も含むか）
- [ ] ログアウト後の遷移先（トップページ／ログイン画面）を明文化するか

## 影響範囲

この抜け漏れは、要件定義書だけでなく以下にも波及する。

- 基本設計書の画面一覧・画面ID体系（`SCR-001`をログイン画面とするかトップページ画面を別途追加するか）
- 画面遷移図（起点ノードの定義）
- 権限マトリクス（`基本設計書_作成必要要素まとめ.md` 6-1 で指摘済みの「未ログイン状態で何が見えるか」は、本指摘の未決定事項が解決すれば同時に確定できる）
