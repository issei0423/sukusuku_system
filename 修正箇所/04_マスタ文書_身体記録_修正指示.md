## 0 本書の位置づけと使い方

- 本書は、**マスタ文書へ手作業で適用するための差分指示**である。リポジトリ側の各設計書は既に最新化されており、**マスタ文書だけが 2026/07/27 の内容で止まっている**。
- 従来は `基本設計書_身体記録_挿入用.md` という中間ファイルを作り、その本文をマスタ文書へコピーしていた。しかしその方式は**中間ファイル自体が旧版のまま残り、版ずれの発生源になった**（GitHub Issue #25）。今後は中間ファイルを作らず、**本書のような「どこを何にするか」の差分指示だけを残す**運用に改める。
- マスタ文書は「成果物」フォルダ配下にあり、Claude Code からは**読み取り専用**である。適用はマスタ文書の編集権限を持つメンバーが行う。

# 2 修正指示

## 2-1 【5-1 ② 園児マスタ（m_child）】列を1行追加する

**現状**：`child_id` / `child_name` / `birth_date` / `class_id` / `allergy_info` / `medical_history` / `base_temperature` の7列。**性別が無い。**

**修正**：`birth_date` の次に次の1行を挿入する。

| 物理名 | 論理名 | 型 | 制約 | 備考 |
| :-- | :-- | :-- | :-- | :-- |
| sex | 性別 | CHAR(1) | NOT NULL | 1:男 2:女 9:未回答。成長曲線基準値（⑦ m_growth_standard）の参照キー。**未回答の場合は基準値の帯を描画せず、測定値の折れ線のみを表示する** |

**根拠**：全体要件定義書 第1.8版 4-1-3「性別の登録」で要件化済み。性別の利用範囲は成長曲線の基準値参照と帳票出力に限り、機能の出し分けには用いない。

> **あわせて**：⑦ m_growth_standard の `sex` の備考に「**基準値は男女のみ。園児側の 9:未回答 に対応する基準値は持たない**」を追記する。

## 2-2 【3-2-5 身体記録】本文を差し替える

**現状**：連携先が「保護者ポータル」。権限表が「管理者モード／一般モード」表記。検討中の論点が5件残っている。

**修正**：節全体を次の内容に差し替える。

---

園児の身長・体重を定期的に記録し、成長曲線（厚労省パーセンタイル基準値）と重ね合わせた成長グラフとして可視化する、身体発育の把握支援機能。記録した測定値は、共有範囲設定に従って**チャットツールの個人チャット**へ引き渡され、保護者はチャット画面上でこれを閲覧する。発育の良否判定・肥満ややせ等の医療的診断は行わず、記録と可視化による気づき支援に責務を限定する。

**画面構成**

- 職員用画面（管理者・一般）… 身体記録画面（SCR-010）の1画面。入力タブ（測定日・身長・体重の登録、入力済みマーク、クラスの実施状況）、グラフタブ（測定値の時系列と成長曲線基準値を重ねた閲覧、PDF出力）、管理タブ（未連携記録の一覧・再連携。管理者のみ）をタブで切り替える
- 管理者のみの操作 … 範囲チェックしきい値の設定、共有範囲設定（SCR-011）、記録の削除、PDF出力、再連携
- 保護者 … **本機能の専用画面を持たない。** チャットツールの個人チャットで、共有可とされた自児の記録を閲覧する

**機能要件と権限**

| 機能 | 管理者（園長・主任） | 一般（保育士） | 保護者 |
| :-- | :-- | :-- | :-- |
| 身体測定の記録（登録・修正） | 全クラス | 自クラスのみ | ― |
| 身体測定の実施状況の確認 | 全クラス | 自クラスのみ | ― |
| 過去測定値・成長グラフの閲覧 | 全クラス | 自クラスのみ | 自児のみ（共有可の場合。個人チャット経由） |
| 記録の削除（論理削除） | 可 | ― | ― |
| 範囲チェックしきい値の設定 | 可 | ― | ― |
| 共有範囲設定の変更 | 可 | ― | ― |
| PDF出力 | 可 | ― | ― |

- 一般の参照範囲は**園児単位で判定する**。現在の担任クラスに在籍する園児であれば、その園児の過年度の記録も参照できる（全体要件定義書 4-1-2）。
- 測定回の単位は**年月**とする。測定を行う月は設定マスタで園が定め、当該月に記録がない園児を未実施として一覧に表示する。**未実施の通知は行わない。**
- 月齢は**応当日基準**で算出する。発達チェックと同一の共通関数を用いる（全体要件定義書 7-1 No.6）。

---

**削除する記述**：「検討中の論点」5件はすべて決着済みのため削除する。決着内容は `基本設計書（身体記録のみ）.md` 第5.0版の 7-2 に記載。

## 2-3 【5-1 ⑥ 身体測定記録（t_physical_record）】定義を更新する

**現状**：6列（`physical_record_id` / `child_id` / `measured_on` / `height_cm` / `weight_kg` / `staff_id`）。`measured_on` の備考に「child_id + measured_on でユニーク」。

**修正**：次の4列を追加し、`measured_on` と `staff_id` の備考を書き換える。

| 物理名 | 論理名 | 型 | 制約 | 備考 |
| :-- | :-- | :-- | :-- | :-- |
| share_status | 連携状態 | CHAR(1) | NOT NULL、初期値 1 | 0:対象外 1:未連携 2:連携済。未連携記録の抽出と再連携に用いる |
| is_deleted | 削除フラグ | BOOLEAN | NOT NULL、初期値 false | 論理削除（全体要件定義書 7-3 No.6） |
| created_at | 登録日時 | DATETIME | NOT NULL | レコードの作成時刻 |
| updated_at | 更新日時 | DATETIME | NOT NULL | レコードの最終更新時刻 |

- `measured_on` の備考 … 「未来日不可。**一意制約は `child_id + measured_on` を、`is_deleted = false` の行のみを対象とする部分一意インデックスとする**（削除した測定日に登録し直せるようにするため）」へ変更
- `staff_id` の備考 … 「**初回登録者。更新時に書き換えない**（最終更新者は共通操作ログ側で追う）」へ変更

> **注意**：部分一意インデックスは SQLite・PostgreSQL が対応し、**MySQL は非対応**である。DBMS の選定時に本制約を満たせることを条件とする。

## 2-4 【5-1 ⑪ 共有範囲設定（m_share_setting）】名称と対象を広げる

**現状**：節名が「**保護者ポータル**共有範囲設定」。`item_id` の備考が「m_development_item を参照」。

**修正**：
- 節名を「**共有範囲設定（m_share_setting）**」へ変更
- `item_id` の備考を「m_development_item を参照。**身体測定（身長・体重）も対象項目として扱えるようにする**」へ変更
- `share_flag` の備考に「チャットツールへの引き渡し時に付与し、**保護者への表示可否はチャットツール側が最終判定する**」を追記

**根拠**：現状の定義では対象が発達チェック項目に限られ、身体測定を共有範囲の対象にできない（`基本設計書（身体記録のみ）.md` 1-7 欠落2）。
