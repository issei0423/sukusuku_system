# 09 ダッシュボードと設定

> この説明は commit 41fbc463（2026-11-26 の本線）のコードに合わせてある。引いたコードと行番号は、どちらもこの版のもの。

## この機能でできること

- 職員は、ログインした直後の職員ダッシュボードで、残っている仕事の件数を見る。「届けること」（家庭からの連絡・園からのひとこと・午睡中の園児）と「園内のこと」（日誌・チャット・発達チェック・異常時の記録）に分かれ、各行の「開く」で、その仕事の画面へ移る。
- 保護者は、ログインした直後の保護者ホームで、いま見ているお子さまの「きょう」（日付・園児名・きょうのようす・園から・家庭から）を見る。お子さまが2人以上なら、名前のタブで切り替える。連絡帳・成長の記録・チャット（配布物はその中）への入口は、ホームには置かず、画面の下のタブ（きょう・連絡帳・成長・チャット）にある。連絡帳の「新着 n」・成長の「新着」・チャットの「未読 n」は、このタブに字で添える。
- 管理者は、設定画面で、連絡帳・AI の下書き・そのほかの設定値を変える。変えた値はまとめて1回で保存し、操作ログに残る。
- 管理者は、設定画面の AI の区画で、文章の下書き（AI）を使うかと、1日の上限回数を決める。サーバに API キーが無ければ、AI のボタンはどの画面にも出ない。文章の下書きは、連絡帳（園から・活動のひとこと・クラスのようす）と日誌の入力欄に出る。

要求を受ける仕組み（ログイン・権限の共通の関数・知らせ・保護者の枠 `GuardianLayout` の全体）は [01 全体の仕組み](./01-全体の仕組み.md) を見る。ダッシュボードが数える個々の仕事の中身は、各機能の説明（[03 連絡帳](./03-連絡帳.md)・[04 午睡チェック](./04-午睡チェック.md)・[05 日誌](./05-日誌.md)・[06 チャットと配布物](./06-チャットと配布物.md)・[07 成長の記録](./07-成長の記録.md)）を見る。日誌の AI の下書きに固有のところ（材料・指示文・見出し・日誌作成の画面）は [05 日誌](./05-日誌.md) を見る。

行事カレンダーは、職員ダッシュボードにも保護者ホームにも行を置いていない（`StaffDashboard.tsx`・`GuardianHome.tsx` に行事の項目は無い）。入口はメニューにある。職員は左のメニュー（連絡帳の次。[StaffLayout.tsx](../web/src/layouts/StaffLayout.tsx) 35〜36行の `NAV`）、保護者はメニューの先頭（[GuardianLayout.tsx](../web/src/layouts/GuardianLayout.tsx) 46〜47行の `MENU_PAGES`）である。行事カレンダーの中身は [11 行事カレンダー](./11-行事カレンダー.md) を見る。

## 流れ

管理者が設定を変え、それが発達チェック一覧とダッシュボードの「予定日が近い」に効くまでを例にする。

1. 管理者が設定画面で「発達チェックの予定日が近いとする日数」を 7 から 14 に変え、「保存する」を押す。確認の窓で変更の前後を見てから、もう一度「保存する」を押す。
2. 画面は `api.saveSettings` を呼ぶ（本番は `POST /api/settings`）。送るのは変えたキーだけと、設定を読んだ時刻（`read_at`）である。
3. サーバの `handleSaveSettings` が、管理者か・変えてよいキーか・値が正しいかを確かめる。1つでも誤りがあれば何も書かない。
4. トランザクションの中で `m_setting` を書く。ほかの管理者が読んだあとに変えていれば 409 にする。変わったキーごとに操作ログを残す。
5. 設定を読む側（`settingInt` など）は、呼ばれるたびに `m_setting` を読む。そのため次に一覧やダッシュボードを開いたときから、新しい値が効く。

```
設定画面（管理者）                       Go サーバ
SettingsForm ─POST /api/settings─▶ handleSaveSettings
  （変えたキーと read_at）            ├ requireAdmin・editable か・settingSpecs の検査・下限 < 上限
                                      ├ m_setting を書く（読んだあとに変わっていたら 409）
                                      └ 操作ログ（キーごとに前と後）
                                               ↓ 次に読むとき
職員ダッシュボード ─GET /api/dashboard/staff─▶ handleStaffSummary
                                      └ settingInt("dev.notice_days_before") → devNear で数える
```

**解説**
- 承認待ちの日誌は、管理者だけに数える。そのうち自分が申請した数も返す。自分の申請は自分で承認できないので、画面は「ほかの管理者へ」と添える（図/画面詳細図「職員ダッシュボード」(2-6) 項目8。GitHub Issue #268）。
- 誤送信への対応を記録していない取り消しも、管理者だけに数える。記録するのが管理者だからである（図/画面詳細図「誤送信対応記録画面（管理者）」(4-4)。GitHub Issue #141）。この行は職員ダッシュボードの項目表に無いので【仮置き】である。
- 数え損ねたときは 0 件を返さず、500 にする。「0 件」は「漏れなし」と読まれるからである。未対応の個人チャットも同じ扱いである（`unhandledPersonalChats`、201〜240行）。
- 差し戻された日誌は、逆に一般の職員だけに数える（22〜31行）。開いた先の日誌一覧と同じ範囲（自分が書いて差し戻されたもの・参照範囲の中）を数える（GitHub Issue #174）。

### 2. 「届けること」を数える（server/api_dashboard.go 81〜116行）

```go
	// 家庭からの「未確認」「更新」と、おひるね中の園児（詳細設計書「ダッシュボード」(4-8 (2))）。今日のページだけを数える。
	// 一般は自クラス、管理者は全クラス（visibleChildren の範囲）
	homeUnconfirmed, homeRevised, napSleeping := 0, 0, 0
	// 園からのひとことを送っていない園児：在籍中で、今日の取り消していない園からが無い園児。
	// 今日の午睡で「きょうは対象外（欠席）」にした子は数えない（詳細設計書 (4-8 (2))、基本設計書「届いていない家庭の一覧」(4-5)）
	facilityUnsent := 0
	for _, c := range children {
		if c.EnrollmentStatus == "1" {
			var sent, absent int
			a.db.QueryRow(`SELECT COUNT(*) FROM t_contact_facility WHERE child_id = ? AND contact_date = ? AND is_deleted = 0`,
				c.ChildID, today()).Scan(&sent)
			a.db.QueryRow(`SELECT COUNT(*) FROM t_nap_exclusion x JOIN t_nap_session n ON n.nap_session_id = x.nap_session_id
				WHERE x.child_id = ? AND x.reason = '1' AND x.is_deleted = 0 AND n.session_date = ?`, c.ChildID, today()).Scan(&absent)
			if sent == 0 && absent == 0 {
				facilityUnsent++
			}
		}
		h, err := a.loadContactHome(c.ChildID, today())
		if err != nil {
			writeErr(w, http.StatusInternalServerError, "集計に失敗しました")
			return
		}
		switch homeState(h) {
		case "unconfirmed":
			homeUnconfirmed++
		case "revised":
			homeRevised++
		}
		var sleeping int
		a.db.QueryRow(`SELECT COUNT(*) FROM t_nap_sleep s JOIN t_nap_session n ON n.nap_session_id = s.nap_session_id
			WHERE s.child_id = ? AND s.woke_at IS NULL AND s.is_deleted = 0 AND n.ended_at IS NULL AND n.session_date = ?`,
			c.ChildID, today()).Scan(&sleeping)
		if sleeping > 0 {
			napSleeping++
		}
	}
```

**解説**
- 3つの数は、見える園児（`visibleChildren`）を1人ずつ見て数える。どれも今日のページだけである（詳細設計書「ダッシュボード」(4-8 (2))）。
- 園からのひとことを送っていない園児は、在籍中で、今日の取り消していない園からのひとことが無い園児である。今日の午睡で「きょうは対象外（欠席）」にした子は数えない（基本設計書「届いていない家庭の一覧」(4-5)）。
- 家庭からの「未確認」「更新」は、連絡帳と同じ `homeState`（[server/api_contact.go](../server/api_contact.go) 457行）で決める。連絡帳（クラス）画面の印と同じ数になる。
- 午睡中は、今日の終わっていない午睡で、まだ「おきた」が無い園児である。
- 発達チェックの未実施と予定日が近いは、このあと（118〜148行）で数える。判定は発達チェック一覧と同じ `devOverdue`・`devNear` を呼ぶ（[07 成長の記録](./07-成長の記録.md) の 2.）。「近い」の日数は設定 `dev.notice_days_before` を、開くたびに読む。
- モックの `staffSummary`（[web/src/api/mock.ts](../web/src/api/mock.ts) 4436〜4510行）が同じ数え方を持つ。

### 7. 開いたときに「読んだ時刻」を残す（web/src/screens/auth/GuardianHome.tsx 49〜86行）

```tsx
  /*
   * 画面を開いたとき（表示した最初と、タブを前に出したとき）に、開いている園児の今日のページを開いた時刻を残す。
   * 知らせを受けた読み直しでは残さない（決めたこと D-23）。開く前からの新しいものの数を持っておき、
   * 開いている間に届いたものと足して「新しく n 件」に出す。
   * お子さまが2人以上のときは、名前のタブで開いた子だけを残す（開いていない子の新しいものを、見ないまま消さない）
   */
  const before = useRef<Record<string, number>>({});
  /** 開いた時刻を残したときに出していた応答（園児ごと）。これより後の応答は、残したあとに届いたものだけを数える */
  const markedData = useRef<Record<string, unknown>>({});
  const latestData = useRef(data);
  latestData.current = data;
  const newCount = (shown: unknown, childId: string, current: number) => {
    const base = before.current[childId];
    if (base === undefined) return current;
    return shown === markedData.current[childId] ? base : base + current;
  };
  // 開いている園児の「新しく n 件」を、下のタブの「連絡帳」に字で添えるため、レイアウトへ知らせる
  const shownNew = current ? newCount(data, currentId, current.today.unread_contact) : 0;
  useEffect(() => {
    if (currentId) reportContactNew(currentId, shownNew);
  }, [currentId, shownNew, reportContactNew]);
  useEffect(() => {
    if (!user || !data || !currentId) return;
    const mark = () => {
      const shown = latestData.current;
      const h = shown?.find((x) => x.child.child_id === currentId);
      if (!shown || !h) return;
      before.current[currentId] = newCount(shown, currentId, h.today.unread_contact);
      void api.markContactRead(user, currentId, today()).catch(() => undefined);
      markedData.current[currentId] = shown;
    };
    if (before.current[currentId] === undefined) mark();
    const onVisible = () => { if (document.visibilityState === 'visible') mark(); };
    document.addEventListener('visibilitychange', onVisible);
    return () => document.removeEventListener('visibilitychange', onVisible);
    // 開いている園児が変わったときだけ付け直す（読み直しのたびに付け直さない）
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [user?.account_id, currentId]);
```

**解説**
- 目的は、ホームを開いたときに、いま見ている園児の今日のページを「読んだ」ことにして、次に開いたときの「新しく n 件」を、そのあとに届いたものだけにすることである。知らせを受けた読み直しでは残さない。見ていないうちに届いたものを、画面に出る前に読んだことにしてしまわないためである（決めたこと D-23）。
- `before`（55行）は園児の ID ごとの、開く前からあった新しいものの数（`useRef`。画面を描き直しても消えない）。`markedData`（57行）は、時刻を残したときに画面に出していた応答（園児ごと）。`latestData`（58〜59行）は、描くたびに、いちばん新しい応答を指し直す。`mark` がこれを読む。
- `newCount(shown, childId, current)`（60〜64行）が、いま「新しく」と出す数を決める。その園児で時刻を残したことがまだ無ければ（`base` が無ければ）サーバが数えた `current`（`unread_contact`）をそのまま返す。残したあとで、画面に出している応答が、残したときの応答そのものなら `base`（開く前の数）を返す。残したあとの新しい応答なら、`base + current`（開く前からの数と、残したあとに届いた数）を返す。残したあとの応答の `unread_contact` は、残した時刻より後のものだけを数えているためである（56行のコメント）。
- 66行の `shownNew` は、開いている園児の「新しく n 件」である。67〜69行の効果が、これを `reportContactNew` で枠へ渡し、下のタブの「連絡帳」の字（「新着 n」）に使わせる（9.）。

**解説**
- 管理者だけが保存できる（`requireAdmin`、76行）。読む `GET /api/settings` も管理者だけである。

**解説**
- 11. と 12. のサーバと、同じ順で同じことを確かめる。管理者か → 空白を落とす → 名前の順 → 変えてよいキーか → 値の検査 → 下限 < 上限 → ぶつかり、の順である。
- 検査の関数は [web/src/api/settingSpecs.ts](../web/src/api/settingSpecs.ts) の `SETTING_SPECS` から引く。サーバの `settingSpecs` と同じ表である。業務の規則は Go サーバとモックの2か所にある（AGENTS.md「いちばん大事な決まり」）。
- 操作ログも、値が変わったときだけ `'9'`・`'2'` で残す（7283行）。

設定の値がどこに効くかは、次の2つの道がある。

- サーバの処理は、`settingInt`・`settingFloat`・`settingText`（[server/scope.go](../server/scope.go) 306〜341行）で、呼ばれるたびに `m_setting` を読む。保存すればすぐ効く。`settingInt`・`settingFloat` は、値が数として読めなければ既定値を使い、警告をログに出す（基本設計書「設定マスタ（m_setting）」(5-9)「既定値へフォールバックしたうえで警告ログを出力する」。[server/dev_schedule.go](../server/dev_schedule.go) 51〜52行のコメントによる）。
- 画面は、件数や午睡の間隔などを、参照表（`GET /api/reference`）の設定から `settingNumber` で引く（[web/src/api/http.ts](../web/src/api/http.ts) 303〜312行）。参照表はログインのときなどに読む（259行の `loadReference`）。保存した管理者の画面は、保存の直後に参照表を読み直す（912〜913行の `saveSettings`）。ほかの人がすでに開いている画面は、参照表を読み直すまで前の値を使う（推測：読み直すきっかけを全部は追っていない）。保護者に返す設定のキーは、保護者の画面で使うものに絞ってある（[server/api_reference.go](../server/api_reference.go) 23行の `guardianSettingKeys`）。

保存の前の確認の窓（[SettingsForm.tsx](../web/src/screens/admin/settings/SettingsForm.tsx) 93〜105行）は、変えたキーの前と後を並べる。AI を有効にするときは「プライバシーポリシーに外部の AI へ送ることを書いた版を施行してから有効にしてください」を、午睡のチェック間隔を既定より長くするときは注意を添える。どちらも保存は止めない。

**文章の下書き（AI）（キーがあるとき・無いとき）**

文章の下書き（AI）は、連絡帳の入力欄と日誌の入力欄に出る任意の層である。下書きは入力欄に入るだけで、送る・保存するのは職員が押したときである。道は2本で、使えるかを読む `GET /api/ai/status` と、下書きを作る `POST /api/ai/drafts` である。下書きの種類（`purpose`）は4つあり、連絡帳の3つ（`facility_note`・`rephrase`・`continue`）は `handleAiDrafts` が最後まで作り、日誌の1つ（`diary`）は `handleAiDrafts` が `handleAiDiary` へ渡す。共通の部分（使える条件・名前の置き換え・上限・呼び口・失敗の振り分け・操作ログ）を、4つが同じ関数で使う。

```
画面（AiDraftPanel）
  ├─ GET  /api/ai/status?child_id= か ?class_id= ─▶ handleAiStatus ─▶ aiAvailableFor ─▶ { available }
  └─ POST /api/ai/drafts ─▶ handleAiDrafts
        ├─ purpose = diary ─▶ handleAiDiary（api_ai_diary.go。固有のところは 05）
        │     使える条件は aiAvailableForDiary ＝ 日誌を書ける判定 ＋ aiAvailableFor
        └─ purpose = facility_note・rephrase・continue
              要求の検査 → aiAvailableFor → 名前の確認 → reserveAiCall（1日の上限）
              → anonymize（名前の置き換え）→ a.ai.Write（ai.go の口）→ aiReadReply → 操作ログ
        どちらも、呼び出しの失敗は aiCallFailure で振り分ける
```

### 15. AI を使える条件（サーバで確かめる）（server/api_ai.go 76〜100行）

```go

func (a *app) aiAvailableFor(u *SessionUser, t aiTarget) bool {
	if a.settingText("ai.enabled", "0") != "1" || !a.aiKeyUsable() || !u.isStaff() {
		return false
	}
	if t.isClass() {
		if !a.classContactAccess(u, t.ClassID).Write {
			return false
		}
		for _, id := range a.enrolledClassChildIDs(t.ClassID) {
			if !a.aiChildConsented(id) {
				return false
			}
		}
		return true
	}
	return a.contactAccess(u, t.ChildID).Write && a.aiChildConsented(t.ChildID)
}

**解説**

        .then((r) => { if (alive) setAvailable(r.available); })
        .catch(() => { if (alive) setAvailable(false); });
    }
    return () => { alive = false; };
    // eslint-disable-next-line react-hooks/exhaustive-deps -- 宛先は targetKey で見る
  }, [user, targetKey]);

  if (!available) return null;
```

**解説**
- 部品は連絡帳の入力欄 `Composer`（[web/src/screens/contact/Composer.tsx](../web/src/screens/contact/Composer.tsx) 102〜106行）の下と、日誌の作成・編集画面（[DiaryEditScreen.tsx](../web/src/screens/diary/DiaryEditScreen.tsx) 601行）に出る。発達チェックの保護者へのひとことには出さない（[07 成長の記録](./07-成長の記録.md) の 8.）。日誌では `diary` を渡す。その型は、この部品の 37〜45行の `AiDiaryUse`（`recordType`・`classId`・`share`・`headings`・`hasSentence`）である。
- 引数は、`childId`（連絡帳と個人日誌。クラス日誌・週案月案では渡さない）・`date`・`field`（欄）・`max`（欄の上限の文字数）・`text`（いまの入力欄の文）・`disabled`・`allowDraft`（「AI で下書き」を出すか。活動のひとことは言い換え・続きだけ）・`onUse(value, mode)`（入力欄に入れる。`replace` か `append`）・`focusAfterUse`・`diary` である（47〜66行）。
- `target`（78行）は、使えるかを読む宛先である。`diary` があり記録種別が個人（`'1'`）でなければクラス（`{ class_id }`）、そうでなく `childId` があれば園児（`{ child_id }`）、どちらも無ければ `null` にする。`targetKey`（79行）は、その宛先を `c:<園児>`・`k:<クラス>`・空の文字列にしたものである。
- `readStatus`（81〜82行）は、`target` があれば `api.aiStatus` を読み、`available` を状態に入れる。宛先が無いとき、読めなかったときは偽にする。
- 83〜93行の効果は、宛先が変わるたびに、まず `available` を偽にしてから `api.aiStatus` を読み直す。読み終わる前に宛先が変わった古い結果は捨てる（`alive`）。依存は `[user, targetKey]` で、宛先は `targetKey` で見る。
- 95行の `if (!available) return null` が、使えないときは何も描かない形である。偽か、読めなかったとき、宛先が無いときは何も出さず、理由も出さない（6〜7行のコメント）。AI が無くても、職員は手で書いて送れる。
- 97〜99行で、描くときの値を決める。`hasText` は、日誌なら `diary.hasSentence`（見出しの行だけの本文は文が無いとみなす）、連絡帳なら欄に文があるか。`roomForMore` は欄の上限まで10文字以上の空きがあるか（`CONTINUE_MIN_ROOM`。【仮置き】）。`checkNote` は、保存してから確かめる日誌（`diary` があり共有でない）なら「…確かめてから保存してください。」、それ以外は「…確かめてから送ってください。」である（`AI_TEXT`）。
- 下書きは入力欄に入るだけで、送るのは職員が「送る」を押したときである。宛先の表示と他児の名前の照合は、ふだんの送信と同じに通る（1〜8行のコメント）。

### 25. 押したときの処理（web/src/components/AiDraftPanel.tsx 108〜137行）

```tsx
  const make = async (purpose: AiPurpose) => {
    if (making) return;
    const pressed = focusedNow();
    let closed = false;
    setMaking(purpose); setError(null); setResult(null);
    try {
      const res = await api.aiDrafts(user!, diary
        ? {
            purpose: 'diary', record_type: diary.recordType, class_id: diary.classId, date, memo: memo.trim(),
            headings: diary.headings, share_to_guardian: diary.share,
            ...(diary.recordType === '1' ? { child_id: childId } : {}),
          }
        : {
            purpose: purpose as Exclude<AiPurpose, 'diary'>, child_id: childId!, date, field,
            ...(purpose === 'facility_note' ? { memo: memo.trim() } : { text: text.trim() }),
          });
      // 欄が空なら下書きをそのまま入れる。文があれば置き換えずに候補として出す
      const insertNow = (purpose === 'facility_note' || purpose === 'diary') && !hasText && res.drafts.length === 1;
      if (insertNow) onUse(res.drafts[0], 'replace');
      setResult({ purpose, drafts: res.drafts, replaced: res.replaced_other_names, inserted: insertNow });
      if (purpose === 'facility_note' || purpose === 'diary') { setMemoOpen(false); closed = true; }
    } catch (e) {
      setError((e as Error).message);
      // キーが無効と分かったときなどは、読み直すとボタンが消える
      void readStatus();
    } finally {
      setMaking(null);
      focusAfter(pressed, closed ? () => draftButton.current : undefined);
    }
  };
```

**解説**
- `make(purpose)` が、「下書きを作る」「言い換え」「続き」のどれを押しても呼ばれる。作っている間（`making`）は二度押しを止める（109行）。押したボタンを `focusedNow()` で覚え、`closed` を偽にして、`making` を立て、前のエラーと結果を消す（110〜112行）。
- 114〜123行が、`api.aiDrafts` に渡す要求である。`diary` があれば、`purpose: 'diary'`・`record_type`・`class_id`・`date`・`memo`・`headings`・`share_to_guardian` に、個人日誌のときだけ `child_id` を足す。なければ、`purpose`・`child_id`・`date`・`field` に、園からなら `memo`、言い換え・続きなら `text` を足す。`api.aiDrafts`（[web/src/api/http.ts](../web/src/api/http.ts) 906〜907行）が `POST /api/ai/drafts` を20秒の上限つきで呼ぶ。
- 125行の `insertNow` は、用途が園から・日誌で、欄に文が無く、下書きが1つのときに真になる。真なら `onUse(drafts[0], 'replace')` で、その場で入力欄に入れる。文があれば入れ替えずに、候補のカードで示す（196〜207行）。カードの「この文を使う」を押すと `use`（154〜159行）が、続きなら `append`、それ以外は `replace` で入力欄に入れる。
- 127行で結果（`purpose`・`drafts`・`replaced`・`inserted`）を状態に入れる。園から・日誌のときは、メモの欄を閉じる（128行）。
- 129〜132行は、失敗したときである。応答の文（「いまは下書きを作れません。そのまま書いて送れます。」など）を `error` に入れて出す。入力欄の文は残す。キーが無効と分かったときなどは、`readStatus()` で読み直すと、ボタンが消える。
- 133〜136行の `finally` で、`making` を戻し、`focusAfter` でフォーカスを移す。作っている間はパネルのボタンがすべて押せなくなり、押したボタンからフォーカスが外れるためである。言い換え・続きは押したボタンへ戻す。メモの「下書きを作る」は、作れたらメモの欄が閉じてボタンが消えるので、欄を開いた「AI で下書き」（`draftButton`）へ移す（WCAG 2.4.3、GitHub Issue #213。101〜107行のコメント）。
- 163〜176行のボタンは、「AI で下書き」（`allowDraft` のとき。メモの欄を開閉する）と、言い換え・続きである。言い換え・続きは日誌（`diary`）では出さない。言い換えは欄に文があるとき、続きは文があり空きがあるときだけ押せる。
- 178〜191行のメモの欄は、見出しの文とメモの注意（「体温や体の具合は書かずに、その日のようすを書いてください」。`AI_TEXT.memoNote`）、500文字までの `textarea`、「下書きを作る」（日誌なら `make('diary')`、そうでなければ `make('facility_note')`）と「閉じる」を持つ。
- 193行は、作っている間の「下書きを作っています（10秒ほどかかることがあります）」、196〜212行は、できたあとの候補・確かめる注意（`checkNote`）・置き換えた旨（`AI_TEXT.replacedOthers`「ほかのお子さんの名前は『おともだち』に置き換えて送りました。」）・「閉じる」である。

## 気をつけているところ

- **権限の担保はサーバにある。** ダッシュボードの管理者だけの数は、一般の職員には 0 を返す。保護者ホームは職員に 403。設定の読み書きは `requireAdmin`。AI の使える条件は、ボタンを出すときと押したときの両方でサーバが確かめる。画面の出し分けは使いやすさのためである（基本設計書「権限チェックの実装方針」(6-2)）。
- **「0 件」を嘘にしない。** 未対応の個人チャットと誤送信の数は、数え損ねたら 500 にする。0 件の行も消さずに出す。
- **件数を画面ごとに食い違わせない。** 発達チェックは一覧と同じ `devOverdue`・`devNear`、家庭からは連絡帳と同じ `homeState`、差し戻しは日誌一覧と同じ範囲で数える。
- **設定は全部か何もしないか。** 1つでも誤りがあれば書かない。ほかの管理者とぶつかったら 409 で読み直させる。値が変わったキーだけ操作ログに残す。
- **効かないキーを見分ける。** 保存できても、この版では読む処理が無いキーが7つある（`settingNoEffect`）。画面はその行に添え書きを出す。
- **API キーを外に出さない。** キーは環境変数だけ。応答はあるか・無効かの真偽だけ。テスト・手元の CI・受け入れテストはキーを渡さずに回す。
- **AI の下書きの共通の部分は、1つの関数にまとめてある。** 連絡帳の3つの用途と日誌の用途は、使える条件（`aiAvailableFor`。日誌は `aiAvailableForDiary` が日誌を書ける判定を重ねる）・名前の置き換え（`anonymize`）・1日の上限（`reserveAiCall`。連絡帳と日誌を合わせた園全体で1つ）・失敗の振り分け（`aiCallFailure`）・呼び口（`draftWriter`）を同じように使う。用途で違うのは、要求の検査・渡す事実・指示の文・出力の形・操作ログの機能と表である（23.）。下書きの種類を足すときは、この違うところだけを足す。
- **保護者の「いま見ているお子さま」は、枠が1か所で持つ。** ホーム・下のタブの「連絡帳」「成長」・URL がそれぞれ別に選ばず、`GuardianChildContext` の `childId` を見る（5.・9.）。保存は `sessionStorage` で、タブを閉じると忘れる。
- **規則は2か所にある。** `handleStaffSummary`／`staffSummary`、`handleGuardianHome`／`guardianHome`、`guardianToday`／`guardianTodayOf`、`settingSpecs`／`SETTING_SPECS`、`handleSaveSettings`／`saveSettings`、`aiAvailableFor`・`aiAvailableForDiary`・`aiChildConsented`（同じ名前）、`handleAiDrafts`／`aiApi.aiDrafts`。片方だけを直さない。
- **仮置きの値。** ダッシュボードの「対応の記録がない取り消し」の行・項目の並びと見出し、`settingNoEffect` の7つ、設定画面の区画の説明、AI のモデルを変える口、保護者の画面の見た目（きょうのようすの並び・`sessionStorage` への保存）などは、設計が決めていない。コードに【仮置き】と書き、[web/仮置き値.md](../web/仮置き値.md) に一覧がある。
