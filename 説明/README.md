# 説明：すくすくシステムのソースコードを読む

> この説明は commit 74f09acf のコードで書いた。行番号はその版のもの。

このフォルダは、すくすくシステム（保育園の連絡帳・日誌・午睡チェックなどのモックアップ）のソースコードの解説である。
どのファイルが何をしているかの一覧と、機能ごとに「実際のコード → その解説」の順で読める文書を置く。

読む人は、Go と React の文法の基本は分かるが、このリポジトリのどこに何があるかはまだ知らない人を考えている。
設計の正は `docs` ブランチの設計書である。この説明は設計書の代わりではなく、コードの道案内である。

## 全体の構成

1つの操作は、次の道を通る。上が画面（ブラウザ）、下がサーバである。

```
ブラウザ（職員のタブレット・PC ／ 保護者のスマートフォン）
  │
  ▼
React の画面（web/src）
  main.tsx（入口）→ App.tsx（経路と、入れる人の守り）→ layouts/（共通の枠）→ screens/（機能ごとの画面）
  │   画面は、データが欲しいとき必ず api/client.ts を呼ぶ
  ▼
API の呼び口（web/src/api/client.ts）。環境変数 VITE_API で行き先を切り替える
  ├─ VITE_API=mock … api/mock.ts   ブラウザの中のモック（データは api/mockDb.ts）。テストと npm run dev:mock
  └─ それ以外（既定）… api/http.ts  fetch で /api/... を呼ぶ
                          │  HTTP。ログインは Cookie のセッション
                          ▼
Go サーバ（server/。main.go が起動する）
  headers.go（セキュリティの応答ヘッダ）→ csrf.go（状態を変える要求の送信元を確かめる）
  → routes.go（URL とハンドラの対応表）
  → api_*.go（ハンドラ。機能ごとのファイル）
       ├─ session.go の requireStaff など … ログインしているか・職員か・管理者か
       ├─ scope.go・contact_scope.go ほか … この人がこの園児・クラスを見てよいか（権限の担保はここ）
       ├─ oplog.go                        … 操作ログ（追記だけ）
       └─ SQLite（db.go が開く。表は schema.sql、デモデータは seed.sql）
  書き込みのあと
       └─ events.go … 開いている画面へ「変わった」とだけ知らせる（SSE）
                          │  GET /api/events（つないだままの接続）
                          ▼
  web/src/live.ts が受け取り、hooks.ts の useAsync が既存の API で読み直す
```

言葉を3つだけ先に決めておく。

- **ハンドラ**：1つの URL の要求を受けて応答を返す関数。Go では `func (a *app) handleXxx(w, r)` の形をしている
- **モック**：サーバの代わりに、ブラウザの中で同じ規則・同じ形の応答を返す実装（`web/src/api/mock.ts`）
- **SSE**（Server-Sent Events）：サーバから画面へ一方向に知らせを流し続ける仕組み。ここでは「変わった」という合図だけを送る

## このリポジトリでいちばん大事な決まり

解説のあちこちに出てくるので、先に並べる。どれも [AGENTS.md](../AGENTS.md) に書いてある決まりである。

- **業務の規則は2か所にある。** 参照範囲・権限・承認の可否・入力の検証・操作ログの規則は、Go サーバ（`server/`）とモック（`web/src/api/mock.ts`）の両方にある。片方だけ直すと食い違う。デモデータも `server/seed.sql` と `web/src/api/mockDb.ts` の2か所にある
- **権限の担保はサーバ。** 画面でボタンを隠すのは操作しやすくするためで、守りではない。守りは `server/scope.go` ほかのサーバ側の判定である（基本設計書「権限チェックの実装方針」(6-2)）
- **設計に無い値は【仮置き】。** 設計が決めていない値（色・間隔・件数・文言など）を置いたところには、コードに `【仮置き】` と書き、[web/仮置き値.md](../web/仮置き値.md) に一覧がある
- **日付と時刻は JST に固定。** Go は `server/model.go` の `now()`・`today()`、画面は `web/src/api/util.ts` の `now()`・`today()` で作る

## 読む順のすすめ（初めての人向け）

1. この README の図で、画面からサーバまでの道をつかむ
2. [01-全体の仕組み](01-全体の仕組み.md) を読む。どの機能も同じ道（起動 → 配線 → 権限 → DB → 知らせ）を通るので、ここを先に押さえると機能ごとの解説が短く読める
3. [00-ファイルの一覧](00-ファイルの一覧.md) は辞書として使う。知らないファイル名が出たら引く
4. 機能ごとの解説（02〜09）は、気になるものから読んでよい。迷ったら 02（ログイン）→ 03（連絡帳）→ 04（午睡チェック）の順がよい。03 と 04 には、宛先の表示・他児の名前の照合・訂正の決まりなど、ほかの機能でも使う部品が多く出てくる
5. コードを直す前に [10-テストの仕組み](10-テストの仕組み.md) を読む。規則を変えたら Go とモックの両方にテストを足す決まりがある
