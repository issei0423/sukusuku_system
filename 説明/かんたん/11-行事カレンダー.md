# 11 行事カレンダー（かんたん版）

> [長い版](../11-行事カレンダー.md) を、関数1つにつき2〜3行に縮めたもの。行番号は書かない（コードが変わるとずれるため）。名前で検索して探す。

## 予定の表と形

#### `ensureEvents`（server/db.go）
行事カレンダーの予定の表 `t_event` を、古い DB にも用意する。`openDB` が開くたびに呼ぶ。
表が空（消した予定も数える）のときだけ `seedEvents` でデモの予定を入れる。→ 詳しく：[11 の節 1](../11-行事カレンダー.md)

#### `seedEvents`（server/db.go）
デモの予定を4件入れる。日付は起動した日の月から決め、`seed.sql` には予定を置かない。
モックの対は `buildEvents`（web/src/api/mockDb.ts）で、同じ4件を入れる。→ 詳しく：[11 の節 1](../11-行事カレンダー.md)

#### `eventTitleMax`（server/api_event.go）
題名の上限（50 文字）。内容の上限 `eventNoteMax`（500 文字）とともに、設計に定めが無い【仮置き】だ。
画面の入力もこの値で止めるが、担保はサーバの検査だ。→ 詳しく：[11 の節 2](../11-行事カレンダー.md)

#### `timePattern`（server/api_event.go）
時刻の形を確かめる式。`00:00`〜`23:59` の「09:30」の形だけを通し、「9:00」「24:00」は通さない。
足す・直すの入力の検査（`validateEvent`）が使う。→ 詳しく：[11 の節 2](../11-行事カレンダー.md)

#### `CalendarEvent`（server/api_event.go）
画面へ返す予定の JSON の形。開始・終了の時刻とクラスは、空のとき `null` にするためにポインタにしてある。
`class_name` と `can_edit` は、読んだあとで `fillEvent` が入れる。→ 詳しく：[11 の節 2](../11-行事カレンダー.md)

#### `scanEvent`（server/api_event.go）
予定の1行を `CalendarEvent` に読む。空を許す列は `sql.Null…` で受ける。
列の並びは `eventColumns` と合わせてある。→ 詳しく：[11 の節 2](../11-行事カレンダー.md)

## 権限と読み出し

#### `canWriteEventClass`（server/api_event.go）
予定を書ける範囲を決める、ただ1つの判定。保護者は偽、園全体は管理者だけ、クラスは管理者か担当の職員が真になる。
足す・直す・消すのどれもこれを通す。直すときは、いまの対象と移し先の両方を通す。モックは `canWriteCalendar`。→ 詳しく：[11 の節 3](../11-行事カレンダー.md)

#### `fillEvent`（server/api_event.go）
予定に `class_name` と、見ている人がその予定を直せるかの `can_edit` を入れる。
行を読み終えてカーソルを閉じたあとに呼ぶ。→ 詳しく：[11 の節 3](../11-行事カレンダー.md)

#### `writableEventClassIDs`（server/api_event.go）
見ている人が予定を書けるクラスの ID の並びを返す。管理者は今年度のクラスすべてだ。
画面が「予定を足す」を出すかと、対象の選択肢に使う。→ 詳しく：[11 の節 3](../11-行事カレンダー.md)

#### `handleCalendarEvents`（server/api_event.go）
月の予定を読む。ログインしていれば職員も保護者も通し、見られる範囲は `handoutClassIDs` に任せる。
日付順（終日が先）に並べ、`events`・`can_write_all`・`writable_class_ids` などを返す。モックは `calendarEvents`。→ 詳しく：[11 の節 4](../11-行事カレンダー.md)

## 足す・直す・消す

#### `validateEvent`（server/api_event.go）
予定の入力を確かめ、整えた時刻と誤りの文言を返す。題名の必須と上限・内容の上限・時刻の形・終了が開始より後かを順に見る。
最初に当たった誤りを返す。モックは `checkCalendarInput`。→ 詳しく：[11 の節 5](../11-行事カレンダー.md)

#### `classIDExists`（server/api_event.go）
今年度にそのクラスがあるかを返す。足す・直すで、対象にクラスを指定されたときに呼ぶ。
`handleAddCalendarEvent`・`handleUpdateCalendarEvent` が呼ぶ。→ 詳しく：[11 の節 5](../11-行事カレンダー.md)

#### `handleAddCalendarEvent`（server/api_event.go）
行事の予定を1件足す。職員に限り、入力と書ける範囲を確かめてから入れる。
入れたら `eventLogValue` の中身で操作ログを残し、`notifyCalendar` で開いている画面へ知らせる。モックは `addCalendarEvent`。→ 詳しく：[11 の節 6](../11-行事カレンダー.md)

#### `eventLogValue`（server/api_event.go）
操作ログに残す予定の中身を作る。日付・時刻・題名・内容・クラスの6項目を、決まった順で JSON にする。
足す・直す・消すの操作ログの前後の値に使う。→ 詳しく：[11 の節 6](../11-行事カレンダー.md)

#### `handleUpdateCalendarEvent`（server/api_event.go）
予定を直す。職員・ID・入力・いまの対象と移し先の権限を順に確かめ、足した職員と日時は変えない。
操作ログには変更の前後を残し、知らせる。モックは `updateCalendarEvent`。→ 詳しく：[11 の節 7](../11-行事カレンダー.md)

#### `handleDeleteCalendarEvent`（server/api_event.go）
予定を消す。行は消さず `is_deleted = 1` と、消した職員・日時を書く論理削除だ。
いまの対象に権限が無ければ 403。モックは `deleteCalendarEvent`。→ 詳しく：[11 の節 7](../11-行事カレンダー.md)

## 知らせ

#### `notifyCalendar`（server/events.go）
予定が変わったことを、見られる人にだけ知らせる。中身は予定の ID・日付・操作だけだ。
判定は `handoutClassIDs` と同じで、管理者か、園全体の予定か、自分のクラスの予定のときに送る。モックは `publish`。→ 詳しく：[11 の節 8](../11-行事カレンダー.md)

## 画面

#### `weeksOf`（web/src/components/MonthCalendar.tsx）
月を、週ごとの7日の並びにする。月の外の日は `null` で、1日の曜日の数だけ先に `null` を置く。
月の移動は `shiftMonth` が、前の月・次の月を返す。→ 詳しく：[11 の節 9](../11-行事カレンダー.md)

#### `MonthCalendar`（web/src/components/MonthCalendar.tsx）
月の格子の部品。選んだ日は `aria-pressed`、今日は `aria-current="date"` で示す。
件数の印は、字を DOM に置かず CSS の `content: attr(data-count)` で描く。ボタンの名前は日付の字だけにするためだ。→ 詳しく：[11 の節 9](../11-行事カレンダー.md)

#### `StaffCalendarScreen`（web/src/screens/calendar/StaffCalendarScreen.tsx）
職員の行事カレンダー画面。月か `tick` が変わると `api.calendarEvents` で読み直し、知らせでも読み直す。
書ける人にだけ「予定を足す」を出し、`save` が足す・直す、`remove` が確認のあとに消す。→ 詳しく：[11 の節 10](../11-行事カレンダー.md)

#### `GuardianCalendarScreen`（web/src/screens/calendar/GuardianCalendarScreen.tsx）
保護者の行事カレンダー画面。見るだけで、足す・直す・消す窓も書ける範囲の状態も持たない。
見られる予定はサーバが絞って返す。文言は `calendarText.ts` で職員の画面と共通だ。→ 詳しく：[11 の節 11](../11-行事カレンダー.md)

## モック

#### `calendarApi`（web/src/api/mock.ts）
モックの行事カレンダー。サーバの足す・直す・消す・読むと、同じ順・同じ文言で確かめる。
操作ログの機能は `'2'`（チャット）で、サーバと同じ。書ける範囲は `canWriteCalendar` が決める。→ 詳しく：[11 の節 12](../11-行事カレンダー.md)
