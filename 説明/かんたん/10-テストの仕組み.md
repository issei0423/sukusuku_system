# 10 テストの仕組み（かんたん版）

> [長い版](../10-テストの仕組み.md) を、テストのファイル・仕組み1つにつき2〜3行に縮めたもの。行番号は書かない（コードが変わるとずれるため）。名前で検索して探す。

## Go のテスト

#### `server/api_dashboard_test.go`
Go のテストの土台（`newTestApp`・`loginAs`・`call`）。テストごとに一時フォルダへ DB を作り、ポートを開かずにハンドラを直に呼ぶ。
ほかのテストもこれを使う。本物の時計で動くので、一覧の末尾や件数を決め打ちせず、本文や ID で探す。回し方は `cd server && go vet ./... && go test -count=1 ./...`。→ 詳しく：[10 の節 1](../10-テストの仕組み.md)

#### `server/api_scope_test.go`
応答の状態コードを確かめる土台（`request`・`expectStatus`）。200 以外を確かめたいときに使う。相手は Go のハンドラ。
`api_dashboard_test.go` の `call` とあわせて使う。→ 詳しく：[10 の節 1](../10-テストの仕組み.md)

#### `server/ai_test.go`
AI の下書きのテストの土台。外部の AI は呼ばず、`app.ai` に偽物の書き手（`fakeWriter`）を入れる。相手は Go のハンドラ。
AI の下書きのテストは、キーも通信も要らない。→ 詳しく：[10 の節 1](../10-テストの仕組み.md)

#### `server/api_dashboard_test.go` の既読のテスト
職員が送ったメッセージの既読の人数が、保護者が読むと 1 になることを確かめる。
送ったメッセージを一覧の末尾でなく本文で探す。決まった時間帯にだけ落ちるときは、まず時刻を疑う。→ 詳しく：[10 の節 2](../10-テストの仕組み.md)

#### `server/api_dev_test.go`
発達チェックの「未実施」は予定日を過ぎてから、という規則と、一覧とダッシュボードが同じ数を出すことを守る。相手は Go のハンドラ。
`t.Run` に日本語の名前を付けて観点ごとに分け、日付は `today()` から作る。同じ観点のモック側が `devCheck.test.ts`。→ 詳しく：[10 の節 3](../10-テストの仕組み.md)

#### `server/api_mock_rules_test.go`
Go とモックで同じ規則・同じ結果になることを、同じ観点で確かめる組の Go 側。
職員・管理者だけの API を保護者と担当外の職員に使わせないことなどを守る。モック側は `web/tests/mockServerRules.test.ts`。→ 詳しく：[10 の節 3](../10-テストの仕組み.md)

#### `server/api_event_test.go`
行事カレンダーの権限・入力・操作ログを守る Go のテスト。相手は Go のハンドラ。モック側は `web/tests/calendar.test.ts`。
ファイルの頭のコメントに、同じ観点のもう片方の場所が書いてある。→ 詳しく：[10 の節 3](../10-テストの仕組み.md)

## vitest（モックが相手）

#### `web/tests/devCheck.test.ts`
発達チェックの規則を、Go 側と `describe`・`it` の名前まで同じ観点でモックに確かめる。
相手は `api`（`client.ts`）経由のモックで、`mockDb` を直に書き換えて状況を作る。`mockDb` はファイル内で使い回されるので、前のテストを当てにしない。回し方は `cd web && npm test`。→ 詳しく：[10 の節 4](../10-テストの仕組み.md)

#### `web/tests/mockServerRules.test.ts`
Go とモックで同じ規則になることを確かめる組のモック側。相手はモックで、`npm test` で回る。
行事カレンダーの権限と操作ログの組も、ここにある。→ 詳しく：[10 の節 4](../10-テストの仕組み.md)

#### `web/vitest.config.ts`
vitest の設定。`VITE_API: 'mock'` で相手をモックにし、時計を止めるファイルを先に読む。
`npm test` はこの設定で回る。→ 詳しく：[10 の節 4](../10-テストの仕組み.md)

#### `web/tests/setup-clock.ts`
vitest の時計を、日本時間の今日の 18:00 で止める。偽物にするのは `Date` だけで、時計は進まない。
時間の経過が要るテストは `vi.advanceTimersByTime` で進める。時刻を変えて確かめるには `SUKUSUKU_TEST_CLOCK=03:00 npx vitest run`。→ 詳しく：[10 の節 5](../10-テストの仕組み.md)

#### `web/tests/growthScreens.test.tsx`
画面を描くテストの見本。1行目に `// @vitest-environment jsdom` が要り、`MemoryRouter` と `SessionProvider` で `App` を包んで描く。
相手はモック。部品は役割と名前で探し、保護者の画面に出してはいけない値が無いことも確かめる。→ 詳しく：[10 の節 6](../10-テストの仕組み.md)

#### `web/tests/visibleWording.test.ts`
画面に出す文言に、設計書の名前や章番号が無いかを見張る。相手はモックの画面とソースで、`npm test` で回る。
見張る理由の Issue は #144 だ。→ 詳しく：[10 の節 6](../10-テストの仕組み.md)

## 本物のサーバ・ブラウザが相手

#### `web/tests/integration.test.ts`
画面と同じ `http.ts` を通して、本物の Go サーバにつなぐ結合テスト。`SUKUSUKU_API` が無ければ全体を飛ばす。
サーバを立ててから `SUKUSUKU_API=http://localhost:8080 npm run test:integration` で回す。時計は本物に戻し、権限の外を開くと拒否されることも確かめる。→ 詳しく：[10 の節 7](../10-テストの仕組み.md)

#### `web/tests/acceptance/05-growth.spec.ts`
受け入れテストの見本。テスト仕様書のケースを、本物の画面と使い捨ての Go サーバ（127.0.0.1 だけ）で回す。
テスト名はケースNoで始め、証跡の画像を残す。期待は設計書から書き、NG は隠さず報告する。回し方は `npm run test:acceptance`。→ 詳しく：[10 の節 8](../10-テストの仕組み.md)

#### `web/tests/responsive/a11y-axe.spec.ts`
a11y の検査。モックの画面の全場面に axe を掛ける。HTTP の API を呼んだら誤りに数え、ブラウザの時計は固定する。
critical・serious の違反で、既知の一覧（`a11y-known.ts`）に無いものがあれば落とす。回し方は `npm run test:a11y`。→ 詳しく：[10 の節 9](../10-テストの仕組み.md)

#### `web/tests/security/probes.ts`
セキュリティの攻撃のケース（プローブ）。画面を通さず、使い捨ての Go サーバの API を直に叩き、止まるかを確かめる。
1つでも止まらなければ落ちる。本体は `security.spec.ts`で、`npm run review:security` で回す。→ 詳しく：[10 の節 10](../10-テストの仕組み.md)

#### `web/tests/deployed/smoke.spec.ts`
公開先のスモークテスト。公開先そのものに向けて、デモアカウントのログインと主な画面が開くことを、読むだけで確かめる。
ログインを失敗させず、保存も既読付けもしない。回し方は `npm run test:deployed`。→ 詳しく：[10 の節 11](../10-テストの仕組み.md)

#### `web/tests/keepMockOutOfBuild.test.ts`
本番のビルドにモックとデモデータが入らないよう、Vite のプラグイン `keepMockOutOfBuild` を見張る。
隠しログインの値は、デモ用のビルド（`npm run build:demo`）だけ通す。プラグインの関数を直に呼ぶので、相手はモックでもサーバでもない。→ 詳しく：[10 の節 12](../10-テストの仕組み.md)

## CI

#### `.github/workflows/ci.yml`
PR と本線への push で、server・web・a11y・結合・security の5つのジョブを並べて回す。1つでも赤ならマージしない。
結合のジョブは、サーバを立て、`/api/me` の応答を待ってから `npm run test:integration` を回す。実行環境は UTC で、ジョブを足すときは checkout に `ref: ${{ inputs.ref }}` を付ける。→ 詳しく：[10 の節 13](../10-テストの仕組み.md)

#### `.github/workflows/deployed-smoke.yml`
Oracle Cloud へ反映したあとと毎朝、公開先のスモークテストを回す。
相手は公開先そのものだ。→ 詳しく：[10 の節 13](../10-テストの仕組み.md)

#### `agent-harness/api-agent/scripts/local-ci.sh`
`ci.yml` と同じ確かめを手元で順に回すスクリプト。GitHub Actions が止まっていた間の代わりに作り、いまも手元で全部回すときに使う。
回し方は `bash agent-harness/api-agent/scripts/local-ci.sh <worktree> <ログの置き場>`。→ 詳しく：[10 の節 13](../10-テストの仕組み.md)
