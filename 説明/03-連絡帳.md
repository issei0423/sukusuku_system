# 03 連絡帳

> この説明は commit 74f09acf のコードで書いた。行番号はその版のもの。

## この機能でできること

- 保護者は、朝にスマートフォンで「家庭から」（体温・夜の睡眠・朝ごはん・きげん・お迎え・連絡事項）を送る。
- 職員は、タブレットの連絡帳（クラス）画面で、家庭からを読んで「確認しました」を押す。同じ表で食事・排せつ・体温を記録する。
- 職員は、連絡帳（園児）画面で、1人・1日のページを見る。活動のひとこと・写真・園からのひとことを送り、記録を直す・取り消す。
- 保護者は、連絡帳画面で、その日のページ（家庭から → きょうのようす → 園から）と月の一覧を見る。
- 職員は、ひとこと・写真に「成長の記録に残す」を付けられる。付けたものは、その子の成長の記録に並ぶ。

ねた・おきた（午睡の時刻）も連絡帳のページに出る。記録するのは午睡チェック画面である（[04 午睡チェック](./04-午睡チェック.md)）。
要求を受ける仕組み（ログイン・権限の共通の関数・知らせ）は [01 全体の仕組み](./01-全体の仕組み.md) を見る。

## 流れ

職員が食事を記録し、保護者がそれを見るまでを例にする。

1. 職員が連絡帳（クラス）画面で量を押す。画面は `api.recordEvents` を呼ぶ（画面は `web/src/api/client.ts` だけを通す。本番は `http.ts`、モックは `mock.ts` へつながる）。
2. サーバのハンドラ（1つの URL の要求を受けて応答を返す関数）`handleRecordEvents` が受ける。職員かを確かめ、`contactAccess` で書ける園児かを確かめる。
3. 値を検査し、トランザクション（全部が書けるか、何も書かないかのどちらかにする仕組み）で `t_contact_event` に入れる。操作ログも残す。
4. `notifyContactChild`（[server/events.go](../server/events.go) 435〜443行）が、その園児を読める人の開いている画面へ「知らせ」を送る。知らせの仕組みは 01 を見る。
5. 保護者の画面は知らせを受け、`GET /api/contact/children/{childID}` を読み直す。
6. サーバの `contactPage` は、保護者に見せない値（記録した職員の名前など）を落として返す。

```
職員の画面                         Go サーバ                                保護者の画面
ContactClassScreen ─POST /api/contact/events─▶ handleRecordEvents
                                               ├ contactAccess（書けるか）
                                               ├ t_contact_event に保存・操作ログ
                                               └ notifyContactChild ─知らせ─▶ GuardianContactScreen
                                                                                  │ 読み直す
                   handleContactPage ◀─GET /api/contact/children/{id}────────────┘
                   └ contactPage（保護者には職員だけの値を落とす）
```

## コードを読む

### 1. 読めるか・書けるかを決める（server/contact_scope.go 42〜72行）
```go
func (a *app) contactAccess(u *SessionUser, childID string) access {
	var n int
	if a.db.QueryRow(`SELECT COUNT(*) FROM m_child WHERE child_id = ? AND is_deleted = 0`, childID).Scan(&n) != nil || n == 0 {
		return access{}
	}
	switch {
	case u.isAdmin():
		return access{Read: true, Write: true}
	case u.isGeneralStaff():
		classes := a.staffClassIDs(u)
		if len(classes) == 0 {
			return access{Read: true}
		}
		args := []any{childID}
		for _, id := range classes {
			args = append(args, id)
		}
		var hit int
		a.db.QueryRow(`SELECT COUNT(*) FROM t_class_child WHERE child_id = ? AND class_id IN (?`+
			strings.Repeat(",?", len(classes)-1)+`)`, args...).Scan(&hit)
		return access{Read: hit > 0, Write: hit > 0}
	case u.isGuardian() && u.GuardianID != nil:
		var status string
		if a.db.QueryRow(`SELECT link_status FROM t_guardian_child WHERE guardian_id = ? AND child_id = ?`,
			*u.GuardianID, childID).Scan(&status) != nil {
			return access{}
		}
		return access{Read: status == "1" || status == "3", Write: status == "1"}
	}
	return access{}
}
```
**解説**
- 連絡帳のどの経路も、最初にこの `contactAccess` で「読める（Read）」「書ける（Write）」を決める。戻り値は2つの真偽の組（20行の `access`）である。
- まず園児がいるかを見る。取り消した園児（`is_deleted = 1`）なら、何もできない。
- 管理者は全園児を読み書きできる。一般の職員は、今年度の担任クラスの園児だけを読み書きできる。担任クラスが無い職員（フリー）は、全園児を読むだけである。
- 保護者は紐づけ（`t_guardian_child`）の状態で決まる。1:有効 なら読み書き、3:猶予中（卒園・退園のあと）なら読むだけである。
- 既存の `canSeeChild`（scope.go）は猶予中とフリーを扱わない。そのため連絡帳はこの関数を使う（コメント 8〜9行、決めたこと D-18）。典拠は詳細設計書「判定の関数」(4-1 (2))。
- モックにも同じ名前の `contactAccess` がある（[web/src/api/mock.ts](../web/src/api/mock.ts) 4755〜4766行）。規則を変えるときは両方を直す。クラスの表を読めるかは、隣の `classContactAccess`（104〜125行）が決める。

### 4. 保護者が開いた時刻を残す（web/src/screens/contact/GuardianContactScreen.tsx 53〜67行）
```tsx
  /*
   * 「新」の印は、この画面を開く前に読んだ時刻と比べる。開いた直後に開いた時刻を残すため、
   * 読み直しの応答の last_read_at は新しくなる。最初の値を持っておき、開いている間に届いたものにも印を残す

  if (data && data.child_id === childId && data.contact_date === date && firstRead.current?.key !== key) {

  useEffect(() => {
    if (!user || !data || data.child_id !== childId || data.contact_date !== date) return;
    void api.markContactRead(user, childId, date).catch(() => undefined);
    // 開いたとき・日付を移ったときに1回。知らせの読み直しでは呼ばない
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [user?.account_id, childId, date, !!data]);
```
**解説**
- 保護者が連絡帳画面を開くと、`api.markContactRead` で「このページを開いた時刻」をサーバに残す（`POST /api/contact/children/{childID}/read`。サーバは [server/api_contact.go](../server/api_contact.go) 410〜441行）。

- 「新」の印は、この画面を開く前の時刻と比べる。開いた直後に時刻を残すので、読み直しの応答の `last_read_at` は新しくなる。そのため最初の値を `firstRead` に持っておく。

- 画面は [KeepInGrowthToggle.tsx](../web/src/screens/contact/KeepInGrowthToggle.tsx) と、写真を送る窓のチェックボックスである。モックは `growthApi.keepInGrowth`（[web/src/api/mock.ts](../web/src/api/mock.ts) 5504〜5520行）。

### 15. 月の一覧で数える（server/api_contact_month.go 133〜156行）
```go
	// きょうのようす（食事・排せつ・体温・ひとこと・写真）。保護者には出す種類だけ数える
	// 接続は 1 本なので、行を読んでいる間に設定を引かない。種類ごとの可否は先に決めておく
	seesEvent := map[string]bool{}
	for _, kind := range []string{"1", "2", "3", "4", "5"} {
		seesEvent[kind] = !guardian || a.guardianSeesItem(eventItem(kind))
	}
	er, err := a.db.Query(`SELECT contact_date, event_type, recorded_at, corrected_at FROM t_contact_event
		WHERE child_id = ? AND is_deleted = 0 AND contact_date BETWEEN ? AND ?`, childID, first, last)
	if err != nil {
		return nil, err
	}
	for er.Next() {
		var date, kind, at string
		var fixed *string
		if er.Scan(&date, &kind, &at, &fixed) != nil {
			continue
		}
		if guardian && !seesEvent[kind] {
			continue
		}
		count(date)
		newer(date, laterOf(at, fixed))
	}
	er.Close()
```
**解説**
- 月の一覧は、日ごとに「家庭から」「園から」の有無と、きょうのようすの件数を出す。保護者の連絡帳画面の「月の一覧」で開く（[MonthList.tsx](../web/src/screens/contact/MonthList.tsx)）。
- 保護者には、園が出さない種類を数えない。種類ごとの可否は、行を読む前に決めておく。DB の接続は1本なので、行を読んでいる途中で設定を引けないからである（134行のコメント）。
- `newer`（97〜103行）が、保護者が前に開いた時刻より後に記録・訂正されたものに「新しい」（`unread`）を付ける。職員の応答には付けない。
- 移れる月の下限は、その子の連絡帳にいちばん早く記録のある月である（191〜204行）。在籍の始まりの日を持つ列が無いための【仮置き】である（20〜21行のコメント）。応答に `has_home`・`record_count` を足したのも【仮置き】である（18〜19行）。
- 権限は1ページを読むのと同じ `contactAccess` の Read である（48行）。モックは `contactMonth`（[web/src/api/mock.ts](../web/src/api/mock.ts) 5183行から）。

## 気をつけているところ

- **権限の担保はサーバにある。** 連絡帳の経路は、すべて `contactAccess`・`classContactAccess`・`canFixContact` を通る。画面の `can_write` による出し分けは使いやすさのためで、守りではない（基本設計書「権限チェックの実装方針」(6-2)）。
- **在るかどうかを漏らさない。** 権限の外も、園児が無いのも、取り消した行も、同じ 403「この園児の連絡帳は開けません。」にする（[contact_scope.go](../server/contact_scope.go) 18行）。写真も同じく「この写真は開けません。」にそろえる。
- **保護者に見せない値。** 記録した職員・確認した職員・書いた保護者と続柄・直した職員の名前、入眠時の体温、実施の ID、出来事・園から・ねた・おきたの版（`updated_at`。家庭からの版は、保護者も送り返すので返す）、クラスのようすの元の日誌（`source_diary_id`）、取り消した行、`contact.show_items` で外した種類。5分ごとの確認と「きょうは対象外」は、そもそも読まない。
- **知らせも同じ規則で絞る。** `notifyContactChild`（[events.go](../server/events.go) 435〜443行）は、読めない人に送らない。保護者には、出さない種類の変化を送らない。
- **判定しない。** 体温は範囲の外も保存し、色や言葉で良し悪しを言わない。午睡の長さにも言わない（[contactText.ts](../web/src/screens/contact/contactText.ts) 4行）。
- **同時に押したとき。** 版を書くたびに必ず進め、書き換えの文の条件で照合する。違えば 409 にして、画面は読み直す（決めたこと D-40）。
- **写真。** 形式は先頭のバイトで決める。描き直して付帯情報を落とす。実体は公開しない。同意は送った時点の値を残す。
- **規則は2か所にある。** モック（`web/src/api/mock.ts`）は、同じ名前の関数（`contactAccess`・`canFixContact`・`canSeePhoto`・`canKeepInGrowth`・`readersOf` など）で同じ規則を持つ。片方だけを直さない。
- **仮置きの値。** 写真の画素数の上限、写真の行のクラス、月の一覧の日の形と下限、続柄が空のときの「保護者」などは、設計が決めていない値である。コードに【仮置き】と書き、[web/仮置き値.md](../web/仮置き値.md) に一覧がある。
