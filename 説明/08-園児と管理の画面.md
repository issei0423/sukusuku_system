# 08 園児と管理の画面

> この説明は commit 74f09acf のコードで書いた。行番号はその版のもの。

## この機能でできること

- 管理者（園長・主任）は、園児マスター（園児の基本の情報・クラス・アレルギー・既往歴）を登録・編集する。誤って登録した園児は取り消す。CSV ファイルでまとめて登録もできる。
- 職員は、園児一覧と、全園児のアレルギー一覧を見る。一般（保育士）は見るだけで、登録・編集はできない。
- 管理者は、保護者の新規登録に使う招待コードを発行し、配布用に印刷し、失効させる。
- 管理者は、保護者と園児の紐づけを解除し、戻し、結び直す。職員アカウントを発行・変更・停止・再開し、一時パスワードの再発行とロックの解除をする。
- 年度の切り替え（年度更新）は、いまの年度の内訳を見るだけだ。実行はこのモックアップでは作っていない。
- 管理者は、操作ログを絞り込んで見て、CSV で出す。

## 流れ

園児を1人登録するときの流れを書く。

1. 管理者が、園児一覧の「新規登録」から入力画面（ChildInputScreen）を開く。画面は、使われている番号の次を園児ID に入れておく。
2. 「確認へ進む」で、画面が必須・よみ・生年月日・アレルギーを確かめる。園児ID の重複は `GET /api/children/{childID}/exists` で尋ねる。
3. 確認画面（ChildConfirmScreen）が `GET /api/children/same-name-birth` で、同じ氏名・生年月日の園児を尋ねる。いれば知らせるが、止めはしない。
4. 「登録する」で `POST /api/children` を送る。サーバのハンドラ（1つの URL の要求を受けて応答を返す関数）`handleSaveChild` は、`requireAdmin` で管理者かを確かめ、入力を検査し直す。
5. 1つの取引（トランザクション。いくつかの書き込みを「全部するか、全部しないか」にまとめる仕組み）で、園児・クラスの在籍・最初の発達チェックの予定・個人チャット・アレルギー・既往歴を書く。
6. 確定のあと、変わった項目を操作ログへ残し、登録した園児を返す。

```
screens/master/* ──api.*──▶ client.ts ─┬─▶ http.ts ──/api/children・/api/admin/*──▶ requireAdmin ／ requireStaff ──▶ SQLite
                                        └─▶ mock.ts（同じ規則を持つ、もう1つの場所）
```

- 解除した紐づけを有効へ戻す道は2つある。「紐づけを戻す」と「結び直す」だ。どちらも同じ API（`POST /api/admin/guardian-links/restore`）で、`relink` で分ける。
- 解除した日から 7 日まで（`restoreLinkDays`、1147行）は「紐づけを戻す」になる。誤って解除したときの戻し先で、解除の前の状態へ戻す（基本設計書「保護者と園児の紐づけを戻す」(4-3)）。チャットの参加の `left_at` を消すので、解除していたあいだのやりとりも読める（`rejoinRoomsOfChild`、1102〜1141行）。
- 7 日を過ぎた紐づけと、`relink: true` の要求は「結び直す」になる（1279行）。紐づけた日時を今にし（1284〜1288行）、今の時刻でチャットへ入り直す（`joinRoomsOfChildNow`）。新しい招待コードで結んだときと同じ扱いで、解除していたあいだのやりとりは読めない（決めたこと D-48）。
- 7 日という日数と、過ぎたら結び直すこと、`relink` で選べることは【仮置き】だ（1143〜1147行・1197行）。
- 止まっていたアカウントは、あわせて再開する（1304〜1314行。GitHub Issue #118）。止まった保護者アカウントを再開する道はこの操作だけなので、日数で断らない（1180〜1181行）。
- 画面（GuardianAccountsScreen.tsx 120〜130行）は、期間の内なら「紐づけを戻す」と「結び直す」を並べる。過ぎたら「結び直す」だけを出す。戻せる最後の日は、サーバが一覧に入れて返す（`restore_until`、api_admin.go 926〜928行）。どちらになるかの最後の判定は、サーバだ。
- 同じ画面は、最新版の規約に同意していない保護者を、一覧の上に出す（GuardianAccountsScreen.tsx 66行・74〜83行）。
- モックの `restoreGuardianLink`（mock.ts 3833〜3875行）も同じ規則だ。日数は、画面とモックが `web/src/api/codes.ts` の `RESTORE_LINK_DAYS` を使う。

## 気をつけているところ

- **権限の担保はサーバだ。** 園児の登録・編集・取消・CSV・招待コード・アカウント・紐づけ・操作ログは、どれも `requireAdmin` で管理者に限る（基本設計書「権限チェックの実装方針」(6-2)）。画面の `RequireAdmin`（App.tsx 151〜158行）とボタンの出し分けは、操作性のためだ。
- **園児の参照範囲は `scope.go` が決める。** `visibleChildren`・`canReadChild`・`canSeeChild` だ。アレルギー一覧だけは全園児を返す例外で、返す列を絞っている。既往歴は `canSeeChild` で確かめるので、フリーの職員は読めない（api_child.go 178行、scope.go 124〜127行）。
- **園児情報・アレルギー・既往歴は、保護者に返さない**（api_child.go 115〜121行。基本設計書「権限と利用可能機能」(6-1)。GitHub Issue #157）。
- **業務の規則はサーバとモックの2か所にある。** 園児の検査・取消の条件・CSV の検証・招待コードの枚数と日数・紐づけの解除と戻し方・操作ログの残し方・出力の記録は、どれも両方にある。管理者だけの断りの文も、サーバの `requireAdmin` とモックの `ADMIN_ONLY_MESSAGE`（mock.ts 87行）でそろえてある。デモデータも、`server/seed.sql` と `web/src/api/mockDb.ts` の2か所にある。
- **書き込みは1つの取引にまとめ、失敗したら全部を戻す。** モックは `undo` を積み上げて、同じことをする。
- **操作ログは、変わった項目を `{"項目名": 値}` で残す。** システムが行った停止は「システム」の行に分ける。一時パスワードは残さない。
- **重ねての操作で、事実と違うログを残さない。** 取り消した園児の取消・失効したコードの失効・ロックされていないアカウントの解除は、どれも断る（GitHub Issue #166 の 4・6）。
- **セッションを切る操作がある。** 一時パスワードの再発行・職員の停止・紐づけの解除だ（[02 ログインとアカウント](./02-ログインとアカウント.md) の「気をつけているところ」）。
- **【仮置き】の主なもの。** 招待コードの有効日数（1〜365 日）・一覧の並び・配布物の手順の文面、紐づけを戻せる日数（7 日）と結び直し、同じ氏名・生年月日の知らせ、よみの必須、CSV の平熱の整数部 3 桁、システムの行の分け方。一覧は `web/仮置き値.md` にある。
