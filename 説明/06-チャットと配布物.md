# 06 チャットと配布物

> この説明は commit 41fbc463（2026-11-26 の本線）のコードに合わせてある。引いたコードと行番号は、どちらもこの版のもの。

## この機能でできること

- 職員（タブレット・PC）と保護者（スマートフォン）が、チャンネル（話す場）ごとにメッセージをやりとりする。
- チャンネルは5種類ある。園全体・職員・クラス・目的別グループ・個人チャット（園と1家庭のやりとり）。だれが入るかは、ほとんどがアカウント・ロール・担任の割り当てから自動で決まる。
- 職員が保護者の参加するチャンネルへ送るときは、送る前に「ほかの子の名前が入っていないか」をサーバが照合し、当たれば注意を出す。
- 送ったメッセージは取り消せる。管理者は誤送信への対応として、ほかの人のメッセージも削除できる。その後、誤送信対応記録画面で「既読だったか」「とった対応」を残す。
- リアクション・編集・取消は、メッセージを右クリック（タブレット・スマートフォンでは長押し）して開く操作の一覧から行う。キーボードでは、吹き出しを選んで Enter・スペースで同じ一覧を開く。
- 職員のチャット画面では、「保護者との個人チャット」の欄を、園児の名前で絞り込める。管理者は全クラスの家庭の個人チャットが並ぶため。
- 園だより・献立表などの配布物は、管理者が配布物管理画面で掲載・取り下げする。掲載すると、チャットに知らせが流れる。保護者は「園からの配布物」で月ごとに見返す。保護者の画面では、下のタブ「チャット」から開く。

## チャンネルの種類とだれが入るか

`m_chat_room.room_type` のコード値は [web/src/api/codes.ts](../web/src/api/codes.ts) 32〜36行にある。職員の参加の規則は [server/chat_membership.go](../server/chat_membership.go) の頭（8〜33行）の表にまとまっている。

| `room_type` | 名前 | 入る職員 | 入る保護者 | 投稿できる人 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | 園全体（保護者の画面では「園からのお知らせ」） | 有効な全職員 | 登録した保護者 | 管理者だけ |
| 5 | 職員 | 有効な全職員 | 入らない | 参加している職員 |
| 2 | クラス（クラスグループ） | そのクラスの当年度の担任と管理者 | 子がいま在籍するクラスの保護者 | 参加している職員 |
| 4 | 個人（保護者の画面では「担任の先生とのやりとり」。お子さまが2人以上いて個人チャットが2つ以上あるときは、園児名を添える） | その園児のクラスの当年度の担任と管理者 | その園児の保護者 | 参加している職員と、その家庭の保護者 |
| 3 | 目的別グループ | 職員がグループ編成画面で手で入れる | 入らない | 参加している職員 |

- 保護者の参加は、招待コードの登録・お子さまの追加のとき（`joinRoomsOfChildNow`、[server/api_guardian.go](../server/api_guardian.go) 269行〜）に決まる。紐づけを解除すると、個人チャットとクラスグループから外れる（`leaveRoomsOfChild`、[server/api_admin.go](../server/api_admin.go) 1081〜1100行）。
- 外れるときは参加の行（`t_chat_member`）を消さず、`left_at`（外れた日時）を入れる。所属していた期間を、過去ログを読める範囲の判定に使うため（基本設計書「チャット」(5-5)）。
- メッセージの `source_type` は、1 がふつうの投稿、4 が配布物の掲載の知らせ。2・3 は以前の「日誌・発達身体の共有の知らせ」で、いまはすべて取り消し済みにしてある（[server/db_diary.go](../server/db_diary.go) 52〜60行）。

## 流れ

1. 画面を開くと、`GET /api/chat/rooms`（`handleChatRooms`）で、参加しているチャンネルと、未読の件数・投稿できるか（`canPost`）・届く保護者の人数を読む。個人チャットには、その園児の `child_id` も添える（[server/api_chat.go](../server/api_chat.go) 26・92〜94行。個人チャットでない部屋には付けない。PR #375）。異常時記録画面の「この園児の個人チャット」は `/staff/chat?child=…` で開き、チャット画面は `child_id` でその園児の個人チャットを選ぶ。一覧に無ければ、別の家庭のチャンネルを黙って開かず、その旨を出す（[StaffChatScreen.tsx](../web/src/screens/chat/StaffChatScreen.tsx) 82〜87・97〜108・344〜348行）。職員の画面では、一覧の「保護者との個人チャット」の欄を園児の名前で絞り込める（ブロック 6・7）。保護者の画面は、連絡先の一覧から1つを選んで開く（ブロック 10）。
2. チャンネルを選ぶと、`GET /api/chat/rooms/{id}/messages` でメッセージを読み、`POST .../read` で既読にする。メッセージを右クリック（長押し）して開く操作の一覧から、リアクション・編集・取消をする（ブロック 8・9・11）。
3. 送ると `POST /api/chat/rooms/{id}/messages`（`handleSendMessage`）。サーバは参加・権限・本文・他児の名前を確かめてから `t_chat_message` に書く。
4. 他児の名前が当たると 409（いまの状態とぶつかったときなどに返す応答。ここでは注意を表す。`kind: other_child_names`）。画面は注意のダイアログを出し、「このまま送る」で承諾した名前を添えて送り直す。
5. 書けたら操作ログを残し、`notifyRoomPost` で、いまの参加者の開いている画面へ知らせる。画面は知らせを受けて読み直す。
6. 配布物は `POST /api/handouts`（管理者）で掲載する。同じトランザクション（全部書くか、何も書かないかのまとまり）で、園チャットかクラスグループへ「〇〇を掲載しました。」のメッセージ（`source_type` 4）を入れる。見られる範囲を決める `handoutClassIDs`（[server/api_handout.go](../server/api_handout.go)）は、行事カレンダーの予定の範囲と知らせの送り先にも使われる（経路は同じ `routeChat` の中。中身は [11 行事カレンダー](./11-行事カレンダー.md) を見る）。

```
StaffChatScreen ──送信──▶ POST /api/chat/rooms/{id}/messages ──▶ handleSendMessage
                                  │ 参加・猶予・投稿権限・本文・他児の名前
                                  ├─ 当たった ──▶ 409 other_child_names ──▶ NameCheckDialog ──承諾して送り直す
                                  └─ 通った ──▶ t_chat_message ──▶ 操作ログ・notifyRoomPost
                                                                     └──▶ 参加者の画面が読み直す
StaffHandoutsScreen ──掲載──▶ POST /api/handouts ──▶ t_handout ＋ 掲載の知らせ（source_type 4）
GuardianChatScreen（下のタブ「チャット」）──「園からの配布物」の行／知らせのカード──▶ GuardianHandoutsScreen ◀── GET /api/handouts
```

## コードを読む

### 1. 職員を自動のチャンネルへ入れる（server/chat_membership.go 43〜75行）

```go
// autoRoomsWhere は、アカウント・ロール・担任の割り当てから参加者が決まるチャンネル（m_chat_room を r として引く）
const autoRoomsWhere = `r.is_archived = 0 AND r.room_type IN ('1', '2', '4', '5')`

// syncStaffChatRooms は、職員1人の参加を規則に合わせる。入れたり外したりした数を返す。
// 職員でないアカウントには何もしない。
func syncStaffChatRooms(q dbtx, accountID int64) (int, error) {
	var role, status string
	if err := q.QueryRow(`SELECT role, status FROM m_account WHERE account_id = ?`, accountID).
		Scan(&role, &status); err != nil {
		return 0, err
	}
	if role != roleAdmin && role != roleGeneralStaff {
		return 0, nil
	}

	wanted := map[int64]bool{}
	if status == "1" {
		ids, err := queryIDs(q, `SELECT r.chat_room_id FROM m_chat_room r
			WHERE `+autoRoomsWhere+`
			  AND (r.room_type IN ('1', '5')
			       OR ? = '1'
			       OR r.class_id IN (SELECT cs.class_id FROM t_class_staff cs
			                           JOIN m_class c ON c.class_id = cs.class_id AND c.fiscal_year = ?
			                           JOIN m_staff s ON s.staff_id = cs.staff_id
			                          WHERE s.account_id = ?))`,
			role, fiscalYear, accountID)
		if err != nil {
			return 0, err
		}
		for _, id := range ids {
			wanted[id] = true
		}
	}
```

**解説**

- `syncStaffChatRooms` は、職員1人について「入るべきチャンネル」（`wanted`）を決め、いまの参加と食い違う分だけ入れたり外したりする。
- 入るべきチャンネルは、園全体（1）と職員（5）はだれでも、管理者（`? = '1'`）はクラスと個人のすべて、一般は当年度の担任のクラスとそのクラスの園児の個人チャット。
- 停止中（`status` が 1 でない）の職員は `wanted` が空になり、自動のチャンネルからすべて外れる。外すときは `left_at` を入れる（77〜95行）。戻すときは `left_at` を空にして入れ直す（96〜107行）。
- 目的別グループ（3）とアーカイブ（過年度のクラスグループ）は `autoRoomsWhere` から外れていて、ここでは動かさない。
- 呼ぶのは、職員アカウントの発行・変更・停止と再開（api_admin.go 268・381・537行）、園児の登録で個人チャットを作るとき（child_room.go 42行）、起動のとき（`syncChatMembership`、140〜166行。main.go 140行から）。起動のときは、職員だけのチャンネルに入っている保護者も外す。
- 【仮置き】個人チャットの担任は、ルームの `class_id`（園児のクラス）で決める。名前で引くと、同じ氏名の別の園児の家庭に入ってしまうため（27〜30行。GitHub Issue #140・#163）。
- 目的別グループは手で編成する（`handleUpdateGroupMembers`、[server/api_chat.go](../server/api_chat.go) 1137〜1227行）。入れられるのは有効な職員だけで、保護者は入れない（`groupMemberError`、1107〜1122行）。一般の職員は、いま参加しているグループだけを編成できる（【仮置き】GitHub Issue #161）。
- 気をつけるところ：モックの `syncStaffChatRooms`（[web/src/api/mock.ts](../web/src/api/mock.ts) 2031〜2054行）に同じ規則がある。片方だけ直すと食い違う。

### 2. 後から入った保護者・外れた職員に見せないメッセージ（server/api_chat.go 173〜179・207〜210行）

```go
const beforeJoinedClause = ` AND NOT EXISTS (
	SELECT 1 FROM t_chat_member gm
	  JOIN m_chat_room gr ON gr.chat_room_id = gm.chat_room_id
	 WHERE gm.chat_room_id = m.chat_room_id AND gm.account_id = ?
	   AND gr.room_type = '4' AND m.sent_at <= gm.joined_at
	   AND m.sent_at >= ` + firstGuardianJoinedAt + `
	   AND (gm.joined_at > ` + firstGuardianJoinedAt + ` OR gm.account_id <> ` + firstGuardianAccountID + `))`
// …（略）…
const afterLeftClause = ` AND NOT EXISTS (
	SELECT 1 FROM t_chat_member lm
	 WHERE lm.chat_room_id = m.chat_room_id AND lm.account_id = ?
	   AND lm.left_at IS NOT NULL AND m.sent_at >= lm.left_at)`
```

**解説**

- どちらも、メッセージを読む SQL（`t_chat_message` を `m` とする）の WHERE に足す条件である。一覧・未読の数え・既読・知らせのどれにも同じ条件を足し、範囲をそろえる。
- `beforeJoinedClause`（保護者だけに足す）：後から登録した保護者には、自分が入る前の個人チャットのやりとりを見せない。先に登録していた保護者は、自分の書いたものが後から加わる人に読まれると知らないため（基本設計書「チャット」(5-6)。155〜172行の説明）。
- ただし、その部屋に保護者がまだ1人もいなかった間の投稿は見せる。個人チャットは園児の登録のときに作るので、保護者の登録より前から園が書けるため（GitHub Issue #140）。境は、その部屋に保護者が初めて入った日時（`firstGuardianJoinedAt`、191〜193行）。
- 時刻は秒の単位なので、登録と同じ秒のメッセージは前か後かを区別できない。見せない側へ倒す（基本設計書「メッセージの送受信」(4-7)。GitHub Issue #102・#301）。
- `afterLeftClause`（だれにでも足す）：外れたあとの投稿は見せない。読めるのは所属していた期間の過去ログだけ（GitHub Issue #161）。保護者は外れた時点でチャンネルごと読めなくなる（ブロック 3）ので、実際に効くのは職員である。同じ秒は、これも見せない側へ倒す（【仮置き】）。

### 3. チャンネルを読めるか・書けるか（server/api_chat.go 238〜274行）

```go
// isMember はそのチャンネルを参照できるかを判定する。
// 職員は外れたあとも、所属していた期間の過去ログを参照できる（読む範囲は afterLeftClause で絞る）。
// 保護者は left_at が入った時点で参照できなくなる（基本設計書 5-5）
func (a *app) isMember(u *SessionUser, roomID int64) bool {
	joined, left := a.memberState(u.AccountID, roomID)
	if !joined {
		return false
	}
	return !(left && u.isGuardian())
}

// canRead は、そのチャンネルのメッセージを読めるか。参加していれば isMember と同じ。
// 管理者は、参加していないグループも読める（書けない。書けるのは isParticipant の人だけ。GitHub Issue #312）
func (a *app) canRead(u *SessionUser, roomID int64) bool {
	if a.isMember(u, roomID) {
		return true
	}
	if !u.isAdmin() {
		return false
	}
	var n int
	a.db.QueryRow(`SELECT COUNT(*) FROM m_chat_room WHERE chat_room_id = ? AND room_type IN `+adminReadOnlyRoomTypes,
		roomID).Scan(&n)
	return n > 0
}

/*
isParticipant は、いまそのチャンネルに参加しているか（外れていないか）を判定する。

投稿・編集・取消・リアクション・未対応の切り替え・メンバー一覧の取得は、いまの参加者に限る。
外れた職員は過去ログを読めるだけで、書くことはできない（基本設計書「メッセージの送受信」(4-6)
「閲覧のみの権限では拒否する」、図/画面詳細図.md 4-3 No.8。GitHub Issue #161）。
*/
func (a *app) isParticipant(u *SessionUser, roomID int64) bool {
	joined, left := a.memberState(u.AccountID, roomID)
	return joined && !left
}
```

**解説**

- 3つの判定を使い分ける。`isMember` は参加の行があるか（保護者は外れたら偽）、`canRead` は読めるか、`isParticipant` はいま参加しているか（外れていないか）。
- 職員は外れたあとも、所属していた期間の過去ログを読める（`isMember` が真のまま）。保護者は `left_at` が入った時点で読めなくなる（基本設計書「チャット」(5-5)）。
- 管理者は、参加していないグループ（園全体・クラス・目的別・職員の全年度）も読める（`adminReadOnlyRoomTypes`、141行。要件定義書「過去ログの参照範囲」(4-4 (c))。GitHub Issue #312）。個人チャットは園児ごとに決めるので、参加の行があるものだけ。
- 書く操作（投稿・編集・取り消し・リアクション・未対応の切り替え）は、いまの参加者（`isParticipant`）に限る。外れたチャンネルは閲覧のみである（GitHub Issue #161）。例外として、管理者の取り消しは参加を問わない（ブロック 13）。

```ts
/** 照らす前にそろえる。全角・半角（NFKC）、空白を除く、英字を小文字に */
export function normalizeRoomQuery(s: string): string {
  return s.normalize('NFKC').replace(/\s/g, '').toLowerCase();
}

/** 個人チャットの園児名。部屋の名前は「園児名の保護者」（詳細設計書「園児の登録と個人チャット」(4-9)） */
export function childNameOfRoom(room: Pick<ChatRoom, 'room_name'>): string {
  return room.room_name.replace(/の保護者$/, '');
}

/** 入れた文字に当たる個人チャットか。空（空白だけを含む）なら、すべて当たる */
export function matchesRoomQuery(room: Pick<ChatRoom, 'room_name'>, query: string): boolean {
  const q = normalizeRoomQuery(query);
  return q === '' || normalizeRoomQuery(childNameOfRoom(room)).includes(q);
}
```

### 8. 右クリック・長押し・キーボードで、操作の一覧を開く（web/src/secondaryAction.ts 57〜128行）

```ts

  const timer = useRef<number | null>(null);
  const start = useRef<{ x: number; y: number } | null>(null);
  // 長押しで開き、まだ指を離したあとのクリックを無視していない
  const suppressClick = useRef(false);

  const cancel = () => {
    if (timer.current !== null) { clearTimeout(timer.current); timer.current = null; }
    start.current = null;
  };

  useEffect(() => {
    const swallow = (e: Event) => {
      if (!suppressClick.current) return;
      suppressClick.current = false;
      e.preventDefault();
      e.stopPropagation();
    };
    const reset = () => { suppressClick.current = false; };
    document.addEventListener('click', swallow, true);
    document.addEventListener('pointerdown', reset, true);
    return () => {
      document.removeEventListener('click', swallow, true);
      document.removeEventListener('pointerdown', reset, true);
      cancel();
    };
  }, []);

  return (open) => ({
    tabIndex: 0,
    /*
     * aria-haspopup・aria-expanded は付けない。吹き出しは役割を持たない div で、この2つを付けられない（axe の aria-allowed-attr）。
     * role="button" にすると、中のリンク（配布物のカード）が入れ子の操作になる。開いたら一覧の最初のボタンへ移り、
     * Esc で吹き出しへ戻ることと、案内文（aria-describedby）・開いたときの知らせ（MENU_OPENED_TEXT）で伝える
     */
    // 吹き出しそのものを選んでいるときだけ。中のリンク・入力欄の Enter はそのまま通す
    onKeyDown: (e) => {
      if (e.target !== e.currentTarget || (e.key !== 'Enter' && e.key !== ' ')) return;
      e.preventDefault();
      open(e.currentTarget);
    },
    onPointerDown: (e) => {
      if (e.pointerType === 'mouse' || onControl(e.target)) return;
      cancel();
      start.current = { x: e.clientX, y: e.clientY };
      const el = e.currentTarget;
      timer.current = window.setTimeout(() => {
        timer.current = null;
        suppressClick.current = true;
        open(el);
      }, LONG_PRESS_MS);
    },
    onPointerMove: (e) => {
      const s = start.current;
      if (s && Math.hypot(e.clientX - s.x, e.clientY - s.y) > LONG_PRESS_MOVE_PX) cancel();
    },
    onPointerUp: cancel,
    onPointerCancel: cancel,
    onPointerLeave: cancel,
    onContextMenu: (e) => {
      if (onControl(e.target)) return;
```

### 11. 保護者の操作の一覧は、外の部品へ移ったときだけ閉じる（web/src/screens/chat/GuardianChatScreen.tsx 447〜458行）

```tsx
/*
 * 操作の一覧から、フォーカスが一覧の外の部品へ移ったか。Tab などで外の部品へ移ったときだけ一覧を閉じる。
 * 次の2つは外へ移ったのではないので閉じない。閉じると、押したボタンが指・マウスを離す前に消え、
 * リアクション・編集・取消のどれも効かなかった（Safari。iPhone・iPad・Mac）。
 *   - Safari は、押したボタンへフォーカスを移さず、一覧を含む枠（.guardian-main）か body へ落とす。
 *     移り先は一覧の祖先か、無い（null）になる
 *   - 長押しで開いたあと指を離すと、長押しした吹き出しへフォーカスが移ることがある（Chromium のタッチ）
 */
function focusLeftMenu(menu: HTMLElement, to: EventTarget | null, messageId: number): boolean {
  if (!(to instanceof Node) || menu.contains(to) || to.contains(menu)) return false;
  return !(to instanceof HTMLElement && to.dataset.messageBubble === String(messageId));
}
```

**解説**

- 保護者の画面の操作の一覧は、フォーカスが一覧の外へ移ると閉じる。一覧の `onBlur`（364〜365行）が `focusLeftMenu(e.currentTarget, e.relatedTarget, m.chat_message_id)` を呼び、真のときだけ `setMenuId(null)` で閉じる。職員の画面（ブロック 9）は `onBlur` で閉じず、一覧の外を押したときと Esc で閉じる。
- `focusLeftMenu(menu, to, messageId)` は、移り先 `to`（`relatedTarget`）を見て、閉じてよいかを返す。偽（閉じない）になるのは次の3つ。`to` が `Node` でない（`null`。body へ落ちた）、`to` が一覧の中（`menu.contains(to)`）、`to` が一覧を含む祖先（`to.contains(menu)`）。さらに、移り先が、いま開いている吹き出し（`data-message-bubble` がこのメッセージの id）のときも偽。それ以外は、Tab などで一覧の外のほかの部品へ移ったので、真（閉じる）。
- なぜ：Safari（iPhone・iPad・Mac）は、ボタンを押してもそのボタンへフォーカスを移さず、一覧を含む枠（`.guardian-main`）か body へ落とす。以前の `onBlur` はこれを「外へ移った」と取り、ボタンを押した瞬間（mousedown）に一覧を閉じた。すると、離したときのクリックが届かず、リアクション・編集・取消のどれも効かなかった（PR #395）。長押しで開いたあと指を離すと、長押しした吹き出しへフォーカスが移ることがある（Chromium のタッチ）ので、そこでも閉じない。

### 19. モックにも同じ送信の規則がある（web/src/api/mock.ts 1792〜1820行）

## 気をつけているところ

- **誤送信を防ぐ。** 書きかけはチャンネルごとに持つ。届く保護者の人数を入力欄の上に出す。職員が保護者の参加するチャンネルへ送るときは、サーバが他児の名前を照合し、承諾がなければ送らない。
- **誤送信のあとを残す。** 取り消しは本文を消して事実だけを残し、もとの本文は操作ログに残す。管理者は既読の有無ととった対応を誤送信対応記録画面で記録する。記録の無い取り消しは、ダッシュボードにも件数で出る。
- **見てよい範囲をサーバでそろえる。** 一覧・未読・既読・知らせ・リアクションのどれも、`afterLeftClause`・`beforeJoinedClause`・`isMember`／`canRead`／`isParticipant` の同じ条件を通す。画面で投稿欄を隠すだけに頼らない（基本設計書「権限チェックの実装方針」(6-2)）。
- **保護者に見せない値。** 既読の人数・未対応／対応済み・メンバー一覧（ほかの家庭の氏名と続柄）は保護者に返さない。後から加わった保護者には、先の保護者と園のやりとりを見せない。
- **外れた人は閲覧のみ。** 職員は所属していた期間の過去ログだけを読め、書けない。保護者は外れたらチャンネルごと読めない。参加の行は消さず `left_at` で期間を残す。
- **参加は規則から決める。** 職員の参加は `syncStaffChatRooms` の1か所で決め、起動のたびに合わせ直す。目的別グループだけが手で編成でき、保護者は入れない。
- **ひとまとまりで書く。** 送信と未対応への戻し、配布物と掲載の知らせ、取り下げと知らせの取り消しは、それぞれ1つのトランザクションで書く。取り消し・編集は WHERE に `is_deleted = 0` を入れ、同時の操作で上書きしない。
- **規則は2か所。** サーバ（server/api_chat.go・chat_membership.go・api_handout.go）とモック（web/src/api/mock.ts の `chatApi`・`syncStaffChatRooms`・`handoutApi`）に同じ規則と文言がある。テストもサーバ（server/api_chat_*_test.go）とモック（web/tests/）の両方にある。
- **画面の中だけで決めるものは、規則に入れない。** 個人チャットの園児名での絞り込み（`roomSearch.ts`）と、操作の一覧を開くきっかけ（`secondaryAction.ts`）、保護者の連絡先の名前（`labelFor`）は、画面だけで決める。参加・参照範囲・権限はサーバとモックが決め、画面はその結果を並べたり出し分けたりするだけである。
- **操作の一覧は、職員・保護者で同じ入口を使う。** 右クリック・長押し・キーボードの扱いは `secondaryAction.ts` の1か所にある。閉じる条件は画面ごとに違う（職員は一覧の外を押す・Esc、保護者はフォーカスが一覧の外の部品へ移ったとき。Safari ではボタンを押す前に閉じないよう `focusLeftMenu` で見分ける）。
- **設計に無い値は【仮置き】。** リアクションの絵文字4種、職員だけのチャンネルの既読の数え方、外れたのと同じ秒の扱い、保護者の送ったものを誤送信の対象にしないこと、配布物のファイルの実体を持たないこと、個人チャットの絞り込みの置き方と一致のしかた、長押しの時間と指のずれの上限、などは web/仮置き値.md にある。
