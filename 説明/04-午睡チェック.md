# 04 午睡チェック

> この説明は commit 74f09acf のコードで書いた。行番号はその版のもの。

## この機能でできること

- 職員（担任）は、タブレットの午睡チェック画面でクラスの午睡チェックを開始し、終えたら終了する。
- 実施中は、画面の上のタイマーが次の確認までの時間を示す。時刻を過ぎると、通知音と読み上げで知らせる。
- 職員は、園児ごとの行で体位・呼吸・顔色（と測ったときは体温）を選び、「記録する」を押す。確認のダイアログは挟まない。
- 同じ行で「ねた」「おきた」「きょうは対象外」を押す。ねた・おきたは保護者の連絡帳に届く。
- 異常があれば異常時記録画面に残し、そこからヒヤリハット（日誌）を起票できる。
- 午睡記録検索画面で過去の記録を探し、直せる人は理由を付けて修正する。管理者は CSV（午睡チェック表）を出せる。
- 実施中は、開始した職員の自動ログアウトを止める。手でのログアウトは、先に終了するよう示して止める。

ねた・おきたが保護者の連絡帳にどう出るかは [03 連絡帳](./03-連絡帳.md) を見る。
要求を受ける仕組み（ログイン・セッション・権限の共通の関数・知らせ）は [01 全体の仕組み](./01-全体の仕組み.md) を見る。

## 流れ

1. 職員が午睡チェック画面で「午睡チェックを開始する」を押す。`POST /api/nap/session` で実施（`t_nap_session`）を1行作る。
2. 画面は1秒ごとの時計でタイマーを進める。確認の時刻を過ぎた子が増えると、通知音と読み上げで1回知らせる。
3. 職員が行で体位・呼吸・顔色を選んで「記録する」を押す。`POST /api/nap/session/{id}/records` で `t_nap_record` に1行入る。時刻はサーバが打つ。
4. 「ねた」「おきた」は `POST /api/nap/session/{id}/sleeps`・`POST /api/nap/sleeps/{id}/wake` で `t_nap_sleep` に入る。職員の画面（nap）と保護者の連絡帳（contact）の両方へ知らせる。
5. 終えたら「午睡チェックを終了」を押す（`POST /api/nap/session/{id}/end`）。押し忘れたら、午睡の時間帯の終わりにサーバが自動で終える。
6. あとで午睡記録検索画面から `GET /api/nap/records` で探す。直すときは `POST /api/nap/records/{id}/correct` で、修正前後と理由を操作ログに残す。

```
午睡チェック画面                    Go サーバ                         届く先
「開始」 ───POST /api/nap/session──────▶ t_nap_session（実施）
「記録する」─POST …/records────────────▶ t_nap_record（監査の層）──▶ 職員の画面だけ
「ねた」「おきた」─POST …/sleeps・/wake─▶ t_nap_sleep（伝える層）───▶ 職員の画面 と 保護者の連絡帳
「対象外」─POST …/exclusions───────────▶ t_nap_exclusion（監査の層）▶ 職員の画面だけ
「終了」 ───POST …/end─────────────────▶ ended_at を入れる（押し忘れは時間帯の終わりに自動）
```

**解説**
- 開始できるのは、そのクラスを扱える職員である（`canUseClass`。[server/scope.go](../server/scope.go) 251〜256行）。管理者は全クラス、一般の職員は自分のクラスだけである。
- 開始できるのは当日だけである。過去の日付で開始すると、足した直後に自動で解除され、呼ぶたびに行が増えたため（GitHub Issue #97）。これは【仮置き】である。
- すでに実施中なら、新しく作らずにそれを返す。あとから押した職員も同じ実施に入る。ただし `t_nap_session` に一意の制約は無い。確かめ（213行）と書き込み（217行）のあいだに別の要求が割り込めば、2つできうると推測する（確かめていない）。
- 開始した職員（`started_staff_id`）を残す。これが自動ログアウトの例外の「担当」になる（15.）。
- `notifyNapSession` で、そのクラスを扱える職員の画面へ知らせる。保護者には送らない。
- 終了（`handleEndNapSession`。234〜277行）も同じ `canUseClass` で確かめる。終わった実施は、終了時刻と終了した職員を書き換えない（409）。

### 2. 押し忘れた実施を自動で終える（server/api_nap.go 139〜185行）
```go
func napAutoCloseAt(sessionDate, startedAt, timeRange string) (closeAt, endedAt string) {
	end := "15:00"
	if i := strings.Index(timeRange, "-"); i >= 0 && len(strings.TrimSpace(timeRange[i+1:])) == 5 {
		end = strings.TrimSpace(timeRange[i+1:])
	}
	rangeEnd := sessionDate + "T" + end + ":00"
	if startedAt < rangeEnd {
		return rangeEnd, rangeEnd
	}
	dayEnd := sessionDate + "T23:59:59"
	return dayEnd, dayEnd
}

// autoCloseNapSessions は、解除の時刻を過ぎた実施中の午睡チェックを終了にする
func (a *app) autoCloseNapSessions() {
	// …（略）…
	timeRange := a.settingText("nap.time_range", "13:00-15:00")
	for _, x := range list {
		closeAt, endedAt := napAutoCloseAt(x.date, x.start, timeRange)
		if now() <= closeAt {
			continue
		}
		// 終了した職員はいないため ended_staff_id は空のままにし、自動で解除した印を立てる
		if _, err := a.db.Exec(`UPDATE t_nap_session SET ended_at = ?, is_auto_closed = 1
			WHERE nap_session_id = ? AND ended_at IS NULL`, endedAt, x.id); err != nil {
			// 解除できなかった実施は実施中のまま残る。黙って捨てない（GitHub Issue #99）
			log.Printf("午睡チェックの自動解除に失敗しました（session=%d）: %v", x.id, err)
		}
	}
}
```
**解説**
- 終了を押し忘れた実施は、午睡の時間帯（設定 `nap.time_range`。既定は 13:00-15:00）の終わりで解除する（基本設計書「午睡チェックの実施」(4-7)）。解除しないと実施中のまま残り、共用のタブレットが自動ログアウトされなくなる（131〜133行のコメント）。
- 時間帯の終わりより後に開始した実施は、開始した時点で解除の時刻を過ぎている。すぐに解除しないよう、その日の終わり（23:59:59）に解除する。これは【仮置き】である。
- 自動で解除したときは、終了した職員を空のままにし、`is_auto_closed` を立てる。
- 解除に失敗したら、黙って捨てずにログに書く（GitHub Issue #99）。
- この関数は、実施を読む・記録する経路の入口で毎回呼ぶ（108〜109行・251行・410行など）。時計で動く仕組み（定期の処理）は持たず、読むときに追いつかせる形である。
- 画面は1分ごとに読み直し、終了を押していないのに実施中でなくなったら「午睡の時間帯を過ぎたため、午睡チェックを自動で終了しました。」と出す（[NapCheckScreen.tsx](../web/src/screens/nap/NapCheckScreen.tsx) 136〜157行・266〜267行）。

### 5. 園児の行で記録する（web/src/screens/nap/NapCheckScreen.tsx 507〜532行）

**解説**
- 「記録する」は、体位・呼吸・顔色の3つがそろうまで押せない（471行・631〜635行）。押せない理由をボタンの近くに出す。
- 体温が 30.0〜43.0℃ の外なら、1度だけ止めて確かめる。もう一度押せば記録する。判定はせず、打ち間違いに気づかせるだけである。
- 記録したら、選んだ値を空に戻す。次の確認では前回の値を入れず、毎回目で見て選んでもらうためである（450行のコメント）。
- 確認の画面を出さないので、行に「保存しました」を5秒出す。これが唯一の手応えである（30〜31行・476〜482行）。
- キーボードで押したときは、次の園児の行の最初の選択肢へフォーカスを移す。巡回の順に次の子へ進めるためである（GitHub Issue #213）。
- うつ伏せや「呼吸 確認できず」を選ぶと注意の文を出す（605〜606行）。注意喚起であって判定ではなく、記録は妨げない。呼吸が確認できないときは、記録より先に子どもへの対応と応援の要請を促す。

### 7. 通知音を鳴らす（web/src/napSound.ts 83〜114行）
```ts
export function useNapSound(active: boolean) {
  const supported = !!contextCtor();
  // null は「まだ確かめていない」。確かめる前に「出る状態になっていません」を一瞬出さない（PR #322 の review）
  const [ready, setReady] = useState<boolean | null>(null);

  useEffect(() => {
    if (!active || !supported) return;
    const sync = () => setReady(running());
    const unlock = () => { void resume().then(sync); };
    watchers.add(sync);
    // 触れたことがあれば、いま使える状態にする。無ければ、最初に触れるまで待つ

    window.addEventListener('pointerdown', unlock);
    window.addEventListener('keydown', unlock);
    return () => {
      watchers.delete(sync);
      window.removeEventListener('pointerdown', unlock);
      window.removeEventListener('keydown', unlock);
    };
  }, [active, supported]);

  const play = useCallback(() => {
    const ctx = ensureContext();
    if (!ctx) return;
    if (ctx.state === 'running') { schedule(ctx); return; }
    // 止められていても、もう一度試す（操作を受けたあとなら通る）
    void resume().then(() => { if (running()) schedule(ctx); });
  }, []);
```

```go
	// 1回目の版のままの訂正は書き換えの文の条件で 409 になる
	res, err := a.db.Exec(`UPDATE t_nap_sleep SET slept_at = ?, woke_at = ?,
		woke_staff_id = CASE WHEN woke_staff_id IS NULL AND ? IS NOT NULL THEN ? ELSE woke_staff_id END,
		corrected_at = ?, updated_at = ? WHERE nap_sleep_id = ? AND is_deleted = 0 AND updated_at = ?`,
		sleptAt, wokeAt, wokeAt, u.staff(), at, nextVersion(sleep.UpdatedAt), sleep.ID, in.UpdatedAt)
	if err != nil {
		writeErr(w, http.StatusInternalServerError, msgContactSaveFailed)
		return
	}
	if n, _ := res.RowsAffected(); n == 0 {
		writeJSON(w, http.StatusConflict, apiError{Message: msgFixConflict, Kind: kindVersionConflict})
		return
	}
```
**解説**
- 押し間違いを直す道である。実施の後も直せる（実施中に限るのは、記録を足すほう）。直せる人は連絡帳と同じ `canFixContact`（`sleepTarget`。17〜40行）で、その日はその園児のクラスの担任、管理者はいつでもである。
- 時刻の範囲（その日の0時からいままで）を確かめるのは、元の値から変えた時刻だけである。「ねた」と「おきた」が同じ秒に押されると、おきたは「ねた＋1秒」で、まだ来ていない時刻になる。変えていない時刻まで確かめると、その直後に直せなかった（受け入れテスト 04-017）。
- 順（ねた < おきた）は、変えたかどうかに関わらず確かめる。
- おきたが無いまま実施が終わった組に「おきた」を入れるのも、ここで行う。おきたを推測で入れない。人が時刻を入れる（9〜10行のコメント）。入れた職員を `woke_staff_id` に残す。
- 版（`updated_at`。行を書き換えるたびに進める印）は書くたびに必ず進める（決めたこと D-40）。同じ秒に2回直しても、1回目の版のままの訂正は 409（衝突を表す HTTP の応答の番号）になる。
- `corrected_at` に今を入れるので、保護者の連絡帳に「訂正しました（時刻）」が出る。取り消し（`handleCancelSleep`。127〜154行）は `is_deleted` を立て、保護者の画面から消す。モックは `correctSleep`（[web/src/api/mock.ts](../web/src/api/mock.ts) 6000〜6026行）で、同じ順に確かめる。

### 14. 実施中のログアウトを止める（web/src/layouts/StaffLayout.tsx 104〜118行）
```tsx
  const napRunning = async () => {
    try { return (await api.sessionStatus(user)).nap_exempt; } catch { return false; }
  };
  // 保存していない入力（書きかけの日誌・メッセージなど）があれば、破棄される旨を表示して確認する（基本設計書「ログアウト」(4-3)）
```

**解説**
- ヘッダの「ログアウト」を押すと、先に `api.sessionStatus` で `nap_exempt`（自分が開始した午睡チェックが実施中か）を尋ねる。
- 実施中なら、ログアウトせずに「午睡チェックの実施中は、ログアウトできません。先に午睡チェックを終了してから、ログアウトしてください。」の窓を出す（217〜224行。基本設計書「ログアウト」(4-3)）。
- 担当を交代するときは「終了 → ログアウト → 次の職員がログイン → 開始」の順で引き継ぐ（100〜101行のコメント）。
- 尋ねられないとき（サーバに届かないなど）は止めない。これは画面の出し分けで、権限の規則ではない。サーバのログアウトは止めない（102行のコメント）。
- 保存していない入力があるときの確認（113〜116行）より先に、実施中かを見る。

### 15. 実施中は自動ログアウトしない（server/session.go 271〜307行）
```go
func (a *app) napExemption(accountID int64, since, at time.Time) (active bool, lastEnded time.Time) {
	const layout = "2006-01-02T15:04:05"
	// 接続は1本に絞っている（db.go）。行を読んでいる途中で a.db へ問い合わせないよう、設定は先に読む
	timeRange := a.settingText("nap.time_range", "13:00-15:00")
	rows, err := a.db.Query(`SELECT ns.session_date, ns.started_at, ns.ended_at
		  FROM t_nap_session ns
		  JOIN m_staff st ON st.staff_id = ns.started_staff_id
		 WHERE st.account_id = ? AND (ns.ended_at IS NULL OR ns.ended_at > ?)`,
		accountID, since.In(jst).Format(layout))
	if err != nil {
		// 確かめられないときは例外を当てず、通常の自動ログアウトにする。黙って捨てない（GitHub Issue #99）
		log.Printf("午睡チェックの実施を確かめられません（account=%d）: %v", accountID, err)
		return false, time.Time{}
	}
	defer rows.Close()

	nowISO := at.In(jst).Format(layout)
	for rows.Next() {
		var date, started string
		var ended sql.NullString
		if err := rows.Scan(&date, &started, &ended); err != nil {
			continue
		}
		end := ended.String
		if !ended.Valid {
			closeAt, _ := napAutoCloseAt(date, started, timeRange)
			if nowISO <= closeAt {
				return true, time.Time{}
			}
			end = closeAt
		}
		if t, err := time.ParseInLocation(layout, end, jst); err == nil && t.After(lastEnded) {
			lastEnded = t
		}
	}
	return false, lastEnded
}
```
**解説**
- `napExemption` は、そのアカウントの職員が開始した実施のうち、いま実施中のものがあるかを返す。担当は開始した職員である（264〜266行のコメント）。
- 終了を押し忘れた実施は、DB の自動の解除（2.）を待たずに、同じ `napAutoCloseAt` で解除の時刻を求める。時間帯の終わりを過ぎていれば、実施中とみなさない。
- 実施中でなければ、最後に終わった時刻を返す。自動ログアウトまでの時間は、その時刻から数え直す（`idleDeadline`。248〜258行）。実施中に操作が無くても、終わった直後に切れることはない（要件定義書「午睡チェック中の例外」(4-1-4 (4))）。
- 確かめられないとき（DB の誤り）は、例外を当てずに通常の自動ログアウトにする。黙って捨てずにログに書く（GitHub Issue #99）。
- 自動ログアウトの判定そのもの（`sessionAccount`。214〜234行）は 01 を見る。画面の予告（`SessionTimeoutWarning.tsx`）は、`nap_exempt` が真の間は出さない。モックは `idleDeadlineOf`（[web/src/api/mock.ts](../web/src/api/mock.ts) 5661〜5679行）。

## 気をつけているところ

- **判定しない。** うつ伏せでも、呼吸が確認できなくても、記録は妨げない。注意の文は注意喚起である。体温の範囲外も、画面で1度確かめるだけで保存する。異常時の記録の重大さも、保護者への連絡の要否も、システムは判断しない。
- **監査の層と伝える層を分ける。** 5分ごとの確認（`t_nap_record`）・対象外（`t_nap_exclusion`）・異常時の記録（`t_nap_abnormal`）は職員の中だけにある。保護者に届くのは、ねた・おきた（`t_nap_sleep`）だけである。入眠時の体温も職員だけに返す。
- **時刻はサーバが打つ。** 確認・ねた・おきたの時刻は、画面の時計でなくサーバの今で入れる。画面は届いた時刻を `jstMs` で日本時間として読む。
- **終わった実施へは足さない。** 記録・ねた・おきた・対象外・異常時の記録は、終わった実施には 409 `session_ended` を返す。直すことは、終わったあともできる。
- **記録は消さない。** 修正は行を書き換え、修正前後の値と理由を操作ログに同じトランザクションで残す。帳票の「修正の履歴」になる。ねた・おきたの取り消しは `is_deleted` を立てるだけで、行は残る。
- **権限の担保はサーバにある。** 開始・終了・記録は `canUseClass`（一般は自クラス）。フリーの職員は `canReadClass` で全クラスを読むだけで、画面も記録の部品を出さない（[NapCheckScreen.tsx](../web/src/screens/nap/NapCheckScreen.tsx) 114〜115行）。ねた・おきたは `contactAccess` の Write も見る。記録はその園児のクラスの実施だけに付く。CSV は管理者だけ（`requireAdmin`）で、出したことを操作ログに残す。
- **同時に押したとき。** 実施中の実施があれば、開始はそれを返す。「ねた」と対象外は1つの文で確かめて書き、部分一意の索引でも止める。訂正は版で照合する。
- **規則は2か所にある。** モック（`web/src/api/mock.ts`）の `napApi`・`napApi2`・`napSleepTarget`・`correctSleep` などが、同じ規則を持つ。自動で終える時刻は、さらに `web/src/api/util.ts` と `server/session.go` にもある。
- **仮置きの値。** 当日だけ開始できること、時間帯の後に開始した実施の解除の時刻、通知音の音、異常時の記録は実施中だけであること、検索の並び、修正で体温を消せることなどは、設計が決めていない値である。コードに【仮置き】と書き、[web/仮置き値.md](../web/仮置き値.md) に一覧がある。
- **設計書の番号のゆれ。** 「午睡チェックの実施」は、コメントによって基本設計書の (4-7) と (4-8) の両方で書かれている（api_nap.go 131行と napSound.ts 3行など）。設計書の版で章の番号が変わったためと推測する。名前で探すとよい。
