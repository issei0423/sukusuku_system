## server/（Go サーバ）

Go のファイルはすべて `package main` の1つのパッケージにある。フォルダは分かれていない。
ここでは役目ごとに表を分けた。テスト（`*_test.go`）は最後の「テスト」の節にまとめた。

## テスト

テストは1ファイルずつではなく、場所と種類でまとめる。中身は [10-テストの仕組み](10-テストの仕組み.md) が扱う。

| 場所 | 数 | 種類と相手 |
| :-- | :-- | :-- |
| `server/*_test.go` | 71 | Go のテスト。一時フォルダに DB を作り、ハンドラを直接呼ぶ。ファイル名は確かめる機能に合わせてある（`api_contact_*`・`api_nap_*`・`api_diary_*`・`api_chat_*` など）。共通の準備（`newTestApp`・`loginAs`）は `api_dashboard_test.go` にある |
| `web/tests/*.test.ts` | 63 | vitest。相手はモック（`api/mock.ts`）。規則と流れを確かめる。`integration.test.ts` だけは Go サーバにつなぐ結合テスト（ふだんは飛ばす） |
| `web/tests/*.test.tsx` | 55 | vitest。画面を描いて確かめる（1行目に `// @vitest-environment jsdom`） |
| `web/tests/setup-clock.ts` | 1 | vitest の時計を、日本時間の今日の 18:00 で止める |
| `web/tests/acceptance/` | 24 | Playwright の受け入れテスト（機能ごとの `*.spec.ts` と補助） |
| `web/tests/responsive/` | 17 | Playwright のレスポンシブレビューと、アクセシビリティの検査（`a11y-*.spec.ts`） |
| `web/tests/security/` | 8 | Playwright のセキュリティの検査 |
| `web/tests/deployed/` | 2 | 公開先に対する簡単な確かめ（smoke） |

Go とモックの規則が食い違わないかを、同じ観点で両方から確かめるテストもある。
`server/api_mock_rules_test.go` と `web/tests/mockServerRules.test.ts` がその組である。
